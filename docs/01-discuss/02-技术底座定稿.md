## 二、为什么 GCC 16（本机前提）

- 系统 gcc-13 不支持 `-std=c++26`;clang 19 支持方言但配套 libstdc++-13 缺 `<generator>` `<print>`。
- GCC 16 原生提供 `<generator>`（LLM 流式响应要用）`<print>` `std::expected` 与完整 C++26 核心语言，是最省心的选择。
- apt/PPA 装失败后可改纯二进制路线:下载 21 个 deb → `dpkg -x` 合并到用户目录,与系统完全隔离(换机器可整体拷贝)。

## 三、踩坑记录（重要）

1. **CMake 3.28 不认识 `cxx_std_26` meta-feature**，会把标准悄悄降级。对策:不用 `CMAKE_CXX_STANDARD`,在 preset 里显式 `CMAKE_CXX_FLAGS=-std=c++26`,顶层 CMakeLists 加护栏检测 `-std=c++26` 缺失即 FATAL_ERROR。
2. **该 CMake 3.28.3 构建对 `${env:HOME}` / `${userHome}` 宏报 "Invalid macro expansion"**（`${sourceDir}` 则正常,已逐字段二分定位）。对策:编译器在 preset 中用裸名 `g++-16`,由 `env.sh` 的 PATH 解析;机器相关路径不写进 CMakePresets.json。
3. **`dpkg-deb -I` 校验会被截断文件骗过**(只看控制段)。对策:大文件下载后比大小(远端 Content-Length)(或真实 `dpkg -x`),三个 ~90MB 驱动包曾因此截断。
