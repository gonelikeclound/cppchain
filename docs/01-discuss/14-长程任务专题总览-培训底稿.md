## 一、这是什么（30 秒版）
一个任务持续跨**多次分批运行**（数天/数月）：每批 = 一次 wfr 触发，批间保持任务计划与进展，结论在时间轴上
**不飘移**，且 Agent 能感知「今天是哪批、几号」。单批内部复用已完成的 **PEV 三级验证环**（arch 19/01-discuss/11）。

## 二、为什么做（两个真实信号）
1. **A1 全量（28 份合同）被 LLM 端点 900s 超时踢掉** —— 一次跑完对大任务不可靠，解法是分批续跑。
2. **结果不飘移**：跨"天"级时间轴，Agent 易忘最初目标/被新输入带偏——需要把"任务本身"与"某一次运行"解耦。

## 三、核心定论（三句话）
- **任务 = 一份档案**（`.wfr/tasks/<task>.json`）：goal + 步骤全清单 + 全局 cursor + batch_no + 批间摘要，跨批唯一事实。
- **replay = 模型记忆，档案 = 计划+批进度**：会话日志给模型全部历史（记忆），档案决定"下一步从哪做"（计划指针），两者分工不替代。
- **批次 = 计划的一截**：每次触发跑当前 cursor 起的若干步（loop max 步），批尾把进展写回档案。

## 四、能力模型
| 能力 | 说明 | 落地 |
|---|---|---|
| 分批续跑 | 一次触发一个批；批间从档案还原 cursor 续 | `task begin/end` + `lot` workflow |
| 结果不飘移 | 计划跨批唯一（档案不动）；每批可复查上批摘要 | `recheck_prev` → `audit_prev` 步（L3 裁判） |
| 感受时间变化 | 每批注入「📅 第 N 批 @ 日期 / 上批摘要」 | `task begin`（`@config.task_date` 可模拟跨天） |
| 批间可改（fork） | 回到历史某批快照再续 | `task_revision=N` + `.history/batch<N>.json` 快照 |
| 到点再跑（调度） | 到期自动触发一批 | `wfr cron`（轻量；OS cron 押后 05） |

## 五、机制与文件
- 节点：`task`（phase=begin/end）、复用 `plan`/`verify`/`plan_review`；流程 `lot.json`（含 chat_bash+审批）。
- begin：建档（@config.plan_steps）或读档还原 + 批号/日期/摘要注入（+recheck/《audit》插入）；end：写回档案 + 历史快照。
- 历史只增不减（`.wfr/tasks/<task>.history/batch<N>.json`）；end 遇空 plan 不覆盖档案；begin 缺种子早返。
- CLI：`wfr lot --workdir … --set task=T [--set task_revision=N] [--set recheck_prev=on] [--set task_date=…]`；
  `wfr cron [--once|--sleep-secs|--max-rounds]` 到期重进本进程触发 lot 批。
- 单测：`tests/wf/lot_task_test.cpp`（二批还原 / revision fork / recheck_prev）。

## 七、踩过的坑（诚实的工程史）
1. **审批悬挂**：长程要跑 bash/office 必须 `approve_policy=allow`（否则挂在 approve 节点等 stdin 超时）。
2. **跨 fire checkpointer 奇偶性**：同线程二次 fire 的回放会扰乱批续跑 → **跨批契约=档案文件**，测试用全新 cp+独立线程（SKIP 转正）。
3. **DeepSeek-flash DSL 怪癖**：偶发把工具调用序列当正文输出、产物不落盘——步骤强约束（bash 重定向到文件）+ 离线确定性合并兜底。
4. **CWD 污染**：工具写进程 CWD 的 `.out/` / `life.jsonl` 误入版本库 → 已删 + .gitignore。
5. **cron every=0 被守卫跳过**（demo 用 1）。
6. **end 曾覆盖空档案导致后续批丢 plan** → 加护栏（空 plan 不写盘；缺种子早返）。
