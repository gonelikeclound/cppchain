## 0. 一句话架构

> **形状**三选一（直调 / ReAct / 计划×步）；**性质**一个都不能少（可验证 / 防重放 / 可逆）；
> 形状由**结构谓词**决定，性质由**账本**兜底；模型只能**申请**和**提示**，不能**断言**。

## 1. 分层图

```
┌─────────────────────────────────────────────────────────────┐
│ L0 入口层    正则 / 语料库召回 / 小模型       （0 次 LLM 决策）│
├─────────────────────────────────────────────────────────────┤
│ L1 路由层    结构谓词 → probe 预演 → 三档             ← 缺口 G3│
├─────────────────────────────────────────────────────────────┤
│ L2 执行层    ├ 直调   （1 步）                                │
│              ├ ReAct  （边做边想）                            │
│              └ 计划×步（step = run）                    ← 缺口 G1│
├─────────────────────────────────────────────────────────────┤
│ L3 保障层    ★ 不变式：结果可验证 / 副作用防护 / 可逆          │
│              ★ 与形状无关，任何档位进入前统一施加              │
├─────────────────────────────────────────────────────────────┤
│ L4 事实层    效果账本（entry / idempotencyKey / status）        │
│              + 补偿票据（cmd / expiresAt）              ← 缺口 G2│
├─────────────────────────────────────────────────────────────┤
│ L5 终态层    run → Terminal（四档）→ task 进度          ← 缺口 G1│
├─────────────────────────────────────────────────────────────┤
│ L6 观测层    Signal 传感器 / 混淆矩阵 / 干预数                 │
└─────────────────────────────────────────────────────────────┘
```

## 2. 全链路：8 个闸门

| # | 闸门 | 输入 | 判定 | 失败去处 |
|---|---|---|---|---|
| G0 | 召回 | query | 语料库/正则命中？ | 未命中 → 进 L1 路由 |
| G1 | 结构谓词 | 候选工具签名 + goal | 多 EFFECT / 依赖链 / 跨域≥2 / P50 超阈值 | 全否 → 直调或 ReAct |
| G2 | probe 预演 | goal + 候选工具 | 能否列出 ≥2 条**可核对**验收条目 | 写不出且一试不出 → 澄清 |
| G3 | 副作用预检 | 工具 + 参数（**无论有无 signal 都执行**） | 不可逆？已授权？ | 不可逆且无票 → 审批 |
| G4 | 执行 | step | 工具调用 | 契约前置失败 → `PreconditionFailed{missing}` |
| G5 | 无效调用检测 | 近窗口工具序列 | 信息增益三元组 / 六形态 | 无效 → 提示/换策略/升级/澄清 |
| G6 | 收尾闸门 | 账本 + 证据 | 覆盖检查（计划档）/ 对账 + 新鲜度 | 不过 → 回灌差异，继续 |
| G7 | 终态 | run | 四档互斥穷尽 | 异常 → `Aborted`（01 C-30） |

**顺序不可交换**：G3 必须在 G4 之前且**无条件**（见 §6 矛盾 C3）；G6 必须在 G7 之前。

## 3. 一致性矩阵 A：三档 × 三条保障

| 保障 | 直调 | ReAct | 计划×步 |
|---|---|---|---|
| **结果可验证** | 包装层读回校验 | 终态闸门：账本对账 + 证据新鲜度 | 每步 Terminal + **覆盖检查** |
| **副作用防护** | 契约前置检查 + 幂等键 | 每轮调用前按契约判定 | 计划期**预演全部 EFFECT** |
| **可逆** | 补偿票据（最常被跳过，最该补） | 每轮留票据 | 计划期标注哪些步不可逆 |

> **审计结论 A**：三条保障在三档中的落点**齐全，无空洞**。唯一风险是直调档——它没有计划期，所有保障只能靠工具包装层，因此**包装层是单点**（见缺口 G4）。

## 4. 一致性矩阵 B：五条副作用要求 × 落点

| 要求 | 落地组件 | 状态 |
|---|---|---|
| 1 防重放 | `EffectLedger` + 幂等键（包装层生成） | ✅ 已有设计 |
| 2 可逆性分析 | `EffectContract.effectClass` | ✅ |
| 3 不可逆补偿分析 | `CompensateEntry{cmd, expiresAt}` → 回收站 | ⚠️ 有设计，缺调度者（G2） |
| 4 预警 + 高风险审批 | 风险分级器 + 能力票据 | ✅ |
| 5 时效性 | `expiresAt` + **状态迁移触发者** | ❌ **无触发者**（G2） |

> **审计结论 B**：第 5 条是**孤儿需求**——"时效"被声明为要求，但系统中没有任何组件负责"时间到了就改状态"。静态表装不下随时间退化的能力。

---

## 5. 一致性矩阵 C：四层完成判定 × 三档

| 层 | 直调 | ReAct | 计划×步 |
|---|---|---|---|
| **L1 语义** | 语料库命中即隐含 | probe 的 acceptance | 计划前的覆盖检查 |
| **L2 收敛** | `Terminal` | `Terminal` | 每 step 一个 `Terminal` |
| **L3 事实** | entry 读回 | 账本对账 | 账本对账 + 新鲜度 |
| **L4 效果** | 读回即验收 | **❌ 无归宿**（G5） | 覆盖检查 + 每步验收条目 |

> **审计结论 C**：这是全套设计里**最实质的一个洞**。ReAct 档没有验收条目（它本来就不该有），所以它的 L4 只能靠"账本对账"——但对 **`ANSWER` 类目标**（无副作用，只要一个正确答案），账本里根本没有可对账的东西。**ReAct + ANSWER 是目前唯一没有 L4 判定的组合。**

## 6. 矛盾清单（4 条，已裁决）

| # | 矛盾 | 裁决 |
|---|---|---|
| C1 | 点 3「简单/中度可直接重执行」× 副作用不可重放 | **按账本状态而非档位决定**：无 `committed`/`unknown` → 可重来；有 `committed` → 只续跑；有 `unknown` → 找人 |
| C2 | 幂等键含 `stepId` × 重规划后 stepId 变 | **`stepId` 移出去重键**，只做审计；语义锚点用 `(taskId, intentSlot, canonicalArgs, tool)` |
| C3 | `Signal type="intent"` 预检 × 工具层预检 | **预检在 G3 无条件执行**；signal 只是**提前**，绝不能成为绕过的分叉点（否则模型学会"不说就绕过"） |
| C4 | 衰减探索额度 × 读回校验消耗额度 | 契约标 `readPurpose: explore \| verify`，**verify 不占额度** |

## 7. 缺口清单（12 条，按严重度分级）

### P0 —— 会导致错误行为，发布前必须闭合

**G1｜`task` 层不存在，只有 `run` 层。**
跨 run 的进度、续跑授权、`taskId` 生命周期、跨 run 账本视图全部无载体。而幂等键里已经用到了 `taskId`——**它在被使用，但没人定义它**。
→ 建议：定义 `Task{taskId, plan, stepStatus[], taskTerminal, resumeQuota}`，`stepStatus[i] = done` 由第 i 步的 `Terminal` 派生，不靠信号。

**G2｜时效/补偿窗口没有触发者。**
`expiresAt` 只是一个字段。谁在到期时把 entry 从"可补偿"迁到"终态不可补偿"？谁在 `risk()` 里重算？
→ 建议：账本旁挂一个**轻量调度器**（或复用现有定时任务），只做一件事：扫描过期票据 → 写 `compensation_expired` 事件 → 提升相关 entry 的风险等级。**不主动做任何补偿**，只改"还能不能撤"的判定。

**G3｜路由层缺"召回"这一步，存在循环依赖。**
结构谓词要判"多 EFFECT / 跨域数"，需要先知道候选工具；而候选工具要靠语料库召回——但召回在 L0 且是"命中即直调"。二者顺序未定义，且"召回失败 → 进 LLM 自主意图"这条老路径与新的三档路由**没有接上**。
→ 建议：明确 `召回 → 谓词 → probe` 三段顺序；召回失败 → 直接进 probe（不是"进 LLM 自主意图"这个旧分支）。

**G4｜直调档的保障全压在工具包装层，是单点。**
小模型/正则路由意味着决策层"不理解副作用"，所以包装层的任何遗漏都是**静默**的。而直调占流量绝对多数。
→ 建议：包装层加**自检**——启动时扫描工具注册表，凡 `effectClass != read` 却无 `compensate`/`idempotency` 声明的，**启动即失败**（fail fast），而不是运行时才发现。

**G5｜ReAct + `ANSWER` 类目标没有 L4 判定。**
见矩阵 C。这是全套里唯一的"判定真空"。
→ 建议：给 `ANSWER` 类两条出路之一：① 强制降级为"未验证成功"子档（诚实，成本 0）；② 对可形式化的答案（数字/日期/ID）加**轻量核对器**（正则/单位/边界检查），够用即可。不要试图给开放答案做 L4——那只会造出一个 fail-noisy 的评审者。

### P1 —— 会造成局部不一致

**G6｜中途升级（ReAct → Plan）后，已完成副作用如何并入计划未定义。**
升级时若重规划，可能重做已完成的事。
→ 规则：升级时把 `committed` 的 entry **冻结为"隐式 step 0"**，计划只允许在其后追加；覆盖检查须把这些 entry 计入完成度。

**G7｜四种"跟用户说话"的机制边界未收敛。**
`<ask>`（终态）、`<suggest>`（终态）、`ask_user_question`（过程中）、`Signal type="ask"`（过程中的零往返前身）、**加上新增的"超预算转多轮时通知进度"**——五种。
→ 建议：只保留**两个维度**区分：`是否阻塞`（阻塞=等回答才能继续）× `是否收尾`（收尾=本 run 结束）。五种机制应能被这两个维度唯一映射。

**G8｜"预算"从 3 个桶变成 6 个刻度，关系未定义。**
现有：轮数 / token / 时间；新增：单步 ≤K 工具调用、衰减探索额度、`N_max` 步数。它们是同一桶的不同刻度，还是互相独立？会不会互相窃取（比如只读探索吃掉了工具调用额度）？
→ 建议：**两级**——task 级（总轮数 / 总 token / N_max）与 step 级（单步 K 次调用 / 探索额度）。step 级额度**不在 task 级之外单独计数**，只做"单步内的形状约束"。

**G9｜用户中途介入后，计划与已提交副作用的关系未定义。**
用户说"换个做法"时，计划作废，但已 `committed` 的副作用还在。
→ 建议：介入触发 `plan_invalidated` 事件，走"冻结 + 重规划"，并提供**补偿提案**（不是自动回滚）。

### P2 —— 影响可观测性，不影响正确性

**G10｜一致率只覆盖"可对账信号"，`stuck` 类会逃逸。**
→ 补第二个指标：**信号有效转化率**（产生行为改变的信号 / 总信号），并单独监控 `ask` 率——一个永远输出 ask 的模型一致率 100%，但会变成"每轮都问"。

**G11｜假成功率的标注点未定义（task 级还是 step 级）。**
→ 建议：step 级自动（由 Terminal 定），task 级人工抽检；两级分开报。

**G12｜`noProgress` / `progressVector` / `Signal stuck` / 六形态检测器，四个"停滞判据"职责重叠。**
→ 收口为一条：**六形态 = 早期识别（便宜、可解释）；`progressVector` = 总闸（昂贵、权威）；`Signal stuck` = 触发器（不采信）；`noProgress` = 纯函数兜底（可回放）**。四者共用同一份窗口数据，只是触发时机不同。

## 8. 孤儿检查

| 类型 | 内容 | 处置 |
|---|---|---|
| **孤儿机制**（设计了没人调） | `expiresAt` 字段、`N_max` 步数上限 | 并入 G2 / G8 |
| **孤儿需求**（要了没人做） | 时效性、任务级进度、L4(ReAct+ANSWER) | G2 / G1 / G5 |
| **孤儿字段**（存了没人读） | `stepId`（在键里但应只做审计）、`artifact` 属性 | C2 已裁决；`artifact` 需在 G6 收尾闸门读取 |
| **双写**（两处都能改同一事实） | `stepStatus` 既可能来自 signal 也可能来自 Terminal | **只认 Terminal**，signal 永不写状态 |

## 9. 度量三层

| 层 | 指标 | 采集方式 |
|---|---|---|
| **step** | 该步 Terminal 分布 / 是否带 `entryIds` | 自动 |
| **task** | 完成率、`UNVERIFIED` 占比、假成功率（抽检） | 半自动 |
| **会话** | **每会话人工干预数**、升级率、信号一致率 | 自动（对外趋势） |

> 对外只报**干预数**，对内用混淆矩阵做归因——成功率有两套逃逸路径（对比式/拆解式），横向不可比。

---

## 10. 落地顺序

1. **P0 五项**（G1–G5）——它们决定"错了会不会被发现"
2. 直调档的包装层自检（G4）——最低成本、最高覆盖率
3. `Signal` MVP（两条：`ask` / `tool_drift`）+ 一致率埋点
4. 六形态检测器（G5 的替代方案：先只做形态 1、2）
5. probe 预演 —— 最后做，因为它依赖前面全部就位

---

## 11. 一句话

**这套设计的完整度取决于三件事：task 层是否真的存在、时间是否有人负责、以及 ReAct 遇到纯问答时敢不敢诚实地标"未验证"。** 前两个是结构缺失，第三个是纪律问题——而纪律问题恰恰最容易在"看起来一切正常"的时候被跳过。
