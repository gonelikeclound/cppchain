SystemAgent 核心设计规范与场景推演
一、核心定位与设计原则
1.1 本质差异：跳出阻塞式 ReAct Loop
传统 ReAct Agent 采用「思考 → 调用工具 (阻塞等待返回) → 拿到结果 → 再思考」的同步循环，由 LLM 主动发起，工具被动应答，任务生命周期绑定单次对话轮次，天然不适应长生命周期、异步事件驱动、自带独立状态机的系统交互场景。
SystemAgent（SA）是面向操作系统服务、通信会话、外设控制等场景的常驻事件驱动型智能编排体，核心控制权反转：由外部系统原生状态机与事件总线作为主控，LLM 是按需唤醒的决策子组件，无持续运行的主循环。
1.2 核心设计原则
常驻不终止：SA 以系统守护进程形态运行，生命周期独立于单个任务，完全由事件驱动唤醒，空闲时静默休眠。
编排与执行分离：SA 只负责任务拓扑的生成、调整与校验，不执行业务逻辑，所有执行全部委派给拓扑节点。
多任务隔离：同时维护多个独立任务，每个任务对应一张拓扑图与独立上下文，通过订阅机制实现跨任务信息同步。
非阻塞刚性约束：SA 任何决策循环都不等待节点返回结果，提交拓扑变更后立刻释放资源，节点执行结果通过事件反向驱动决策。
双层状态模型：底层为外部系统原生固定状态机（SA 不可修改，仅可监听与下发合法动作）；上层为 SA 维护的任务拓扑与业务上下文，支持动态变更。

三、两层上下文架构
SA 上下文采用严格的二级结构，替代单一线性对话历史，兼顾多任务隔离与跨任务同步。
3.1 第一层：全局任务管理上下文
与单个业务任务无关，负责全局调度与路由。
核心存储
任务注册表：任务唯一 ID、状态（运行中 / 完成 / 失败 / 挂起 / 取消）、拓扑引用、优先级、创建时间
订阅关系表：任务对全局事件、其他任务事件的订阅规则
系统全局状态：可用资源、执行器健康度、全局权限配置
核心职责
事件路由：接收事件后精准投递到对应任务上下文
跨任务通知：匹配订阅规则，主动向订阅任务推送状态变更
全局仲裁：处理资源冲突、优先级抢占、批量调度
3.2 第二层：单任务上下文
每个任务独立持有，彼此默认隔离，是拓扑编排决策的直接依据。
核心存储
任务目标与原始需求
当前版本的任务拓扑图（节点、边、状态）
结构化历史事件轨迹与节点里程碑记录
任务级业务中间数据
瞬时上下文机制
每次事件触发决策时，读取任务最新状态快照拼接成单次决策上下文；决策完成后仅回写拓扑变更与状态增量，不堆积长对话历史，控制 LLM 输入长度。
订阅跟踪能力
任务可订阅全局或其他任务的特定事件，被订阅对象变化时，由第一层自动将事件注入该任务上下文快照，作为下一次决策输入。
四、动态拓扑模型与节点定义
4.1 拓扑图基本定义
单个任务对应一张运行时可变有向无环图（动态 DAG），SA 通过原子 Patch 对图进行增量修改，支持节点增删、依赖调整、子拓扑嵌套。
拓扑具备版本号，每次 Patch 提交生成新版本，执行器仅读取一致的版本快照
所有变更具备事务性，原子提交，避免图结构撕裂
4.2 三类标准节点
表格
节点类型	形态	生命周期特征	上报规则
程序节点（Code Node）	纯后台程序 / 脚本 / 系统调用	自主异步运行，不受 SA 阻塞	仅上报关键里程碑与终态，细碎进度由执行器过滤
AgentLoop 节点	封装封闭 ReAct 循环的 LLM 实例	一次性批次执行，跑完即结束	仅上报最终结果事件，内部工具调用不向上冒泡
子拓扑节点（Subgraph Node）	递归嵌套的独立拓扑图	内部自治调度，对外呈现统一节点契约	可配置冒泡事件范围，终态统一向上上报
4.3 两类边语义
顺序依赖边（→）
语义：上游节点达到终态（成功 / 失败）后，下游节点满足启动条件
触发次数：单次
适用场景：线性任务流水线、终态触发后续处理
事件订阅边（⇢）
语义：不等待上游节点终态，监听到指定里程碑事件即触发下游
触发次数：可多次触发，每次生成临时执行节点
适用场景：长生命周期状态机的中间事件响应，如通话中的语音交互
五、事件驱动的编排循环
SA 单轮事件处理遵循「思考 → 调整 → 验证」低轮次闭环，全程无阻塞，单轮通常仅 1~2 次 LLM 调用，处理完成立刻静默。
5.1 三步标准循环
思考：加载任务上下文快照 + 当前事件，LLM 判断事件影响、决策是否调整拓扑、生成调整方案
调整：将决策转化为原子化 Patch 集合，支持操作：
新增 / 删除节点
新增 / 删除 / 修改依赖边
取消指定活跃节点
拆分节点为子拓扑
修改节点参数与优先级
验证：规则引擎对 Patch 做合法性校验
拓扑无环校验
依赖边语义合法
节点类型与参数合规
取消操作作用于有效活跃节点
校验通过提交执行器，不通过则回退或重试。
5.2 全委派执行机制
SA 仅内置拓扑操作、任务管理、权限校验、订阅管理、规则校验等元能力，无任何业务工具
所有业务逻辑、工具调用、计算任务全部下沉到拓扑节点，由独立执行器调度
SA 不介入节点内部执行过程，仅通过事件接收状态反馈
六、节点中断与取消协议
6.1 取消指令传递链路
plaintext
SA 生成取消 Patch → 提交执行器 → 定位目标节点 → 下发中断信号 → 节点响应 → 上报终态 → SA 更新拓扑
全程异步，SA 下发指令后不阻塞等待，节点取消完成后通过事件回执。
6.2 分级中断实现
程序节点
软中断：发送优雅退出信号，节点执行资源清理与进度保存后上报 Cancelled
硬终止兜底：软中断超时无响应，执行器强制终止进程，标记 ForceCancelled
AgentLoop 节点
中断信号注入 ReAct 循环，触发收尾后主动退出
卡死无响应时由执行器强制终止实例
子拓扑节点
递归中断：取消信号向下传递到所有内部活跃节点，逆序执行
原子回执：所有内部节点终止后，统一向上上报一次终态事件
6.3 兜底保障
所有节点取消后必须上报终态，同步回收资源
执行器维持心跳检测，失联节点自动强制清理
取消操作幂等，重复下发无副作用
七、典型场景推演
案例 1：异步文件下载与内容解析
任务目标：下载远程 PDF，提取联系人信息，整理成表格通知用户。
初始拓扑生成
事件：[用户指令] 下载PDF并提取联系方式
SA 生成初始拓扑，提交后静默：
Code:下载PDF → AgentLoop:提取联系人 → Code:发送结果通知
执行器启动下载节点，后台自主运行。
正常流程
下载进度事件由执行器过滤，不上报 SA；下载完成后上报 Succeeded
SA 唤醒，校验后继节点依赖满足，无需改图，Patch 为空，静默
执行器启动 AgentLoop 解析节点，完成后上报 Succeeded
通知节点执行完成，拓扑无待调度与活跃节点，任务标记完成归档
异常分支：下载失败
下载节点上报 Failed，SA 唤醒生成 Patch：
删除提取联系人、发送结果通知节点
新增发送失败通知节点
校验提交后执行，任务标记失败归档。
案例 2：通话状态机会话任务
任务目标：拨打指定号码，接通后确认会议时间，结束后整理成备忘录。
2.1 通话子拓扑原生状态机（固定不可修改）
表格
当前状态	触发条件	下一状态	抛出事件	事件等级
空闲	下发拨号指令	拨号中	Milestone: Dialing	普通（默认过滤）
拨号中	对端振铃	振铃中	Milestone: Ringing	普通（默认过滤）
振铃中	对端接听	已接通	Milestone: Connected	关键里程碑
已接通	收到对端语音	已接通	Milestone: SpeechReceived	关键里程碑
已接通	任意端挂断	已挂断	Succeeded（含完整转写）	终态事件
拨号 / 振铃中	拨号失败 / 拒接 / 空号	已挂断	Failed（含失败原因）	终态事件
2.2 上层初始拓扑
plaintext
Subgraph:通话会话
  ⇢ [监听 SpeechReceived] AgentLoop:生成应答话术（临时节点模板）
  → [监听 Succeeded] AgentLoop:整理会议结果
2.3 全流程推演
拨号与振铃阶段
子拓扑自主流转，Dialing、Ringing 事件被执行器过滤，SA 保持静默。
接通阶段
子拓扑抛出 Connected 事件，SA 唤醒后判定无绑定后继节点，Patch 为空，静默。
通话交互阶段
对端说话，子拓扑抛出 SpeechReceived 事件，匹配订阅边规则：
SA 唤醒，生成 Patch：新增一次性临时 AgentLoop 节点，输入为语音文本，输出对接通话播放接口
校验提交后节点执行，生成应答并播放，执行完成后节点自动销毁
SA 回到静默，每轮对话重复该闭环
挂断收尾阶段
对端挂断，子拓扑抛出 Succeeded 终态事件，匹配顺序依赖边：
SA 唤醒，清理未执行的临时应答节点，激活「整理会议结果」节点
执行器启动整理节点，完成后任务归档
异常分支：拨号失败
子拓扑抛出 Failed 事件，SA 生成 Patch：删除整理节点，新增拨号失败通知节点，执行后任务标记失败归档。
案例 3：多任务联动与中断取消
场景背景：SA 常驻系统，同时处理系统自动触发的磁盘清理任务与用户提交的下载任务，验证跨任务订阅与中断机制。
任务初始化
磁盘告警触发自动创建任务 T003（磁盘清理），拓扑：扫描大文件 → 清理缓存 → 发送清理通知
用户提交大文件下载任务 T004，同时订阅全局磁盘空间事件
跨任务联动
下载写入导致磁盘使用率达 95%，全局层推送告警事件到 T004
T004 对应 SA 唤醒，生成 Patch：
取消运行中的下载节点
新增等待磁盘空间充足的等待节点
下载节点改为依赖等待节点
执行器下发软中断，下载节点保存进度后上报 Cancelled，SA 更新拓扑后静默
恢复与终止
T003 清理完成，磁盘空间回落，全局层广播空间充足事件
T004 等待节点满足条件，下载节点重新启动
用户下发取消下载指令，SA 生成 Patch：取消所有活跃节点、删除待调度节点、标记任务取消
执行器执行中断兜底，所有节点终态上报后，任务归档释放资源
八、待深化的工程问题
事件分级过滤规则：标准化事件分级策略，明确执行器直接过滤与必须唤醒 SA 的边界，降低 LLM 调用开销
通用条件节点标准化：将等待事件、等待资源类节点固化为第四类标准内置节点，减少 LLM 动态生成的不可靠性
Patch 冲突处理机制：高并发事件下多 Patch 版本合并、事务回滚的具体规则
子拓扑事件冒泡契约：明确子拓扑内部事件的冒泡范围与过滤规则，避免细碎事件淹没顶层 SA
