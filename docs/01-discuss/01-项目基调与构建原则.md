# 01 · cppchain 项目基调与构建原则

> 本文档是 cppchain 的**底座**，所有后续讨论、架构、设计与问题分析都以它为原点，不违背本文的方向。

---

## 一、项目定位

- **项目名称**：cppchain
- **技术基础**：C++26
- **本质**：langchain 与 langgraph 的**简化复刻版本**
- **主要目的**：**学习大模型（LLM）与 Agent 开发**

### 四条定性

1. **不是完整版本** —— 不追求与 langchain/langgraph 功能对齐，只复刻其核心思路与骨架。
2. **一点一点做起来的版本** —— 从零起步、逐步叠加，每一步都要先跑通。
3. **实验场** —— 专门用来**实验各种 Agent 理论和想法**，允许大胆尝试、验证、推翻、重来。
4. **偏底层构建** —— 尽量少用重型外部依赖，核心逻辑自己实现，吃透原理。

---

## 二、构建原则

> **"沿着 langchain 的思路，从底部向上逐步构建。"**

- **自底向上（bottom-up）**：先构建基础能力，再构建上层 Agent 能力。
- **仍以 langchain 的思路为参照**：我们在"思路"上跟随 langchain，在"实现"上独立完成。
- **先跑通、再演进**：在不偏离整体思路的前提下，能用简单实现就先落地，之后基于实验结论优化。

### 初始的"自底向上"大致顺序（可讨论调整）

1. 基础抽象层：`Message`、`Model`（LLM 封装）、`PromptTemplate`
2. 输出层：`OutputParser`、结构化输出
3. 工具层：`Tool` 抽象、工具调用（function calling）
4. Agent 核心：Agent 循环、工具路由、记忆（Memory）
5. 编排层：链（Chain）→ 图（Graph，langgraph 思路）、多智能体（SubAgent / ForkAgent）
6. 高级议题：上下文压缩、工具检索、超长工具返回、工具副作用等

> 具体"第一块积木"选什么、顺序怎么排，放到讨论区讨论（见 `docs/01-discuss/`）。

## 三、文档主线：问题分析与 Demo 验证

本项目文档的核心内容，是**记录大模型与 Agent 开发中常见的问题**：

- 对**每类问题**做独立分析；
- 提出**多种解法**并横向对比；
- 为每种解法提供**可运行的 demo** 进行验证；
- 给出**本项目选型结论**。

### 已列入的典型问题（持续增补）

1. 上下文压缩（Context Compression / Compaction）
2. 大批量工具查找（Tool Routing / Tool Retrieval）
3. 超长工具返回（Long Tool Response）
4. 工具副作用（Tool Side Effects）
5. SubAgent / ForkAgent 使用（子智能体 / 分叉智能体的编排与通信）

### 统一文档结构（每个问题一版）

`问题场景与产生原因 → 常见解法横向对比 → langchain/langgraph 对应做法 → 本项目选型与理由 → Demo 设计与验证结论`

对应落地目录：[`docs/04-problems/`](../04-problems/README.md)。

## 四、文档组织规则

1. `docs/` 下文件**分子目录分类保存**，至少包含：讨论（`01-discuss/`）、架构设计（`02-arch-design/`）、详细设计（`03-detail-design/`）等目录。
2. **目录名、子文件名都以数字开头**编号，保证阅读顺序。
3. 讨论（discuss）→ 架构（arch-design）→ 详细设计（detail-design）→ 问题分析（problems）之间形成**沉淀链条**：讨论有的结论，落进架构/详细设计；问题分析围绕核心问题展开。
