# 07 · 复杂任务：规划 → 执行 → 验证环（可中断 / 可回退）

> **定位**：05 未来专题规划「复杂任务」（#2）的**第一个具体落点**，不是全部，是最有价值的一刀。
> 状态：🟡 **已记录、待启动**（本稿只建档，不实现）。
> 开工后按项目基调走：`02-arch-design/` 定架构 → `03-detail-design/` 定细节 →
> `examples/` 出 demo → 结论沉淀 `04-problems/`。

## 一、动机：任务级缺的不是"更多原语"，是"组织"

wfr 现在已经能：工具级打断（`approve_tools`）、循环里反复迭代（`loop`）、执行防护与副作用治理
（ExecutionGuard / 审计 / 沙箱 / 审批）、崩溃恢复（M10 checkpoint + 会话日志回放）。**但任务的
"组织层"还没有**，具体三处缺口：

1. **没有"计划"这个一等公民**：执行是"模型自由发挥"，没有结构化步骤清单、没有每步的**验证判据**
   （怎么算完成）；"规划"和"执行"没有分开，无法审计"这步本来是干嘛的"。
2. **中断停留在"动作级"**：能按一个工具、批一个命令，不能"在任务中间停下来看一眼进度，改一下
   计划再继续"。
3. **回退停留在"丢弃边界"**：能销毁沙箱、能 checkout 快照，不能"回退到第 K 步、换个方法重跑
   后续步骤"。

## 二、期望能力（规划 → 执行 → 验证）

- **规划**：产出结构化计划 = 步骤序列，每步 = `{目标, 验证判据, 依赖}`。计划作为**可审计的数据**
  进 state（随会话日志落盘、可回放）；规划与执行分离（一次规划 / 失败后局部重规划）。
- **执行**：按步骤推进，**步骤边界 = 独立 checkpoint + 中断落点**。每步的执行结果、统计、决策留痕。
- **验证**：每步执行后跑该步的**验证判据**——优先 `ToolSpec::probe`（自动化、只读、可断言产物）；
  价值判断类判据留给"人在中断点复核"。验证失败 → 修复 / 重试 / 降级 / 回退（策略可选）。
- **可中断**：任意**步骤边界** interrupt 悬挂（复用 M10 interrupt + checkpointer），resume 从该步
  继续；中断的**理由与意向（Intent）**落日志（承接 ExecutionGuard 的 intent 语义）。
- **可撤回/回退**：两级粒度——
  ① **单步/定点回退**：状态回到第 K 步（计划 + 结果），从 K 换法续跑（M10 时间旅行 fork 的底座）；
  ② **整计划回退（丢弃边界）**：沿用 06 §7 的 L7 结论——**不做命令反做**，回退 = 沙箱销毁 /
    git 快照 checkout / probe 意向校验，边界级丢弃。

**结论**：本专题**不是造新原语**，而是把已有件**组装成"计划 → 执行 → 验证"的任务级环**，并定义
"中断/回退"在任务维度的语义。

## 四、第一问（启动切入点）

1. **验证粒度与判据形态**：每步验证 vs 整任务验证？"验证判据"怎么表达——复用 `probe`（只读断言
   产物状态），还是要一档"验证语句"（LLM 复核，需防注入）？哪类步骤值得验证、哪类跳过（只读/查询）？
2. **回退语义**：回退 = 状态回到第 K 步 + 重放后续，还是丢弃边界重来？"**部分成功的步骤**"怎么记
   （失败步之前的副作用算不算要回撤——沙箱场景销毁即回，但宿主场景只能快照）？回退的**裁量权**给谁
   （模型自查 / 人在中断点决定 / 策略表）？
3. **中断落点与计划可变性**：中断只在**步骤边界**（不在步内）？中断时人类能否**改计划**（加/删/换
   步骤）——计划是否必须提交为不可变快照（防改判导致审计断裂）？
4. **计划的一等公民形态**：计划 = 数据（state 里的 `plan`：步骤数组）？独立的 `plan` 节点（生成计划、
   可 route 到执行/要求澄清）vs 状态里存计划键？规划是否要**自评价闭环**（执行后复盘 → 修正计划）？
5. **重规划**：计划会过期（环境/前置失败变了）——失败时是"就近修这步"还是"回规划层重排"？

## 五、验收预想（按项目基调）

- `examples/plan_execute_demo`（+ 内置 workflow）：给目标 → 产出计划 → 逐步入执行 → 每步验证；
- **中断演示**：执行到第 N 步边界停顿，人复核后 resume 续跑（复用 interrupt 悬挂/恢复路径）；
- **回退演示**：第 N 步验证失败 → 回退到第 K 步 → 换法续跑成功；审计里能看到
  `plan/verify/decision/{interrupt_at, rolled_back_to}` 全链路；
- 全仓全绿、零告警。

## 六、边界与开放问题

- **不做命令反做**（沿用 06 §7 L7）；宿主场景回退靠快照（git/worktree），沙箱场景靠销毁。
- 验证的"价值判断"部分大概率仍要人（= 中断点放哪的问题），probe 只管"产物状态对不对"。
- 计划会过期 → 需要"重规划"，是 P-E-V 环的粘合剂，别把它做成一次性的。
- 与 05 #3「长程任务」的关系：本专题做**单轮**复杂任务；长程是**多轮分批**（多次触发、可感受时间
  变化）—— 先做单轮，长程是它的自然上卷。
- db：计划的数据形态（JSON 步骤数组 + 每步验证判据的 schema）是第一个要定的细节，别过度建模。
