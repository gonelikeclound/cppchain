# 04 · C7 打电话：逐事件推演

> 日期：2026-10-29
> 对象：[`03`](./03-案例推演集.md) 的 C7
> 结论：**走通了。** 但推演推翻了 `03` 里 G-b 的解法，并暴露两个新缺口（G-h、G-i）。

---

## 1. 场景

用户："给妈妈打电话，问她晚上来不来吃饭。"

实际发生：拨号 → 振铃 → **妈妈拒接** → 5 秒后重拨 → 振铃 → 接通 → 通话 95 秒 →
**用户中途改口"算了，发个微信就行"** → 挂断 → 改发消息 → 送达 → 向用户汇报。

总时长约 2 分 40 秒。系统产生的事件量（含音频帧、协议信令、传感器）：**数千条**。
SA 需要"看见"的：**6 条里程碑**。

---

## 2. 结论先行

| # | 结论 | 影响 |
|---|---|---|
| **R1** | **G-b 的解法不是 `interrupts` 字段，而是"双平面"：业务平面 + 并发控制平面** | 契约改一处；`04` 的"语义压缩"结论在此兑现（4N 条边 → 4 条） |
| **R2** | **重拨策略属于节点契约（声明式），不属于 SA 编排** | 一通电话的 SA 唤醒从 7 次降到 3 次 |
| **R3** | **"要不要停"由节点本地判定，"停了以后干什么"由 SA 判定** | 这是低延迟与可编排的分界线 |
| **R4** | **输出槽存引用不存内容**（`transcript_ref`），内容永不进 SA 上下文 | 上下文治理的一条硬规则 |
| **R5** | 新缺口 **G-h**：缺 `update_node`（运行中参数修订） | patch 原语集要加一项 |
| **R6** | 新缺口 **G-i**：任务契约缺 **fallback ladder**（无人可用时的确定性降级链） | 否则"用户目标"在 SA 挂掉时无人负责 |

## 3. 时间轴推演

> 列释义：**SA 醒?** = 是否触发 L1b 编排唤醒（一次模型调用）；**动作** = 谁做了什么。

| T | 事件 | 谁处理 | SA 醒? | 动作 |
|---|---|---|---|---|
| 0s | 用户 query | SA | — | 生成图：`N_call` → `N_summarize` → `N_assert` → `N_reply` |
| 0.2s | `patch_graph(add_node ×4)` | SA | — | V1–V7 通过 → 提交 |
| 0.3s | `call.dialing{attempt:1}` | N_call | ❌ | 仅 L1a 增强 digest |
| 4s | `call.ringing{attempt:1}` | N_call | ❌ | digest 更新 |
| 22s | `call.rejected{attempt:1}` | N_call | ❌ | **按 `retry_policy` 内部决定重拨**（退避 5s） |
| 27s | `call.dialing{attempt:2}` | N_call | ❌ | — |
| 33s | `call.ringing{attempt:2}` | N_call | ❌ | — |
| 51s | `call.answered{after_ms:48000}` | N_call | ❌ | 进入 `Talking` |
| 51s–146s | 音频帧、静音检测、语音活动……（数千条） | N_call 内部 | ❌ | **全部不进 SA 上下文** |
| 120s | 用户说"算了，发个微信就行" | **N_call 控制平面** | ❌ | 本地判定 → 执行 `hang_up` → `Ended{user_redirected}` |
| 146s | `call.ended{reason:user_redirected, disposition:redirect_messaging}` | N_call | ✅ | SA 醒：加 `N_message` 节点，`rewire` 到 `N_assert` |
| 146s | `patch_graph(add_node, rewire)` | SA | — | 验证通过 → 提交 |
| ~150s | `msg.sent{to:妈妈, channel:wechat}` | N_message | ❌ | digest 更新 |
| 151s | `msg.delivered` + `assert: 已获得答复 ∨ 已切换渠道并送达` | N_assert | ✅（可选） | 若断言失败 → 唤醒 SA |
| 152s | 向用户汇报 | N_reply | — | 任务终态 `Completed` |

**SA 模型调用总计：3 次**（初始编排 / 改道编排 / 断言失败兜底）。
通话持续 146 秒，其中 **SA 静默 146 秒，零 token**。

## 4. 关键机制：节点内部是**双平面**，不是"一个 FSM + 一堆出口"

### 4.1 先承认 `03` 的 G-b 提错了

`03` 里我写的是"给契约加 `interrupts`（可与任何状态并发的事件集合）"。
推演 C7 时发现这是**补丁式想法**，它只是把问题换个名字：

> 若业务状态有 N 个、控制事件有 M 类，则为每个状态补出口 = **N × M 条边**。
> 电话的业务状态是 6 个，控制事件至少 4 类（用户改口 / 外部取消 / 预算超限 / 链路失效）→ **24 条边**，
> 而且每加一个状态或一类控制事件都要重算一遍。

**正确形态是 statechart 的正交并发区域（orthogonal regions）：**

```
Node N_call
├── 业务平面（business region）
│     Idle → Dialing → Ringing → Connected → Talking → HangingUp → Ended
│                       ↘ Failed{rejected|no_answer|busy|unreachable}
│
└── 控制平面（control region，与业务平面并发活跃）
      Idle ─(事件)→ Decide ─→ Terminate / Redirect / Continue
      事件：user_barge_in / cancel_requested / budget_exceeded / link_lost
```

控制平面每个事件的出口只有一条，**与业务状态数无关**：**24 条边降为 4 条**。

这正是调研里那条"S**语义压缩**"结论的具体兑现（`_research/04` §1.1：扁平 FSM 状态数是乘积，statechart 是加和）。
在这条 case 之前，"层次+并发"只是纸面上的好处；C7 让它变成了可数的边数。

### 4.2 控制平面的强制规则

| 规则 | 理由 | 验收 |
|---|---|---|
| 控制平面**永不被业务平面阻塞** | 用户说"别打了"，不能因为对方正在说话而延迟 | 注入控制事件的响应 p99 与业务状态无关 |
| 控制事件的**处置必须映射到业务平面的合法转移** | 不能出现"控制平面已终止、业务平面还在 Talking" | 静态检查：控制平面每条边都指向业务平面的合法目标态 |
| 控制平面**不产生对话内容** | 它只做"停/改/继续"的判定 | 控制平面输出只有枚举，无自由文本 |
| 控制平面的判定**允许本地小模型** | "算了"是意图判定，需要语义 | 该调用计入节点 budget，不计入 SA 的编排预算 |

> 注：控制平面的本地判定**也是一次模型调用**，但它属于**节点内部**，因此：
> ① 不唤醒 SA；② 走节点自己的 budget；③ 结果记账在节点账本里。
> 这就是"能力内闭环，只在不知道怎么办时上报"。

## 5. 职责切分：谁决定什么

这张表是 C7 最重要的产出。**边界划错，就会退化成"每个事件问一次模型"。**

| 决策 | 谁 | 为什么 |
|---|---|---|
| 拨通后要不要等对方说话 | 节点（FSM 定时器） | 无决策含量 |
| **拒接后要不要重拨** | **节点（`retry_policy` 声明式）** | 是规则，不是判断；SA 介入只会变慢 |
| 重拨用尽后怎么办（换微信 / 放弃 / 问用户） | **SA** | 需要跨能力的目标级决策 |
| 通话中用户说"算了"要不要挂 | **节点（控制平面本地判定）** | 延迟敏感；挂断不能等 SA |
| 挂断以后做什么 | **SA** | 目标级改道 |
| 对话里是否问到了答案 | 下游 `N_summarize`（AgentLoop） | 需要理解内容 |
| 目标是否达成 | `N_assert`（纯函数校验断言） | 不能自报 |
| 超时/预算耗尽 | 节点（`budget`）→ 上报 `exhausted` | 确定性触发 |

**一句话原则：越靠近"执行"的决策越往下沉，越靠近"目标"的决策越往上浮。**

### 5.1 重拨策略放在节点里（R2）的具体收益

如果重拨由 SA 决定：拒接 → 唤醒 SA（1 次模型调用）→ 加一个"重拨节点"→ 再跑。
一次拒接就吃掉 1 次调用 + 一次图变更 + 一次验证。

声明式写法：
```yaml
retry_policy:
  max_attempts: 2
  backoff_ms: 5000
  retry_on: [rejected, no_answer, busy]
  escalate_on_exhausted: true   # 用尽后发 call.exhausted 给 SA
```

**这是"确定性脊柱"在能力层的具体形态**：能力自己知道怎么重试，SA 只在"能力也不知道怎么办"时出现。

## 6. 里程碑词汇表：SA 的全部感官

C7 的通话产生数千事件，进 SA 上下文的只有这些类型：

| 里程碑 | 何时发 | SA 醒? | 载荷 |
|---|---|---|---|
| `call.dialing` | 每次拨号 | ❌ | `{attempt}` |
| `call.ringing` | 振铃 | ❌ | `{attempt}` |
| `call.answered` | 接通 | ❌ | `{after_ms, attempt}` |
| `call.rejected` | 对方拒接 | ❌（策略内重试） | `{attempt}` |
| `call.unreachable` | 关机/空号/网络 | ❌ | `{reason}` |
| `call.exhausted` | 重试策略用尽 | ✅ | `{attempts, last_reason}` |
| `call.user_correction` | 用户中途改口 | ❌（节点自处理） | `{intent}` |
| `call.ended` | 终态 | ✅ | `{reason, duration_ms, disposition}` |

**明确不进词汇表的东西**（进了就等于把音频灌进上下文）：

- 音频帧、静音、音量、DTMF
- 逐句转写内容（改为输出 `transcript_ref`）
- 每次振铃的精确时刻
- 网络抖动

> **词汇表就是 SA 的视网膜**。视网膜分辨率定得太高，大脑处理不过来；定得太低，看不见东西。
> 这张表应该被当作**接口契约**来评审，而不是日志格式。

### 6.1 R4：输出槽存引用，不存内容

`N_call` 输出 `transcript_ref`（一个引用），不是转写文本本身。

- `N_summarize` 需要内容时**自己去拉**（它的输入是引用）；
- SA 全程只看到 `transcript_ref` 存在与否，**永远不读内容**；
- 副作用：任务结束后，转写内容仍可审计（在节点账本里），但从不进编排上下文。

这条规则应当写进契约（`outputs` 的每一项声明为 `by-reference` 或 `by-value`，默认 `by-reference`）。

## 7. 新缺口

### G-h｜缺 `update_node`：运行中参数修订

**暴露点**：用户改口的第二种形态 —— "等等，先问她明天有空吗"。

这不是取消，是**目标改了**。`03` 的 patch 原语只有 `add_node / cancel_node / rewire / bind_input / set_budget`，
**没有"改运行中节点的参数"**。

为什么不能"取消 + 新建"：重拨一通电话的**社交成本**不可忽视，而"改个参数"没有这个成本。

建议加：
```
update_node(node_id, params_delta)
```
约束（否则会破坏"节点独立运行 + 输入不可变"）：

- 只允许改**声明为 `mutable` 的参数**（契约里显式列出），其余一律拒绝；
- 必须走 patch，带 `base_revision`；
- 节点必须声明**能否在中途接受参数修订**（有的节点只能在状态边界接受，如 `Talking` 可改目的，`Dialing` 不可）；
- 校验器新增 **V8**：`update_node` 的目标参数必须在 mutable 白名单内，且当前状态允许修订。

### G-i｜任务契约缺 fallback ladder

**暴露点**：`call.exhausted` 唤醒 SA，但如果 SA 此刻也不可用（预算耗尽 / 模型故障 / 任务已 stuck）呢？

那么"给妈妈打电话问她来不来吃饭"这个**用户目标就无人负责**了——这才是真问题。
节点有 `retry_policy`，但**目标层没有对应的降级链**。

建议在**任务契约**里声明确定性的降级阶梯：

```yaml
goal_assertion: 已获得答复
fallback_ladder:
  - 打电话（attempts: 2）
  - 发微信（attempts: 1）
  - 发短信（attempts: 1）
  - notify_user("联系不上，已尝试电话/微信/短信")
```

特性：

- **纯声明式，不含模型调用**，因此在 SA 不可用时仍可执行；
- 由**确定性执行器**沿阶梯推进，只在"整个阶梯耗尽"时进入 `NeedsHuman`；
- SA 在可用时可以**提前跳出阶梯**（它比阶梯聪明），但阶梯保证了底线。

**这条我认为很重要**：它把"用户目标"从"SA 的编排产物"提升为"任务契约的一部分"。
即使编排层挂了，目标仍有确定的兜底路径——这与 `02` §6.1 的"完成必须可证"是同一思路的另一半：
**完成要可证，完不成也要有交代。**

### G-j（次要）｜补偿的"代价标签"

挂断电话物理上可恢复（重拨即可），但**社交上不可恢复**。
`reversibility: {physical, cost, social}` 三维标签比单一 `compensable: bool` 更准。

暂不纳入 v1，记为观察项：如果后续出现"SA 因为不知道代价而做错决策"的案例，再加。

## 9. 一句话总结

**C7 之所以能走通，不是因为状态机"更聪明"，而是因为把决策放到了正确的层：**
会重试的重试、该挂断的挂断、该问人的问人、该编排的编排——
**每一层只做自己不可让渡的那部分判断**，中间用一个明确的双平面触点把它们接起来。
