# SystemAgent 专题

> 定位：讨论并设计「**事件驱动 + 状态机驱动**」的系统级 Agent（SystemAgent，下称 SA），
> 与 DSH 现有的 ReAct 循环式 Agent 做对照，界定它解决什么、不解决什么、以及在我们代码库里怎么落。

## 一句话命题

传统 ReAct 的形状是 `调用工具 → 等返回 → 思考 → … → 终态`。
SA 的形状是 `事件 → 状态跃迁 →（仅在声明的接缝处咨询模型）→ 新状态 → … → 终态`。

**核心差异不是"循环 vs 事件"，而是"谁站在每一次状态跃迁的关键路径上"。**
ReAct 把 LLM 放在每一次跃迁的必经之路上；SA 把 LLM 降级为**在显式 gate 上被咨询的专家**，
而把确定性跃迁交给机器自己推进。

## 六个核心命题（部分已定）

| # | 命题 | 一句话 |
|---|---|---|
| ① | 异步不是"立刻返回" | 立刻返回只是句柄；真正的异步 = 句柄 + **持久化续体** + 幂等重入。缺任一项都是假异步。 |
| ② | 状态机是脊柱，模型是顾问 | 长生命周期能力（通话/导航/媒体）的 FSM 由系统声明；模型只负责"意图→参数"和"未知事件怎么办"。 |
| ③ | 事件不能直接进对话 | 机器是 actor，对话是唯一串行资源。中间必须有**观测归约 + 咨询协议**，否则上下文爆炸或并发打架。 |
| ④ | SA 不执行，只编排 | SA 的动作只作用于**图**；图外的世界只由节点改变。可直接验收：SA 的工具集里没有改变外部世界的动词。 |
| ⑤ | 上下文是投影，不是历史 | `state = fold(events)`；任务每次醒来看到的 L2 是**装配出来的**，等待期整体丢弃。 |
| ⑥ | 退出必须可证，证不出就交善后 | 协作式取消不可能 100% 成功。允许 `abandon`，并派**清理任务**收尸；触发者是运行时 Reaper，不依赖 SA 醒来。 |

## 与相邻专题的关系

- **`高可信/`**：管「做得对不对」（意图/合规/真实/可回溯）。SA 管「怎么组织执行」。SA 的确定性脊柱天然服务于
  「执行合规性」与「可回溯性」——因为确定性路径不经过模型，才可以被测试和审计。
- **`主动智能/`**：管「什么时候开始」（触发器）。SA 管「开始之后以什么形态运行」。触发器给 SA 送事件，是 SA 的事件源之一。
- **DSH 本体**：`agent-loop` 是唯一持有具体循环逻辑的包，因此 SA 不应 fork 循环，而应以插件形态**寄居在循环之外**，
  只在需要咨询时开一轮模型 turn。

## 演进记录

- **2026-10-29（续·七）**：设计 mock 体系。摸清 DSH 已有 `llm-mock-server` / `llm-replay` / `agent-loop-testkit` / `invariants` 四件可直接复用，
  SA 只需新建虚拟时钟、世界模型、有状态能力 mock、场景 DSL 四件。
  核心判断：**机制测试不经过自然语言**（用 oracle-patch 直灌），**断言只查世界不查返回值**（mock 必须能说谎），
  **CI 里不许有真模型、质量评估里不许有假模型**。落地分 M0–M4，M0（验证器纯函数）只需 2~3 天且不需要任何基建。
- **2026-10-29（续·六）**：推演 C6（事件洪水，4 000:3 信噪比）。
  **收回 `02` 「L0/L1a 必须纯函数」的教条**，改为「漏斗宽度约束」（每级放大倍数有界 + 单位成本递减一个数量级），
  并新增 L0-b 廉价语义层（**禁用主模型**）。新增：不可丢白名单（独立于订阅，SA 无权改）、
  漏报审计（影子通道 + 回收审计 + miss_rate）、**打扰预算**（一等资源）。
  成本账：24k token/夜 vs 6M token/夜，差 250 倍。核心判断：**常驻 agent 的死法不是太贵，是太烦。**
- **2026-10-29（续·五）**：解决 C1 的负收益。结论：**不做任务过滤器，改做"图的形状"**。
  档位 = 多节点图 / 单节点融合图 / 预编译图，共用同一份契约与账本，因此升级只是换形状而非换系统。
  关键：**fusion（编排即执行）** 是唯一能把 C1 降到 1 次调用的办法；
  分诊不是独立阶段而是编排的退化结论；**fail-open**（不确定一律走多节点图）；
  撞墙靠 8 个运行时结构信号检测，不让模型自报；升级无损且不刷预算；高频图自动固化为预编译（HEXIS 依据）。
- **2026-10-29（续·四）**：推演 C7（打电话），结论：**走通**。
  关键修正：`03` 提的 `interrupts` 字段作废，正确形态是**并发控制平面**（业务区 + 控制区），
  把控制事件的边数从 N×M 降为 M —— 这是 statechart 语义压缩在真实 case 上的兑现。
  另确立：重拨等策略属节点契约（SA 唤醒 7→3 次）、"要不要停"节点判/"停了干什么"SA 判、输出槽默认 by-reference。
  新缺口：**G-h** 缺 `update_node`（运行中参数修订）、**G-i** 任务契约缺 fallback ladder。
- **2026-10-29（续·三）**：改用 case 反证设计，产出 03 推演集（13 个 case）。
  写 case 的过程发现七个缺口 G-a~G-g，其中三个要求硬决定：
  **G-b**（须区分"等完成"与"等打断"→ 状态机要并发控制区）、
  **G-e**（L0 过滤器是唯一静默丢弃点，必须有漏报审计）、
  **G-f**（`waits` 若允许自由谓词，静态死锁检测即不可判定）。另发现小任务上 SA 可能负收益（C1）。
- **2026-10-29（续·二）**：拍板 D1–D4 —— 终态须含断言；改图强制 patch 记账；接受 `abandon`；
  **abandon 后交专门的清理任务善后，触发者为运行时 Reaper（不依赖 SA 醒来）**。
  由此新增：节点契约第九项 `resources`（资源账本，善后的前提）、善后六步（对账→补偿→释放→隔离→出证据→上报）、
  防递归深度上限 1、善后不得改写已完成节点的产出。命题增至六条。
- **2026-10-29（续）**：产出 02 架构草案首稿。新增四条结构决定：SA 双模（任务式/常驻式）同一引擎；
