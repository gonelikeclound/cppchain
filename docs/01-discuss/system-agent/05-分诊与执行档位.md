# 05 · 分诊与执行档位：档位不是执行器，是"图的形状"

> 日期：2026-10-29
> 前置：[`02` 架构草案](./02-任务拓扑图与两层上下文-架构草案.md)、[`03` C1](./03-案例推演集.md)
> 起因：C1（"装个安装包"）暴露 SA 在小任务上可能负收益。结论：**不是加过滤器，而是让"简单任务"在同一个语义里自动变便宜。**

---

## 0. 问题

C1 的账：ReAct 一次工具调用干完的事，SA 要 4~5 个节点、1 次编排 + 1 次 AgentLoop + 验证。
**如果小任务上 SA 比 ReAct 贵，这套架构在 80% 的日常场景里没有落地价值。**

但"加个过滤器把简单任务挡在外面"这个直觉有个陷阱，先说清楚。

---

## 1. 结论先行

| # | 结论 |
|---|---|
| **R1** | **"过滤器"是错的隐喻。** 判断"简单"需要理解意图，理解意图就是编排推理 → 分诊会变成小一号的 SA，成本原地不动。 |
| **R2** | **档位不是三种执行器，是图的三种形状**：多节点图 / 单节点融合图 / 预编译图。只有一套语义，所以不会分叉出两套 bug。 |
| **R3** | **C1 的成本解法是 fusion（编排即执行）**：单节点图允许"编排与执行合并为一轮"，成本 = 1 次调用。这是唯一能真正省掉一次调用的办法。 |
| **R4** | **分诊的错误方向只能是"放过简单任务"，绝不能是"挡住复杂任务"**（fail-open）。宁可多花钱，不可干错事。 |
| **R5** | **撞墙必须由运行时按结构信号检测，不能让模型自报"我干不了"**。模型不知道自己不该做的事。 |
| **R6** | **升级要无损且不刷预算**：交接包带"已完成动作 + 剩余预算"，升级次数上限 1。 |
| **R7** | **长期解法是固化（编译缓存）**：高频图自动编译成 Tier 0，C1 的负收益是**瞬态**的。 |

---

## 2. 为什么"过滤器"是错的隐喻

一个"简单任务过滤器"要回答"这任务简单吗"，它必须：

1. 解析意图（用户到底想要什么）
2. 识别有没有隐含的等待/分支/多能力
3. 判断成功标准是否可判

**这三件事就是编排推理本身。** 所以分诊要么是查表（能查的部分很少），要么就是一次模型调用——那这次调用不如直接拿去做编排。

> **推论：分诊不能是一个独立阶段。它是编排的退化结论——"这个任务一个节点就够"也是一种编排结果。**

这就把问题从"要不要加一层"变成"**一次编排决策，如何以最便宜的形状落地**"。

---

## 3. 核心提案：档位 = 图的形状

不要引入"三种执行器"（那会漂移出三套 bug）。**只有一个东西：图。档位是它的形状。**

| 档 | 图的形状 | 何时出现 | 模型调用 | 审计粒度 |
|---|---|---|---|---|
| **多节点图** | N 个节点 + 边 + 里程碑 | 需要等待 / 状态机 / 跨能力 / 条件分支 | 1 编排 + 各节点 | 节点级 |
| **单节点融合图** | 1 个节点，编排与执行**同一轮完成** | 无事件依赖、单能力域、线性、有界 | **1** | 单节点级 |
| **预编译图** | 0 个新节点，命中已固化模板 | 见过的高频模式 | **0** | 模板级 |

三种形状共用同一份：**任务契约 / 工具契约 / 断言 / 预算 / 账本 / 审计事件**。
所以"升级"只是**换形状**，不是换系统（这是 R2 的全部意义）。

### 3.1 fusion：C1 的成本解法

单节点图允许**融合**：SA 在同一个 turn 里决定"就一个 ReAct 节点"，然后**直接执行**，不写图、不落盘、不等里程碑。

这一步是唯一能真正把 C1 从 3 次调用降到 1 次的办法。对比：

| 做法 | C1 的模型调用 |
|---|---|
| 多节点图（当前 `02`） | 3（编排 + AgentLoop + 断言兜底） |
| 单节点图（先写图再执行） | 2（编排 + 节点执行） |
| **单节点融合** | **1** |
| 预编译（固化后） | **0** |

**fusion 的代价**：放弃了"先写图再验证"的保护。但单节点图的 V1/V7 本来就是平凡的（一条边、一个节点），
所以代价可以接受——**真正需要验证的是多节点图**。

### 3.2 fusion 的门槛（必须全部满足）

```
fusion 允许 ⟺ 能力全部 stateless
            ∧ 无事件依赖（不产生 waits）
            ∧ 单能力域
            ∧ 步数上限 ≤ N（建议 5~8）
            ∧ 预算 ≤ 小额度
```

任一条不满足 → 走多节点图。

### 3.3 fusion 仍然必须继承的规则

fusion **不是"简化版规则"**，只是"简化版形状"。以下三条必须保留：

| 规则 | 为什么不能省 |
|---|---|
| **pivot（不可补偿动作前必须确认）** | "把这个文件删了"语义极简单、结构极简单，但不可逆。**不能因为"简单"就跳过确认。** |
| **断言** | 否则"干完了"仍是自报 |
| **账本（副作用记录）** | 否则撞墙后无法无损交接 |

## 4. 分诊判据

### 4.1 判决流程

```
收到请求
  │
  ├─ ① 命中预编译模板（模板 + 参数可填）────────────→ 预编译图（0 调用）
  │
  ├─ ② 引用了 stateful 能力（make_call / navigate）──→ 多节点图（确定性，查表）
  │
  ├─ ③ 目标或成功标准不可判（语义模糊）──────────→ 多节点图（宁可多花）
  │
  ├─ ④ 预估需 ≥2 能力域 / 需等待 / 需条件分支 ────→ 多节点图（宁可多花）
  │
  └─ 否则 ────────────────────────────────────→ 单节点融合（撞墙再升级）
```

### 4.2 唯一完全确定性的判据：能力类型

能力注册表里声明每个能力是 `stateless` 还是 `stateful`：

| 能力类型 | 例子 | 允许 fusion? |
|---|---|---|
| `stateless` | `read_file` / `install_app` / `search_web` | ✅ |
| `stateful`（本身是 FSM） | `make_call` / `navigate` / `play_media` | ❌ 必须多节点图 |

**这条是查表，不是推理，也不需要模型参与。** "打电话"这个词本身就决定了它上不了快通道——
因为状态机必须有图承载（`02` §1.1 的能力层）。

### 4.3 fail-open 原则（R4）

**分诊的唯一安全方向：把复杂任务误判成简单 → 撞墙升级；把简单任务误判成复杂 → 多花一次编排费。**

反过来做（把复杂任务误判成简单并且**不允许升级**）会产生"干错事"，那是不可接受的。
所以：**凡是不确定，一律走多节点图。**

> 一句话：**分诊的错误预算应该花在钱上，不能花在正确性上。**

### 4.4 三个陷阱

| 陷阱 | 说明 |
|---|---|
| **"语义简单"≠"结构简单"** | "订一张回家的机票"语义一句话，但结构上要问日期、选航班、支付（不可逆）→ 必然撞墙。分诊看结构不看语感。 |
| **"简单"≠"可跳过确认"** | "把文件删了"简单但不可逆 → pivot 照走。 |
| **"简单"≠"一次性"** | 查天气是最简单的任务，但它**永远值 1 次模型调用**（除非缓存或固化）。这是成本下限，不要幻想再省。 |

---

## 5. 撞墙：升级信号

### 5.1 为什么不能让模型自报"我干不了"

因为**模型不知道自己不该做的事**。ReAct 循环里模型最常见的失败不是"说我不行"，而是
**自信地把不该做的事做了**（重复打开应用、跳过确认、把错误当成功）。

所以升级触发必须是**运行时可观测的结构信号**。

### 5.2 八个结构性信号

| # | 信号 | 可观测性 |
|---|---|---|
| S1 | 工具返回 `pending` / `async_receipt`（需要等待） | 契约层，确定 |
| S2 | 工具选择跨出能力域边界 | 需能力域划分，确定 |
| S3 | 步数达到上限阈值（如 N-1） | 确定 |
| S4 | 同一工具 + 相同参数被调用第二次（循环迹象） | 确定 |
| S5 | 工具返回**未声明的错误码**（未知状态） | 确定 |
| S6 | 连续 K 次工具失败且原因是**不同**的（需要重规划而非重试） | 确定 |
| S7 | 命中需要 pivot 的不可逆动作，且需要全局信息才能决定 | 半确定（pivot 可由契约标记） |
| S8 | 用户中途改口/取消事件到达（外部中断） | 确定 |

**八个全部可被运行时算出，不需要模型说一句话。**

## 6. 无损交接 + 防刷预算

### 6.1 交接包（handoff payload）

升级时传给多节点图的**不是用户的原始请求**，而是：

```
{
  goal, goal_assertion,            // 来自任务契约
  done_actions: [{tool, args, result_ref,
                  side_effects[], reversible:bool}],
  irreversible_done: [...],        // 禁止 SA 再做一遍的动作
  observation_digest,              // 上下文投影，不是原始 history
  wall_signal: S3,                 // 哪条触发了升级
  remaining_budget: {...}          // 继承，不重置
}
```

**没有 `irreversible_done`，用户就会看到"刚刚已经打开过的应用又被打开一次"。**

### 6.2 防刷预算（必须）

如果"失败就升级、升级就给新预算"，一个失败任务可以无限消耗资源。

| 约束 | 取值 |
|---|---|
| 升级次数上限 | **1** 次（单节点 → 多节点），不再往回退 |
| 预算 | **继承递减**，不重置 |
| 升级事件 | 必须记账（`escalated{from, to, signal, consumed_budget}`），可审计 |
| 升级后失败 | 走 `02` 的 `stuck` / `abandon` / fallback ladder，不再升级 |

---

## 7. 固化：负收益是瞬态的

### 7.1 机制

```
第 1 次：SA 现编一张多节点图（贵）
第 N 次：该形状被识别为高频 → 参数模板化 → 固化
第 N+1 次：命中模板 → 预编译图（0 编排调用）
```

**固化产物** = 图模板 + 参数槽 + 断言 + fallback ladder + 依赖能力的版本号。

### 7.2 固化条件与失效

| 项 | 规则 |
|---|---|
| 触发 | 同一图形状出现 ≥ K 次（建议 3），且**每次断言都通过** |
| 模板化 | 具体参数抽出为槽位；抽不出的（如自由文本目标）保留为"必须填槽"，命中时仍需 1 次填空调用 |
| 失效 | 任一依赖能力的**版本变更**或契约变更 → 模板失效，回退到现编 |
| 逃生 | 预编译图执行中出现任何撞墙信号 → **直接升级到多节点图**，并把该模板标记为"需修订" |

### 7.3 依据

这正是调研里 **HEXIS** 做的事：把 skill 编译成扩展有限状态机，静态检查 + trace 重放验收，**+16.2pp、token 降 38~89%**
（[arXiv:2609.30123](https://arxiv.org/abs/2609.30123)）。
也是 Voyager 式"技能库"的同构思路：**把成功的编排结果沉淀为可复用资产**。

> 所以 C1 的答案不是"把简单任务筛掉"，而是"**让简单任务自己变便宜**"。
> 分诊是**一次性成本**，固化是**长期收益**。

---

## 8. 两道过滤器，同一套纪律

系统里现在有两处"拒绝服务"，纪律必须一致：

| | 挡什么 | 判据 | 失败方向的代价 | 纪律 |
|---|---|---|---|---|
| **任务分诊** | 挡住"不需要图的任务" | 结构信号 + 能力类型 | 误判为简单 → 撞墙升级（多花钱） | 误判必须留痕、可回归 |
| **事件 L0 过滤**（`03` G-e） | 挡住"不需要上下文的事件" | 订阅匹配（纯函数） | 误判为无关 → **漏报（可能丢事）** | 必须抽样审计 |

**共同纪律：拒绝服务必须可解释、可审计、可回滚。** 静默丢弃是设计缺陷，不是优化。

## 9. 验收口径

| # | 验收 | 方法 |
|---|---|---|
| V-a | C1 走单节点融合，模型调用 ≤ 1 | 计数 |
| V-b | fusion 门槛被违反时**必须**拒绝融合 | 构造"含 stateful 能力"的请求，断言落到多节点图 |
| V-c | 八个撞墙信号全部可被触发且升级 | 故障注入，逐条 |
| V-d | 升级后 `irreversible_done` 里的动作**不被重复执行** | 断言副作用次数 = 1 |
| V-e | 升级不重置预算、升级次数 ≤ 1 | 记账校验 |
| V-f | 预编译模板在能力版本变更后失效 | 版本递增后断言不再命中 |
| V-g | 分诊误判全部留痕，可重放回归 | 分诊事件可回放 |

## 11. 遗留问题

1. **能力域（S2 的判据）怎么划分？** 按 app？按系统子系统？按权限域？这决定了跨域检测的准确度。
2. **fusion 的内联执行如何留痕？** 它不写图，那账本与审计事件挂在哪个对象上？（建议：挂"隐式单节点"，等价于一个不落图的节点记录）
3. **固化的 K 值与模板粒度**需要压测。
4. **"语义模糊"的判据仍是软的**——目前靠"目标或成功标准不可判"，这本身需要一次判断。但它是在编排轮内完成的，没有额外调用。

---

## 12. 一句话

> **别筛任务，改形状。**
> 一次编排决策，落在最便宜的那个形状上；形状不够用就升档，用过的形状就固化。
> **成本随"见没见过"下降，而不是随"难不难"分流。**
