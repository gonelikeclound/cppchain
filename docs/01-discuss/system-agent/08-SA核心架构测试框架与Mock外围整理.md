### 0.2 一句话命题（两源一致）

传统 ReAct 的形状是 `调用工具 → 等返回 → 思考 → … → 终态`；
**SA 的形状是 `事件 → 状态跃迁 →（仅在声明的接缝处咨询模型）→ 新状态 → … → 终态`。**

核心差异不是"循环 vs 事件"，而是**谁站在每一次状态跃迁的关键路径上**：
ReAct 把 LLM 放在每次跃迁的必经之路上；SA 把 LLM 降级为**显式 gate 上被咨询的专家**，
确定性跃迁交给机器自己推进（`01`/README）。doubao 同文的说法是**控制权反转**：
外部系统原生状态机与事件总线作主控，LLM 是按需唤醒的决策子组件，无持续运行的主循环（doubao §1.1）。

# 一、SA 的核心架构

## 1.1 定位：SA 只编排，不执行

一句话模型（`02 §0`）：

> **SA 不做任务，SA 编排队列：把每个任务表达成一张可变拓扑图，图上的节点独立运行；
> SA 平时静默，靠事件醒来，每醒一次只做一轮「思考 → 调整图 → 验证」，然后回到静默。**

关键推论 = **不变式 I1（可验收）**：SA 的动作只作用于图，图外的世界只由节点改变。
SA 没有能力直接执行领域动作——这不是权限裁剪，而是整个架构自洽的前提：
若 SA 能直接执行，则图不再是唯一真相（回放无法重建状态）、预算/权限无法按任务隔离、
SA 上下文必须装执行细节（退回 ReAct 老路）。**连"读文件"也必须是节点**（`02 §7`）。

## 1.2 六个核心命题 + 真正的空白原语

| # | 命题 | 一句话（README） |
|---|---|---|
| ① | 异步不是"立刻返回" | 立刻返回只是句柄；真异步 = 句柄 + **持久化续体** + **幂等重入**。缺一即假异步 |
| ② | 状态机是脊柱，模型是顾问 | 长生命周期能力（通话/导航/媒体）的 FSM 由系统声明；模型只负责"意图→参数"和"未知事件怎么办" |
| ③ | 事件不能直接进对话 | 机器是 actor，对话是唯一串行资源；中间必须有**观测归约 + 咨询协议** |
| ④ | SA 不执行，只编排 | SA 动作只作用于图；可直接验收：**SA 工具集里没有改变外部世界的动词** |
| ⑤ | 上下文是投影，不是历史 | `state = fold(events)`；任务醒来看到的 L2 是**装配出来的**，等待期整体丢弃 |
| ⑥ | 退出必须可证，证不出就交善后 | 协作式取消不可能 100% 成功；允许 `abandon`，派**清理任务**收尸；触发者是运行时 Reaper，不依赖 SA 醒来 |

**空白原语（`01 §7`，全行业三选二的交界处）**：

> 一个**显式迁移表**（当前状态 + 事件 → 下一状态，纯函数、可回放、可静态校验）——
> 其中某些边标注为 **gate**；穿过 gate 时发起一次**可作为记账单元重放的 LLM 咨询**；
> 咨询等待期间进程可以死，重启后凭账本继续，**不重问**。

调研已证明（`01 §0`）：异步（A）+ 恢复（C）有大量成熟范式；**（B 状态机 + D 咨询）才是空白**
——有状态机的没咨询原语、有咨询的没迁移表。v1 建议先做 **B+D 最小闭环**（一通假电话 + 两个 gate）。

## 1.3 核心模型：五个对象 + 不变式 I0

| 对象 | 定义 | 持久化 |
|---|---|---|
| **Task** | 一张拓扑图 + 一份任务日志 + 一套订阅 | 是 |
| **Graph** | 可变有向图：活跃节点集 + 边（= fold(patch 事件)） | 是 |
| **Node** | 图上一个可独立运行的执行单元，三类（§1.6） | 是 |
| **Event** | 外部世界的事实（系统事件 / 节点里程碑 / 用户输入），唯一真相 | 是 |
| **Patch** | SA 对图的一次编辑事务，带 `base_revision`，可重放 | 是 |

**不变式 I0（记账）**：图的一切演化只能通过 `Patch` 表达，回放 = 重放 Patch 序列，**不重新问 SA**。
这是"重启可恢复"的唯一依据；`base_revision` 不匹配即乐观并发拒绝（两个 SA 实例不打架，`02 §5.2`）。

**正交两层**（`02 §1.1` = doubao 双层状态模型）：

```
任务层   拓扑图（做什么 / 先后 / 并行 / 依赖）   ← 可静态检查、可编辑、可审计
            │  一个节点可以是一台状态机的宿主
能力层   FSM / statechart（一个动作内部怎么演化） ← 拨号→振铃→接通→挂断
```

**这不是二选一**：一通电话 = 拓扑图上的**一个节点**，节点内部是一台 FSM；
FSM 每次跃迁产出一个**里程碑事件**汇给 SA，SA 从不逐帧观测 FSM 内部。

## 1.4 两种运行模式、同一个引擎（doubao 五层接入）

| | 模式 A：**任务式** | 模式 B：**常驻式** |
|---|---|---|
| 入口 | 用户一个 query | 系统事件流 |
| 起点 | 生成一张图并启动 | 触发规则 → 生成任务 |
| 结束 | 任务终态 | **不结束**（SA 本身永不退出；只有任务有生命周期） |
| 主要风险 | 编排质量 | 成本、去重、**洪水** |

任务生命周期：`pending →(admit) running →(waiting / done / failed / cancelled / idle)`；
`pending` 隐含**确定性准入控制**（并发/预算上限，模型只能建议优先级，不能自己决定准入）。

doubao 的**五层视图**（层间职责切分，接 group 时一一对应）：

| doubao 层 | 核心组件 | group 侧对应 |
|---|---|---|
| 系统接入层 | 事件总线 / 用户交互入口 / 系统适配器（标准化后投递） | 事件源 + `send(target×wakeup)` 准入层（_research/05 §3，DSH 唯一水闸） |
| 全局管理层 | 任务注册表 / 订阅路由 / 资源调度（常驻） | **L1 任务表** + 准入控制 + 订阅双向 + Reaper/janitor 确定性守护 |
| SA 决策层 | 拓扑编排器 / patch 校验引擎 / LLM 决策单元（瞬时唤醒、空闲休眠） | 思考→调整→验证循环 + patch 封闭集 + 验证器 V1–V8 |
| 执行层 | 节点执行器 / 中断管理 / 状态上报（拓扑快照驱动、节点自主） | 图运行时 + 三类节点执行器 + 四级升级 |
| 存储层 | 全局状态 / 任务上下文 / 拓扑版本（读写分离、增量更新） | 事件日志（唯一真相）+ L2 装配 + patch 版本化 |

## 1.5 上下文：两层 + 瞬时装配 + 订阅 + 事件路由

### L1 任务表（SA 唯一常驻物）
每任务维持一条 **digest**（≤ 若干十字：目标 / phase / 图规模 / 最近里程碑 / 阻塞点 / revision）。
**致命风险是它自己会膨胀** → 三项机制：硬上限（20~50 条，按优先级淘汰）、priority 序、
淘汰进**归档索引**（`query_task(id)` 可取回，非常驻）。

> **谁写 digest（易漏但关键）**：digest **必须由运行时从任务事件日志 fold 出来，节点不得自写摘要**。
> 否则节点一句话就能操纵编排者的认知 = **编排层的 prompt injection**，比注入对话更危险
> （被编排者不能编辑编排者对自己的认知，`02 §4.2`）。

### L2 单任务上下文（瞬时装配，非历史）
```
任务一次"醒来"看到的上下文 =
    任务章程（稳定前缀：目标/契约/词汇表，跨醒来不变 → 可复用 KV cache）
  ⊕ L1 快照（只取相关任务）
  ⊕ 本任务 digest（折叠自事件日志）
  ⊕ 触发事件 + 订阅命中的增量
```
进入 `waiting`/`idle` → L2 **整体丢弃**，等待期零 token。

### 订阅：两条独立通路
| 通路 | 谁发起 | 语义 | 可靠性 |
|---|---|---|---|
| 声明式订阅（下→上） | 任务声明 `subscribe(predicate)` | 纯函数匹配，可审计"为什么推给它" | 可解释 |
| 推送（上→下） | L1 判断 `push(task_id, fact)` | 必须有 **reason 字段**，否则无法回归 | 有依据 |

### 事件路由（4 级漏斗，`02 §4.5` + `06` 修正）
```
4000 事件/夜(doubao 同口径)  → 3~5 次编排调用/夜
  ├─[L0-a 结构过滤]   纯函数 类型/来源/速率/时间窗/去重    丢弃≈98.5%
  ├─[L0-b 廉价语义]   小模型/分类器，禁用主模型，有界速率    (06 新增)
  ├─[L1a 任务增强]    命中订阅→写 inbox，不唤醒
  └─[L1b 编排唤醒]    需改图→tick 队列，批量合并后一次思考
```
`06` **收回**了 `02`"L0/L1a 必须纯函数"的教条：纯函数判不了"这条微信要不要回应"。
正确约束 = **漏斗宽度约束**：每级输入量减一个数量级且单位成本减一个数量级。
L0-b 三条硬约束：禁用主模型（静态检查）/ 有界速率（令牌桶、洪峰降级白名单）/ 判定可解释
（每条产出 `{reason, confidence, model_version}`）。
精确匹配的事件（命中活跃任务 `waits`）**bypass L0-b** 直接进 L1a。

配套一等机制（都是 `06` 推演出的新件）：
- **不可丢白名单**（来电/短信/安全/财务/健康）：独立于订阅、**SA 无权修改**（平台/用户定义）——"被编排者不能编辑编排者对自己的认知"的镜像；
- **漏报审计**：影子通道抽样（0.5%）+ 回收审计 + `miss_rate` 指标，复核成本 ≤ 编排预算 5%；
- **触发规则库**（G-k）：规则命中是纯函数，模型只"填槽"不"决定建不建任务"；v1 只允许人写/审，SA 只能提议；
- **事件源侧聚合**（G-l）：SA 看到的是"设备状态变化"，不是传感器流；
- **事件关联窗口**（G-d/G-m）：correlation key + window，确定性状态机、有界缓存；
- **打扰预算**（一等资源，与 token 平级）：`daily_max` / 静默时段 / 超预降级静默摘要 / 计息。
  **常驻 agent 的死法不是太贵，是太烦**（成本差：24k token/夜 vs 6M token/夜，**250 倍**）。

## 1.6 节点：三类、边语义、九项契约（含演进修正）

**三类节点**（对 SA 是同一接口）：

| 类型 | 执行者 | 汇报 | 中断 |
|---|---|---|---|
| **Program** | 进程/后台作业 | 关键**里程碑**（声明式词汇表） | 杀进程（graceful → SIGKILL） |
| **AgentLoop** | 一次 LLM turn（可多步工具） | 一次结果 + 过程里程碑 | abort + 在途工具合成结果 |
| **SubGraph** | 子拓扑图 | 子图终态 + 关键里程碑 | 递归向下 + 级联 |

**两类边语义**（doubao §4.3 写得最明，补 group 的只言片语）：

| 边 | 语义 | 触发 | 适用 |
|---|---|---|---|
| 顺序依赖边 **→** | 上游达终态（成功/失败）后下游启动 | 单次 | 线性流水线 |
| 事件订阅边 **⇢** | 不等上游终态，监听到指定里程碑即触发下游 | **可多次**，每次生成临时执行节点 | 长生命周期状态机的中间事件响应（通话中的语音交互） |

**九项节点契约**（`02 §3.2`；缺的后果略，只列主用途）：

| 字段 | 用途 |
|---|---|
| `kind` | 运行时选执行器 |
| `deps` | control 前驱 + join 语义（all/any/quorum） |
| `inputs` | 引用上游输出槽（不读全局） |
| `milestones` | **声明的里程碑词汇表**（类型+载荷 schema）——观测归约的类型层强制，词汇表外一律不进 SA 上下文 |
| `waits` | 在等什么事件 + 超时（否则"静默"与"挂死"无法区分） |
| `reversibility` | `{cancelable, compensable, compensator}` |
| `budget` | 时间 / token / 步数 |
| `assertion` | 完成时交**可校验断言**，而非自报 OK |
| `resources` | **资源账本**（acquire→release，善后的前提） |

**演进修正（02→03→04）**：
- **G-b（04 改法）**：早先想加 `interrupts` 字段，C7 推演推翻了——正确形态是 **双平面**：
  **业务平面 + 并发控制平面**（正交区域）。控制事件边数从 N×M 降为 M（电话例：24 条边 → 4 条）。
  控制平面四条强制规则：永不被业务平面阻塞 / 每个处置必须映射到业务平面合法转移 /
  不产生对话内容（输出只有枚举）/ 允许本地小模型（计入节点 budget，不计编排预算）。
- **waits 三类推进**：deps 支持 `state` 型前驱（G-a，"取消完成"可作为等待数据源）；
  `waits` 限**封闭事件类型集合 + 结构化匹配**（G-f，否则活性判定不可判定，静态死锁检测作废）；
  订阅边 / 关联窗口补"情境关联"（G-d）。
- **其它契约补丁**：`retry_policy`（重拨入节点契约，SA 唤醒 7→3 次）、输出槽默认 **by-reference**
  （内容永不进 SA 上下文，如 `transcript_ref`）、`mutable_params`（被 V8 校验）、fallback ladder（任务级，G-i）。

**职责切分表（`04 §5`，最重要的产出）**——**越靠近"执行"的决策越往下沉，越靠近"目标"的决策越往上浮**：

| 决策 | 谁 |
|---|---|
| 拨通后要不要等 / 拒接后要不要重拨 | **节点**（FSM 定时器 / `retry_policy`，声明式） |
| 重拨用尽后怎么办（换微信/放弃/问人） | **SA**（跨能力目标级） |
| 通话中"算了"要不要挂 | **节点控制平面**（延迟敏感） |
| 挂断以后做什么 | **SA**（目标级改道） |
| 目标是否达成 | `assertion` 纯函数，**不能自报** |
| 超时/预算耗尽 | 节点 `budget` → 上报 `exhausted`（确定性触发） |

**里程碑词汇表 = SA 的"视网膜"**：当作**接口契约**评审（不是日志格式）。C7 数千事件，进 SA 的只有
6 类里程碑；明确不进（音频帧/逐句转写/振铃精确时刻/网络抖动）——进了就等于把音频灌进上下文。

## 1.7 低轮次循环：思考 → 调整图 → 验证

**单次处理的有界预算**（`02 §5.1`）：

| 维度 | 上限 |
|---|---|
| 每 tick 思考轮数 | 1（禁止 tick 内自我修正） |
| 每 tick patch 数 | K（建议 8~16） |
| 每 tick 模型调用 | **1** |
| 验证失败重试 | 1，再失败 → `stuck` 升级（`stuck` 必须有出口，否则静默变黑洞） |
| 事件处理总时长 | 硬超时 |

**Patch 封闭动词集**（`02 §5.2` + G-h）：`add_node / cancel_node / rewire / bind_input / set_budget
/ update_node`（G-h 新增：运行中参数修订，只允许改 `mutable` 参数、必须走 patch、节点声明能否中途接受）。
**不要允许任意图重写**——每个动词配一条验证规则，回放时不必解释"SA 当时在想什么"。

**验证清单 V1–V8**（验证 = 纯函数、可拒绝、可单测——SA 的"编译器"不是又一次模型调用）：

| # | 检查 | 失败含义 |
|---|---|---|
| V1 | 结构：无悬空边 / 无不可达 / join 可满足 | patch 本身有错 |
| V2 | 活性：每个 `waits` 有存活生产者或已设超时 | **结构性死锁**（静态可判定，图的第一卖点） |
| V3 | 收敛：无环、重试有界 | 图不会终止 |
| V4 | 预算：新节点不超任务预算 | 成本失控 |
| V5 | 副作用：不可补偿动作每条路径都过 `pivot` | 不可收拾的脏状态 |
| V6 | 断言：每个叶子节点都有 `assertion` | 完成不可验证 |
| V7 | 原子性：图空 = 无活跃 ∧ 无在途 patch ∧ 无待投递事件 | 误判完成 |
| V8 | `update_node` 目标参数在 mutable 白名单内且当前状态允许 | 非法参数修订 |

**提交语义**：验证通过才提交（revision+1、patch 落日志）；失败**整体回滚**；**no-op 是合法结果**
（低成本记录，不为"没改"付一次完整思考）；每个 patch 记 `trigger_event_id`（可回答"你当时因为什么改的"）。

## 1.8 终止、死锁、挂死

**图空 ≠ 完成**。终态三态：`Completed / Incomplete / Aborted`
（Completed = 无活跃 ∧ 无在途 ∧ 无待投递 ∧ 全部断言通过；Incomplete → 触发一次 SA 咨询，有限次；
Aborted = 外部取消/超时/预算耗尽）。**有节点被 abandon 时，终态必须附带善后结论**
（cleaned / quarantined / needs_human + 被放弃节点数）——**"完成"里若藏着未善后的孤儿，那个完成就是假的**。

**结构性死锁 = 显式图独有能力**（隐式 ReAct 只能靠超时发现）：存活节点等事件 T，全图无 T 生产者且无外部订阅
→ 必然永不推进，V2 提交前算出、直接拒绝（`waits` 缺失的节点直接判死，这解释了它为何必填）。

**挂死可观测性**（SA 静默 ⇒ 外部无法从"无输出"推断任何信息，必须主动暴露）：
每任务 `liveness` 心跳（运行时产出、零 token）+ `pending`/`waiting` 累计时长可查 + 任务看板。

## 1.9 中断与退出保证（四级升级 + 善后）

**四级升级（缺一级就有僵尸）**：`request`（协作退出）→ `grace`（停新工作入口，G 秒）→ `force`
（SIGKILL / abort LLM / 递归取消）→ **`abandon`**（标记 `Abandoned{at,reason,known_effects}`，
移出活跃图、记日志、触发善后交接）。

- 各类节点中断点必须在契约里声明；**FSM 每个状态必须定义 `Cancel` 出口**（V5 扩展：静态检查验证
  "所有状态都有取消路径"）；
- **中断也是一次图编辑**：取消节点留悬空边，必须走 patch + 验证（V1/V2），**不许绕过 patch 直接改图**；
- **僵尸可观测**：`cancelling_ms` 阈值告警 / `cancel_attempts` 显示走到第几级 / `abandoned` 计数进终态；
- **不可逆动作补偿而非取消**：`{cancelable:false, compensable:true, compensator}`；补偿本身作子节点入图
  （`Compensating` = 可持久化子状态机）；完全不可补偿的路径必须有 **pivot**（人机确认点）。

**善后：把"退不出"交给专门的退出清理任务**（D4，group 自认全稿最重要转向）：协作式取消不可能 100% 成功，
把"退出保证"从"要求节点守规矩"变成"系统承认节点会赖着不走，并为它准备收尸队"。

```
节点卡住 → 四级升级 → abandon
              ↓（运行时判定，纯规则，零模型）
        Reaper（确定性：abandon / cancelling_ms 超阈值 / 孤儿资源账本非空）
              ↓
        生成清理任务（Task，有自己的拓扑图；豁免准入配额、有独立预算上限）
              ↓
        对账 → 补偿 → 释放 → 隔离 → 出证据 → 上报（顺序不能乱）
              ↓
        回写原任务终态 + push 给原任务/SA
```

硬约束：**触发者必须是运行时 Reaper，不是 SA**（否则"SA 卡住 → 没人派善后"，而卡住恰是最需要善后时）；
清理任务对账 = **唯一被允许读世界的地方**（节点自报不可信）；资源账本 = 善后前提（无账本只能考古；
复用 miclaw 的"账本+票据+回收站"设计）；**深度上限 = 1**（清理任务再失败 → `NeedsHuman` + 告警，不自动重试）；
清理任务自身的资源/副作用同样入账；**不得改写已完成节点的产出**（只能隔离/标记），否则破坏可回溯性。

## 1.10 SA 的工具面：只有编排动词（I1 的可验收形态）

**写（只作用于图）**：`patch_graph(task_id, patches[], base_revision)`（唯一图编辑入口）/
`spawn_task(goal, contract)` / `kill_task(id, reason)` / `push_to_task(task_id, fact, reason)` /
`ask_human(question)`（唯一人类交互点）。
**读（只读观测）**：`query_task(id)` / `list_tasks(filter)` / `get_node_output(node_id, path?)`。

**验收口径（I1 落地）**：SA 的工具 schema 中不存在任何改变外部世界（文件/网络/设备/账号）的动词。

**委派代价与缓解**：简单动作也建节点 → **瞬时节点**（同一 patch 内 add→complete，不进活跃图、只落任务日志）；
节点可以粗（一个节点做十件事，不必拆到原子）、编排粒度不必过细。

## 1.11 档位：不是过滤器，是"图的形状"（C1 负收益的解法）

C1（"装个安装包"）账：ReAct 一次调用干完的事，SA 要 4~5 个节点。**若小任务上 SA 比 ReAct 贵，架构在 80%
日常场景无落地价值**。"加过滤器"是错的隐喻（判断"简单"需要理解意图 = 编排推理本身，过滤器会变成小一号的
SA）。**R2：档位不是三种执行器，是图的三种形状**，只有一套语义，共用同一份契约/账本/预算/断言/审计事件：

| 档 | 图的形状 | 何时出现 | 模型调用 |
|---|---|---|---|
| 多节点图 | N 节点 + 边 + 里程碑 | 需等待 / 状态机 / 跨能力 / 分支 | 1 编排 + 各节点 |
| 单节点融合图 | 1 节点，编排与执行同轮完成（**fusion**） | 全 stateless ∧ 无事件依赖 ∧ 单能力域 ∧ 步数≤5~8 ∧ 预算小 | **1** |
| 预编译图 | 命中已固化模板（参数槽化） | 同一形状见过 ≥3 次且每次断言通过 | **0** |

- **fusion 仍必须继承的三条**：pivot / 断言 / 账本——"简单"不能跳过确认（"把这个文件删了"结构简单但不可逆）；能力注册表声明 `stateless / stateful`（**查表决定能不能 fusion，模型不参与**，stateful 必走多节点图）；
- **分诊唯一安全方向 = fail-open**：宁多花钱、不干错事；凡不确定一律走多节点图（分诊的错误预算花在钱上，
  不能花在正确性上）；
- **撞墙升级 = 运行时结构信号（S1–S8），不让模型自报"我干不了"**：S1 pending 回执 / S2 跨能力域 /
  S3 步数达阈值 / S4 同工具同参二次调用 / S5 未声明错误码 / S6 连续不同原因失败 / S7 pivot 命中 /
  S8 用户改口——八个全部运行时可算；
- **无损交接 + 防刷预算**：升级传 `{goal, done_actions, irreversible_done, observation_digest, wall_signal,
  remaining_budget}`；`irreversible_done` 防止"刚打开过的应用又被打开一次"；**升级次数上限 1、预算继承递减、
  升级事件记账**；
- **固化 = 长期收益**（分诊是一次性成本）：产物 = 图模板 + 参数槽 + 断言 + fallback ladder + 依赖能力版本；
  能力版本变更 → 模板失效回退；预编译图内撞墙 → 直接升级多节点 + 标记"需修订"。依据 = HEXIS（skill→EFSM，
  +16.2pp / token 降 38~89%）与 Voyager 技能库同构。

## 1.12 终止成立的前提（完成必须可证）

D1–D4 拍板：**终态 = 图空 ∧ 断言通过**（含"无在途 patch ∧ 无待投递事件"）；改图强制 patch 记账 +
`base_revision` 乐观并发；接受 `abandon`；abandon 后交运行时 Reaper + 清理任务。连带效果：
**"完成"必须可证，证不出来也要有交代**（G-i 的 fallback ladder 是同一思路的另一半，`04 §7`）。

## 1.13 与宿主（DSH）的映射：真正要新建的只有一个

| 本设计 | DSH 现成件（_research/05 源码取证） | 缺口 |
|---|---|---|
| Program 节点执行 | `ctx.jobs`（句柄+cancel/done+归属隔离） | 只有终态事件，缺里程碑 |
| AgentLoop 节点 | agent turn / subagent（abort + 合成结果） | 中途里程碑上报 |
| 节点完成 → 唤醒 | `send(target×wakeup)`（busy→inject / idle→followup） | 生产者粒度是"job 终态" |
| 事件 → 对话准入 | unified send decision + `agent/inbox/spliced` | 观测归约落点已有 |
| 续体/状态持久化 | session 日志 + `schedule` 的 owner 冷恢复 | 需"每任务一条日志" |
| 取消 | `ctx.jobs` 的 `stopping` | 缺 abandon 与级联 |
| 善后 | teardown + 孤儿告警（"warns that work may be orphaned"） | **把"承认孤儿"升级为"派任务处理孤儿"** |
| SA 宿主 | 插件形态（agent-loop 是唯一含循环逻辑的包，不可 fork） | **Graph Runtime 需新建** |

**缺口六项**：G1 细粒度事件 / G2 持久化续体（jobs 明确 process-local）/ G3 机器状态 / G4 咨询 gate /
G5 观测归约 / G6 并发机器↔单对话（后三项是"做出来会不会崩"的治理缺口，业界几乎无人公开讲过）。

> **结论：真正要新建的只有一个——Graph Runtime（图状态 + patch 记账 + 验证 + tick 调度），其余全部复用。**
> 调研同证：异步与持久化的零件齐备，缺的是"显式迁移表 + 记账咨询"这一层。

## 1.15 设计约束十二条（C1–C12，`01 §9`，每条带可验收口径）

| # | 约束 | 验收口径（测试落点，供第二部分用） |
|---|---|---|
| C1 | 状态机支持层次 + 正交 + 历史状态 | 全局 `Cancel`/`AuthExpired`/`BudgetExceeded` 只定义一次即作用于所有子状态 |
| C2 | 一实例 = 一 actor，mailbox 串行 | 注入 1000 乱序事件后终态唯一；同实例处理函数永不并发 |
| C3 | 迁移函数纯函数 | 任意事件序列纯回放终态唯一；生产日志可直接转回归集 |
| C4 | 事件日志唯一真相 + 快照 | `kill -9` 后仅凭"快照+事件"恢复与对照组**逐字段相等** |
| C5 | 工具一律"立即 receipt，事件晚到" | 重复结果记 `DUPLICATE_DROPPED`；陈旧结果被状态守卫拒；工具 p99 不计入跃迁延迟 |
| C6 | 等待态卸载 | 10 分钟通话的模型调用数 ≤ 咨询 gate 数，与时长无关 |
| C7 | LLM 只在 gate，输出限有限动作集/FSM 片段 | 断言 `k ≤ K_max` 且与步骤数 N **解耦**；未过确定性校验的输出不能触发转移 |
| C8 | 咨询是记账单元 | gate 等待时 `kill -9`，重启后**同一 gate 只产生一次**模型调用 |
| C9 | LLM 输入是事件日志投影 | 超长历史下请求 token 有界；可证明 LLM 未见原始 history |
| C10 | 工具声明 `{idempotent, compensable, compensator}`；不可补偿前有 `pivot` | 静态检查枚举所有 `compensable=false` 且证明每条路径过某个 `pivot` |
| C11 | `Compensating` = 可持久化子状态机 | 补偿半路崩溃，重启后从断点继续、已完成步骤不重复 |
| C12 | 恢复与回归只依赖事件重放 | **crash-only**：任意随机步数 `kill -9` 均恢复一致；静态检查"不可达状态=0、无未声明死锁" |

**最小充分集**：**C2 / C3 / C4 / C6 / C7 / C8**，分别锁住：事件序确定性 / 可回放 / 可恢复 /
成本可控（等不烧钱）/ 模型不外溢 / 咨询不重复付费——这是"事件驱动 + 状态机驱动"成立的下限。

# 二、SA 的测试框架

## 2.1 为什么必须自建测试框架：没有论文背书，只能工程自证

`02 §11` 明确列出**没有论文、只能靠可执行验收立信**的块：
① 层次+并发状态图+快照+Saga 的 LLM 系统性工作；② actor mailbox 串行化解决事件乱序；
③ Saga/补偿与副作用回滚的正式工作；④ 观测归约（事件→上下文的事前准入）；⑤ L1 有界性（本项目最可能翻车点）；
⑥ **Reaper 收尸队式善后**——业界只到"记录孤儿并告警"，没人把孤儿升级为"专门任务去收拾"（工程空白，只能
**crash-only 测试 + 故障注入**来证明）。

同时 C1–C12（§1.15）每条都已写成**可验收口径**——测试框架就是把它们逐条变绿的执行机制。
核心判断（`07 R2/R5`）：**机制测试不经过自然语言**；**CI 里绝不放真模型、质量评估里绝不放假模型**，
两类断言**物理隔离**。

## 2.2 测试分层（三类断言，物理隔离）

`07` 的模型 mock 四形态 + R2/R5 落到分层上就是：

| 层 | 断言什么 | 手段 | 谁来跑 |
|---|---|---|---|
| **机制层** | "给定 patch，图是否安全"（V1–V8 / I0 / I1 / 终态三态） | **oracle-patch 直灌**（纯函数、无 LLM、无世界、无时钟） | CI（秒级、确定性） |
| **集成层** | 世界/能力/时钟装配后的端到端（C1/C7/C9/C10） | 假电话 + 世界模型 + 虚拟时钟（§三） | CI（分钟级） |
| **故障层** | 崩溃/说谎/洪峰/退不出（F1–F9） | 故障注入 + crash-only | CI + 定期 |
| **质量层** | 编排质量（不含机制正确性） | **真模型**（M3 录制回放 + 抽样；M4 真机影子） | 非阻断、单独跑 |

**红线（`07 R5`）**：CI 只跑 ①②③④ + F1–F9；真模型只在 M3/M4。**禁反向**：用真模型做回归（又贵又慢又不稳，
改个 prompt 全红）；用假模型评质量（自欺——假模型当然觉得编排合理）。

## 2.3 测试目标清单（测什么，来自各章验收）

# 三、SA 的 Mock 外围搭建

> 本部分 = `07 §§3–7` 的具体搭建规格：四个新建假件怎么造、模型 mock 怎么分级、故障怎么在外围注入、按什么顺序造。

## 3.1 目标与总原则

目标：**可重复、可加速、可注入故障、可度量成本**的测试基座，让 C1/C6/C7/C10/C11 能真跑起来。

- **别从"假设备"开始，从"验证器直灌"开始**（`07 §0`）：运行时契约"给定 patch，系统是否安全"
  不需要 LLM/世界/时钟，**纯函数可测**，且是其它所有测试的地基；
- **依赖面只有五处可替换**（§2.4 接线图）：事件源 / 模型 / 能力 / 时钟 / 世界；
  保留真实的部分：事件类型与 schema、适配器与流式协议、工具契约/权限/预算；
- **断言只查世界，不查返回值**（R4）：mock 必须能**说谎**（返回成功但世界没变），否则测不出结果真实性；
- **双时钟域**（R3）：虚拟时钟只虚"系统域"，模型与 IO 走真实，混一个就 flaky。

## 3.2 N1 —— 虚拟时钟 + 确定性调度器（双时钟域）

```
系统时钟（虚拟）  定时器 / 超时 / 关联窗口 / 重试退避 / 打断超时
模型时钟（真实）  HTTP、流式、mock server
```

**桥接规则（`07 §6.1`，不照做必然 flaky）**：

1. 虚拟时钟只在**系统静默**时推进（`quiescence-then-advance`）：先排空 microtask 与已就绪虚拟定时器，
   确认无进展，再跳到下一个定时器时刻；
2. IO 完成**不推进**虚拟时钟；等 IO 时有更早虚拟定时器到期 → 允许显式 `advance_to(timer)`；
3. 事件调度全序 = `(virtual_time, priority, seq)`，**seq 单调是确定性回放的前提**；
4. 被测代码**禁止直接使用** `Date.now()` / `setTimeout`（lint 强制），一律走 `Clock` 服务。

**验收**：同一 case 连跑 100 次，事件序与终态**逐字节一致**。

## 3.3 N2 —— 世界模型（World）：三种诚实度

```ts
interface World {
  fs: VirtualFs
  apps: Map<string, {version, state: 'absent'|'installing'|'installed'|'partial'}>
  calls: Map<CallId, {state, transcript, started_at}>
  messages: Array<{to, body, delivered_at}>
  battery: number; network: NetworkState; location: GeoContext
  sideEffects: SideEffect[]   // 只追加账本
}
```

| 模式 | 行为 | 用来测什么 |
|---|---|---|
| `honest` | 返回成功 ⇔ 世界真的变了 | 基线 |
| **`lying`** | **返回成功但世界没变** | 结果真实性：断言必须能抓住 |
| `partial` | 世界变了一半（安装到 60%） | 对账 / 善后 / 隔离 |

> **纪律（全部理由）**：所有断言只查 `World`，永不查工具返回值。
> 这把「高可信第③支柱（结果真实性）」变成**可执行的测试规则**而不是口号。

## 3.4 N3 —— 有状态能力 mock（假电话：真实 FSM 形态）

```yaml
capability: make_call
kind: stateful
fsm: phone            # Dialing→Ringing→Connected→Talking→Ended | Failed
script:
  - {at: 4s,   state: ringing}
  - {at: 22s,  action: reject}
  - {retry: 1, at: 6s, state: ringing}
  - {retry: 1, at: 12s, action: answer}
  - {at: 120s, action: barge_in, intent: redirect_to_messaging}
behaviors:
  ignore_sigterm: false        # 置 true 用于 C10 卡死用例
  hangup_delay_ms: 300
  transcript: canned
```

要点（为什么这一个 mock 就能覆盖 C7 全部路径，不需要真电话）：
- **跑在虚拟时钟上**——"通话 146 秒"瞬时完成；
- 支持 `barge_in`（用户中途改口直接打给控制平面，对应 §1.6 双平面）；
- 支持 `ignore_sigterm`（模拟"取消了却退不出"，F5/`07 §6.3`）；
- 支持 `partial` 世界（通话建立到一半链路断）。

## 3.5 N4 —— 场景 DSL + 断言运行器 + 度量采集

```yaml
case: C7-phone-reject-then-redirect
clock: virtual
world:
  contacts: [妈妈]
  capabilities: {make_call: {uses: phone-script-v1}}
llm: {mode: oracle-patch, script: c7.patches.json}
events:
  - {at: 0s,   user: 给妈妈打个电话问她晚上来不来吃饭}
  - {at: 120s, user_speech: 算了，发个微信就行}
inject:
  - {kind: event_storm, at: 300s, count: 4000}     # C6 复用同一 DSL
assert:
  - {model_calls: '<= 3'}
  - {world.calls[0].state: ended}
  - {world.messages: [{to: 妈妈, delivered: true}]}
  - {graph.final: Completed}
  - {milestones_seen: [call.rejected, call.answered, call.ended]}
  - {invariants: [V1..V8, I0, I1]}
metrics: [model_calls_by_layer, wakeups, patches, verify_rejects, cancellations]
```

**为什么必须数据化**：case 写成测试代码的那一刻，就失去了 **可 diff / 可回放 / 可批量生成 / 可做覆盖率统计**
四种能力。断言 DSL 用 YAML（可 diff、非程序员也能写），复杂断言允许 TS 逃生舱（Q-m5）。

## 3.6 模型 mock 四种形态（内部分级，`07 §5`）

| 形态 | 实现 | 用途 | 稳定性 |
|---|---|---|---|
| ① scripted（剧本） | `llm-mock-server --sequence` | 特定失败路径：半截流/重试/超时 | 高 |
| ② recorded（录制回放） | `llm-replay` + session JSONL | 回归：真实模型曾产生的行为 | 高 |
| ③ adversarial（对抗） | `llm-mock-server` 行为库 | 说谎/循环/幻觉工具/超预算 | 高 |
| ④ **oracle-patch（直灌）** | 新建、最简单 | **机制测试主力** | 最高 |

**oracle-patch 为什么是主力**：机制测试问"给定这个 patch，系统是否安全"——与"模型怎么想出这个 patch"
**完全无关**，所以直灌 `PatchScript`（按 `{at: 时间或已在事件}` 排的补丁序列），结果**完全确定**、可断言到
每次 patch/验证/唤醒、不依赖 prompt 稳定性、跑得极快（无 HTTP、无 token）。
**对抗形态必须覆盖的坏行为**（`07 §5.2`，机制层最值得测的清单）：

| 坏行为 | 期望系统反应 |
|---|---|
| 声称成功但没做 | 断言失败 → `Incomplete` |
| 重复调用同一工具同参数 | S4 撞墙 → 升级/阻断 |
| 幻觉出不存在的工具 | 验证器拒绝 patch |
| 产出非法 patch（悬空边/环） | V1/V3 拒绝 + 回滚 |
| 一次产上百个 patch | patch 上限 K → 拒绝 |
| 超出预算仍要新资源 | V4 拒绝 |
| 删掉不该删的节点 | digest `protected` 保护 + V7 |

## 3.7 故障怎么在外围注入（F1–F9 实现贴士）

| 故障 | 在外围哪一层做 |
|---|---|
| F1 `kill -9` | 世界模型**持久化**（测试内）+ 重启后校验世界（Q-m2） |
| F2/F3 重复/乱序 | 事件源生成器注入 + 断言终态唯一 |
| F4 洪峰 | `inject: event_storm`（DSL）→ L0-a 延迟与降级断言 |
| F5 忽略 SIGTERM | 假电话 `ignore_sigterm: true`（N3） |
| F6/F7 说谎/循环 | adversarial 模型（③）或 oracle-patch 直接灌坏 patch |
| F8 时间跳变 | 虚拟时钟天然免疫（两域隔离） |
| F9 日志写失败 | 注入存储故障 → fail-closed 断言 |

## 3.8 搭建顺序与依赖（M0→M4，见 §2.7 表）

顺序原则：**先便宜后贵、先纯函数后外部件**。M0（patch 直灌 + 内存图 + 验证器）**无需任何 mock 基建**，
2~3 天。M1 才把 N1–N4 四件一次性装配出来（N1→N2→N3→N4 依赖链）；M2 加故障与洪峰；M3 才让真模型进来校准质量。
