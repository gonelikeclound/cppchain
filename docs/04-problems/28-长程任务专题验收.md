## 二、批②（批间可改 + 批间复查）

### 2.1 revision-fork（回到历史批再续）——已稳定
- `task end`：写最新档案外，另存 `.wfr/tasks/<task>.history/batch<no>.json` 历史快照（只增不减）；
- `task begin`：`@config.task_revision=N` → 读 `batchN.json` 快照续跑（`cursor/上批摘要` 取快照，`batch_no=N+1` 不回退）。
- **稳定化根因**：跨批续跑的正确契约 = **档案文件本身**；离线测试改成每次 fire 用**全新 checkpointer + 独立线程**
  （屏蔽 M10 checkpointer 同线程跨 fire 回放奇偶性）→ revision 用例从 SKIP 转正。
- 测试 `WfLot.revision_forks_back_to_an_earlier_batch_snapshot`：批1→批2→revision=1（末态 cursor4、batch1 快照 cursor2 存档保留）。

### 2.2 批间 L3 复查（结果不飘移的抓手）
- `task begin` 恢复且 `@config.recheck_prev=on`、非首批、有上批摘要时：在**游标处插入 `audit_prev` 判据步**
  （`verify: model`，criteria = 上批摘要），随批内第一步执行、判定落 plan_log。
- 测试 `WfLot.recheck_prev_inserts_audit_step_with_model_judge`：批2 带 recheck_prev → plan 出现 audit_prev 且
  plan_log 有它的 model 判定。
- 语义：把「上批结论 vs 本批现实」显式摆给模型复核，跨批漂移有实例化检查点。
