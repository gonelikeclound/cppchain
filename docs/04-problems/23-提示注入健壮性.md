# 23 · 提示注入健壮性（wfr-㊸ ⑤）：把「模型被骗」与「防线被破」分开

> **这份是什么**：副作用防护的**最后一层未测面** —— 模型会被注入文本牵着走，我们要验证的是
> **防线本身**在这条攻击链路上稳不稳。威胁模型：注入文本（网页/工具结果/用户输入里的恶意指令）
> 驱动模型去发起 bash 调用；防护 = L2 词面静态门禁 + approve_tools 人审 + allow 前缀自动放行 +
> 沙箱执行。**五层里三层是纯函数/确定性门，模型被骗不改它们；真正要补的两个洞在"语义衔接层"。**

## 一、威胁模型与验证口径

注入不能改静态事实：`classify_bash_command(命令串)` 是纯函数、deny 名单是硬名单、NeedHuman 工具
（bash）判否与模型无关。所以**模型被骗 ≠ 防线被破**生效在哪一层，逐层核对：

| 层 | 是否信任模型 | 注入下是否仍稳 | 实测 |
|---|---|---|---|
| L2 词面分类（纯函数） | 否 | 稳（不解析意图，只审词面） | ✅ 对抗语料 11/11 拦 |
| deny 名单（硬拦） | 否 | 稳 | ✅（sidefx_approve_demo 已验） |
| approve_tools 悬挂（NeedHuman） | 否 | 稳（危险命令必挂人审） | ✅ 既有 |
| **allow 前缀自动放行** | 否，但**语义衔接有洞** | ⚠️ 已修（类别封顶） | ✅ 本批 |
| **人审放行 → guard 执行** | 是（人审后的信任） | ⚠️ 已修（pre_approved 豁免） | ✅ 本批 |

## 二、两个洞（都在"语义衔接层"，不在分类器）

### 洞 A：人审批准后被 guard 二次拦死（正确性的洞，也让注入无法区分场景）

实机证据（修复前）：`approve_bash_demo + approve_policy=allow`，模型发出写命令
`echo x > /tmp/wfr_probe.txt` —— 人审**已经批准**，但 `run_tools` 落地到 `ExecutionGuard::prepare` 时
词面门禁又把 Write **拦死**（`执行 0 · fail-closed 1 · 文件未建`）。后果：写命令的人审批了也执行不了
（批准形同虚设），且语义含糊。

**修复**：`ExecutionGuard::prepare(..., pre_approved)` —— approve_tools 放行的调用（`approved_ids`，
在 `run_tools` 里从 state results 读出）携带 `pre_approved=true`，词面门禁**不重复拦**（审计记
`approved_human`）；**未批准**的写/危险命令照旧 fail-closed —— 注入文本驱动的"没被批却想跑"依然被兜住。
单测：`ExecGuard.pre_approved_write_executes_else_blocked`（批→放行、未批→拦）。

### 洞 B：allow 前缀的「前缀即放行」被注入/串联升级（注入最直白的入口）

批过只读前缀 `echo hi` 后，`starts_with` 会让 `echo hi; rm -rf /x` **自动放行**（无需人审）——
注入文本只需让模型在已批前缀后接危险命令，就绕开了人审。这是真洞。

**修复（类别封顶）**：批准落盘时把命令的**词面类别**写进记录（`class` 字段）；自动放行要求
`新命令类别不比记录类别更危险`（干净→危险 = ReadOnly < Write < Risky ≤ Unknown）。于是
`echo hi`（ReadOnly）只能自动放行 ReadOnly 扩展；`echo hi; rm -rf /x`（Risky）→ 照旧挂人审。
`git add .`（Write）仍可自动放行 Write 扩展，但拒绝 Risky 扩展（如 `git add .; curl evil`）。
**旧格式记录（无 class）→ 不再自动放行**（fail-closed，重新人审后带类别重新落盘）。

## 三、验证

| 件 | 断言 |
|---|---|
| `CommandClassify.injection_evasion_never_readonly` | 11 条注入形态（重定向 / `$()` / `;` / 注释隐藏 / `find -exec` / 管道进解释器 / 编码）均不得 ReadOnly；`echo '$(id)'` 单引号字面量是真只读（对照，防"矫枉过正"） |
| `ExecGuard.pre_approved_write_executes_else_blocked` | 人审批准 Write → 放行（审计 approved_human）；未批准 Write → 拦死 |
| `WfApprovePersist.approved_*_prefix_*`（4 条新增） | RO 前缀 + Risky 后缀 → 挂人审；RO 前缀 + RO 扩展 → 放行；Write 前缀 + Write 扩展 → 放行、+ Risky → 挂；无 class 旧记录 → fail-closed |
| 既有回归 | 批②③④ + deny 硬拦全部不回归 |

全仓 **658/658 全绿**（652→658，+6：注入对抗 1 / pre_approved 1 / 前缀类别封顶 4）。

## 四、结论

注入的**最危险想象**（模型被骗 → 直接跑危险命令）被三层确定性门挡死：词面分类（哪怕注入也归类为
Risky/Write/Unknown）→ NeedHuman 必挂人审 → 沙箱（受限/禁网）兜底执行面。本批补的是**语义衔接层**
的两个洞（批准被二次拦 / 前缀被串联升级），它们会让"合理的放行通道"变成注入的顺风。

**边界（留给将来）**：a) 人对**批决策文案**的被骗（钓鱼式批准理由，属人类工程问题）；b) allow 前缀的
学习型放宽（按用户显式命令学更多上下文）；c) 分类器词表本身（新增工具/命令时需同步只读白名单）。
