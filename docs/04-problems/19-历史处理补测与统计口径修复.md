## 二、B · artifact 真机验证：落盘 12 条，模型诚实声明「读不了」

在 session-nb（22 条：web 检索 + 长报告，历史 ≈85.5k tok）副本上跑：

```bash
wfr hist_clip --session nb_b --set clip_scope=tool_results --set clip_mode=artifact \
              --set clip_tool_budget=200 "第一条检索的原文里，第一条文档的来源和标题是什么？…"
```

**读数**（fixed 二进制，`echo` 原样）：

```
✂️ 裁剪 transformed（artifact / tool_results）· 22 → 22 条 · 85588 → 72801 tok · 裁工具 12 裁回答 0 · 落盘 12
```

- **12 条**超预算工具结果**全部真实落盘**到 `.wfr/artifacts/artifact_<i>_<call_id>.txt`（各 ≈4–4.7KB，全文，
  非截断）。prompt token 省 ≈12.8k。
- 追问「如果是在落盘文件里，请用文件工具读取后再回答」时，模型的**行为**（原话节选）：

  > 读不了落盘文件——我这边只有 get_weather 和 web_search 两个工具，**没有文件读取工具**，所以无法
  > 打开 `artifact_1_call_00_…txt` 去核对。不过你问的那条信息在返回结果的**可见部分**里就完整给出了…

**结论（对「看模型会不会真去读那个文件」的回答，补 FS 工具之前）**：它**识别出了引用行意味着文件存在**，且
**知道自己没有读文件的工具**——于是诚实声明读不了、退回用可见头部作答，**没有编造**。
这条追问的信息恰好落在**可见头部**（inline 保留 `tool_budget` 前的开头）里，所以没触发
「答案只在落盘文件里」的硬场景。这个缺口后来在 **§六** 用 wfr-㊶ 的只读文件工具补上了——补完后的
决定性探针（答案只在文件末尾）模型会真去 file_read。

## 四、顺手修复：`after_tokens` 统计口径 bug（被真机暴露）

C 首跑（修复前）的 stats 是 `85554 → 85554`——裁了两条长回答 token 却纹丝不动。追到底：

- `estimate_msgs` 的策略是**有真实 `usage` 就用实测值**（端点元数据，`total_tokens` 可到 23k）；
- 真机会话里每条 AI 消息都带 `usage`（load_history 回灌），`clip_ai_text` 重写消息时**保留了原 usage**；
- 于是 `after_tokens = estimate_msgs(after)` 对重写消息仍按**旧调用的 usage** 计 → 反映不出裁剪。

离线测试从不暴露：测试造的消息没有 `usage`。修复（`src/agent/history.cpp`）：统计 `after` 时对**被重写**
的消息 `usage.reset()`，让 estimate 按**新内容**重估。配套回归测试
`HistoryRules.clip_ai_text_after_tokens_ignores_stale_usage_of_rewritten_messages`（构造带 usage 的消息，
断言 `after_tokens < before_tokens`）。

**验收**：全仓 **582/582 全绿**、零告警；`models` 层无改动，replay 语义不受影响。

## 六、wfr-㊶ · 把「用文件工具读取」兑现：FS 只读工具入 loop

B 在补 FS 工具之前暴露的缺口：引用行承诺了文件工具，但 wfr loop 只有天气/搜索。补上后跑通了
**端到端兑现**——模型真的去读落盘文件。

**改动（4 处 + 测试）**：

| 位置 | 内容 |
|---|---|
| `src/wfr/main.cpp` | 注册 `file_read` / `list_dir`（只读对），**沙箱根 = 工作区绝对路径**；`chat` 工具集 += 只读对（内置 5 个历史 workflow 全用它；`all`/`ts` 随注册自动包含） |
| `refine_history` 节点 | 落盘引用行 / `message.artifact` 的值改为**沙箱根相对**路径（`display_root` = 工作区绝对路径）——沙箱 file_read 只认根内相对路径，绝对路径会被拒，不改就兑现不了 |
| `write_tool_artifact` | 加 `display_root` 参数（空 = 旧行为），相对化失败（根外/异盘）回落完整路径 |
| 测试 | `HistoryRules.artifact_display_root_rewrites_the_line_to_a_root_relative_path` + 独立文件 `ArtifactFsRedeem.*`（跨半边：喂相对路径给 file_read 读回**完整原文**；根外路径仍被沙箱拒绝） |

**纪律**：只挂**只读**对，`file_write` 不挂（副作用无审批）；沙箱纪律不因「路径来自 artifact 落盘」放松——
根外/`..`/绝对路径依旧被 file_read 拒（有反向护栏测试）。

**真机验证（决定性探针）**：问一个**答案只存在于落盘文件末尾**的问题——第一条检索的 `"total"` 字段
（600 字节的 inline 头部之外、JSON 末尾）：

```
✂️ 裁剪 transformed（artifact / tool_results）· 22 → 22 条 · 85585 → 72764 tok · 裁工具 12 · 落盘 12
🔧 file_read({"path":".wfr/artifacts/artifact_1_call_00_e6bavcl5oe4SXR1r2q2V9372.txt"}) → …（默认 4000 字符，头部没有 total）
🔧 file_read({"max_chars":8000,"path":".wfr/artifacts/artifact_1_call_00_e6bavcl5oe4SXR1r2q2V9372.txt"}) → …全文
✅ "total = 10"
```

模型的行为链条：看懂引用行 → 用**根内相对路径**调 `file_read` → 发现默认 4000 字符截断、头部没有
答案 → **主动带 `max_chars:8000` 重读全文** → 从文件末尾正确答出 `total=10`。这正是 B 原本问的
「会不会真去读那个文件」——补 FS 工具后，**会，且知道怎么读全**。

**验收**：全仓 **585/585 全绿**（新增 3 条）。
