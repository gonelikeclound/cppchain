# 27 · 长程任务批①验收：任务档案 + 批还原 + lot 两批真机

> **这份是什么**：wfr-㊿ 长程任务批①（arch 20 第一期）落地与验收——任务 = `.wfr/tasks/<task>.json` 档案，
> `task` 节点 begin/end 做**跨批唯一接口**，`lot` 工作流一次触发 = 一个批。全仓 676/676。

## 一、交付

| 件 | 说明 |
|---|---|
| `task` 节点（begin/end） | begin：档案不存在→用 `@config.plan_steps` 建档并落盘（`created/batch_no=1`）；存在→读档还原 `state.plan`（cursor/步骤全清单/batch_no+1/上批摘要）并注入 `📅 第 N 批 @ 日期` 与上批摘要；end：把当前 cursor/batch_no/最后 AI 文本（批摘要）写回档案 |
| 今天日期助手 | `today_str()`（YYYY-MM-DD，本地） |
| `lot` 工作流 | `recall → task(begin) → PEV 环(loop max=批步数) → final → task(end) → _turn_end` |
| 测试 +1 | `WfLot.two_batches_restore_cursor_and_inject_batch_no`：批1 建档推进、批2 从档案还原（不给 plan_steps）→ cursor 4、batch 2、档案写回、批2 开场含「第 2 批 @ 日期 / 上批摘要」 |

## 二、真机证据（lot·两批）

- **批1**（plan_steps 6 步）→ begin 建档 → 推进部分步骤 → end 写回；
- **批2**（仅 `--set task`，无 plan_steps）→ begin **从档案还原** → 续跑 → 终态 `cursor=6 · batch=2`；
- 档案：`.wfr/tasks/lt1.json`（goal/steps/cursor/batch_no/last_summary）跨批正确写回；
- **跨批产物累积**（首轮 runs 实证）：`.out/week.txt` 两条 `[2026-10-13] 第1条…第2条…（含来源）`——批2 在批1 的产品上继续追加，模型在上下文里知道"今天是 10-13"。

## 三、诚实记录

- **模型怪癖（已知 DeepSeek-flash 抖动）**：个别轮 final 把工具调用序列（DSL 文本）当作正文输出，产物未真落盘
  （week.txt 空）——属模型行为，非机制问题；档案流在跑流程中仍正确写回（cursor/batch 读数不受影响）。
- CLI 用法：任务名一律 `--set task=<name>`（`--task` 不是 wfr 选项，会隐式为 "null"——机制仍好，只是命名脏）。
