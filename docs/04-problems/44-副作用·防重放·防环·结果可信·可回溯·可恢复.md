## 一、副作用防护（Side Effects）

> **一句话**：工具里有些动作是"一锤子买卖"（发信/扣款/删文件），要一层层设卡：先贴标签、再过词面检查、让人按确认、放进沙箱、最后记账，缺一层都不行。

### ① 这是个什么问题？

工具分两类：**只读**（查询/检索/计算）与**有副作用**（写文件/发邮件/付款/删数据/调外部 API）。副作用带来四类危害：

- **不可逆**：删除/发送/付款一旦执行无法撤销；
- **越权**：模型可能被提示注入诱导，或被一句话带偏；
- **难重放**：checkpoint 恢复会重跑节点，副作用不幂等就**重复执行**；
- **难调试**：出错后现场已被改变。

本项目的特殊难点是**双通道断层**：以上整套纵深只在 **Agent 循环通道**生效；**wfr 命令行（Workflow 图）通道的工具执行不经过任何中间件**——`file_write`（read_only=false）因此挂不进去（[20](20-副作用全景分析.md)、[18](../02-arch-design/18-副作用防护接入Workflow执行路径设计.md)）。

### ② 用户都会怎么问？

- "模型用工具发邮件/付款，安全吗？会不会乱发乱扣？"
- "为什么它能直接删我磁盘上的文件？"
- "网页里藏了段恶意文字，模型会不会被骗着执行 bash 命令？"
- "这个命令到底是真沙箱里跑的，还是装样子？"
- "让 AI 审批了一次，下次能不能别老打断我？"

### ③ 曾经出现过什么 badcase？

| badcase | 后果 |
|---|---|
| `delete_file` 演示"跑了 0 次"——deepseek 自己拒绝调高危工具，中间件根本没被走到，demo 却"跑通了" | 验证假象（[03](03-工具副作用.md) §5 教训） |
| wfr 命令行通道裸奔：`c_tool` 直跑 handler，file_write 无审批可挂 | 任意写操作绕过全部防线（[18](../02-arch-design/18-副作用防护接入Workflow执行路径设计.md)） |
| 沙箱"假装有"：带沙箱标志但 user ns 被禁，裸跑失败还装作成功 | 自以为隔离，实际裸跑（[22](22-沙箱选择器与会话级allow前缀验收.md)） |
| allow 前缀被串联升级：`echo hi` 之后 `echo hi; rm -rf /x` 自动放行 | 一条批准变成注入顺风车（[23](23-提示注入健壮性.md)） |
| 人审批准的命令却被 guard 二次拦死（`approve_policy=allow` 仍 `执行 0 · fail-closed 1`） | 合法放行通道被抽掉（[23](23-提示注入健壮性.md) 洞 A） |

### ④ 解决思路是什么？

**纵深防御，一层都不够**（[03](03-工具副作用.md) §2 的关键认识）：标记（`read_only`）→ 策略（按规则拒绝）→ 审批（HITL 确认）→ 幂等 → dry-run/probe → 审计 → 回滚。并明确一个分工：**"可撤销/可关闭"这类业务语义放在工具自己身上**（窗口期可撤、不可撤、任意状态可关），guard 只管"防重复执行"、不管撤销（[35](35-副作用mock场景库与可逆性梯度workflow验收.md)、[37](37-副作用工具实现方法参考.md)）。

### ⑤ 在 cppchain 中怎么实现？

按 L1–L7 分层落地（[06](../01-discuss/06-bash工具副作用治理设计.md)、[33](33-治理全链workflow落地与验收.md)）：

- **L1 声明契约**：`ToolSpec` 四声明 `read_only / effect_class / approval / probe`；`read_only=false` 必须显式 `effect_class`，缺省触发注册表**启动自检 fail-fast**（[33](33-治理全链workflow落地与验收.md)、[37](37-副作用工具实现方法参考.md)）。
- **L2 静态词面门禁**：命令/参数分 `ReadOnly < Write < Risky ≤ Unknown`，自动放行只允许"不比已批准记录更危险"，旧记录无 class → 不再放行（fail-closed）（[23](23-提示注入健壮性.md)）。
- **L3 审批门**：`approve_tools` 节点（deny 名单 / 策略表 / 按参数回调，`NeedHuman` 整节点 interrupt 悬挂 → resume；`MemoPolicy` 审批记忆化）；**会话级 allow 前缀**三不变量——会话作用域 / `starts_with` 前缀（明确"允许 P 即允许 `P;…`"斜面）/ **沙箱身份绑定**（provider 变了旧批准作废）（[21](21-副作用防护落地与验收记录.md)、[22](22-沙箱选择器与会话级allow前缀验收.md)）。任务级另有 `plan_review` 确认门（步骤边界 HITL，[25](25-复杂任务批4中断与回退验收.md)）。
- **L4 沙箱**：`SandboxManager` provider 选择器——按配置解析第一个**可用**执行器，全不可用 `available()==false` **fail-closed**；`bwrap_usable()` 探针（能建 namespace 才算可用）；受限子进程兜底（chdir + `setrlimit` FSIZE 256MB/NOFILE 1024），`describe()` 明示「非真沙箱」（[22](22-沙箱选择器与会话级allow前缀验收.md)）。
- **L5 限额**：超时 SIGKILL / 输出封顶（`spawn_runner` 共享内核）。
- **L6 审计 / L7 回滚**：见篇五（可回溯）与篇六（可恢复）。真正的执行点防重放由 `ExecutionGuard` 把关，见篇二——**审批管"要不要做"（决策），防重放管"做了没有"（状态）**，两者分层（[18](../02-arch-design/18-副作用防护接入Workflow执行路径设计.md)）。

### ⑥ 实际测试结果如何？

- **落点数字链**：585→600（ExecutionGuard+probe）→604（挂两执行点）→607（wfr 装配+日志事实源+审计）→615（approve_tools 节点）→633（契约+词面分类）→639（审批接 interrupt）→647（沙箱+限额）→652（会话级 allow 前缀+git 快照回滚）→658（提示注入健壮性）→720（governed 全链）→732（活动工具集）→763（mock 场景库，[35](35-副作用mock场景库与可逆性梯度workflow验收.md)）。
- **端到端审批 4 场景**（真实内置 `file_write`，断言只看磁盘：[03](03-工具副作用.md) §5.1）：①名单拒绝——`executions()==0`、文件未创建；②回调按路径放行——`notes/plan.md` 真写盘、`root.txt` 被拒；③崩溃重启防重放——`replays()==1`/`executions()==0`、v2 没写进去；④只读对照——不记账不拦。
- **真机三段**（[21](21-副作用防护落地与验收记录.md)）：A 写文件 `bytes_written=9` + 磁盘真实创建 + 审计 allow；B 同参数续聊 `执行1·重放1·审计1`、mtime 不动、模型自己 `list_dir` 核实；C 拒写、目录压根不存在、模型如实说明不硬来。
- **沙箱探测**：本机 bwrap 不可用自动隐退（不假装有）；allow 前缀 A/B/C 三场景。
- **提示注入对抗**：11 种注入形态均不得 ReadOnly；pre_approved 豁免 1 例；类别封顶 4 例。
- **mock 可逆性梯度**：31 case（订单幂等/微信可撤/短信不可撤/电话可关/治理审批/时序）+ 模拟钟 + 串行链；F2 实测悬挂期间 `executions()==0`、批准后 `==1`。
- **governed 真机三趟**：带探针判据 → `done/done` 完成档；不带判据 → `unverified` + 批级 review fail → `_fail` 失败档；abort → `terminal=cancelled` 取消档（[33](33-治理全链workflow落地与验收.md)）。

### ⑦ 解决效果如何？

从"命令行通道裸奔"变成"外部总纲（8 闸门 × 三层保障 × 12 缺口）L3+L4 的真实实现子集"（[32](32-副作用治理对照总纲评估与规划.md)）；拒绝≠执行、只读免审、审计留痕、沙箱不假装。最危险想象（模型被骗 → 直跑危险命令）被三层确定性门挡死。**遗留/边界**：日志保留策略与 SQLite 后端未做；人对批决策文案被骗属人类工程问题；分类器词表需与规则同步维护（[23](23-提示注入健壮性.md)）。

## 二、防重放（Anti-Replay / 幂等）

> **一句话**：把"我已经做过这件事、结果是这个、绝不再做第二遍"记下来——系统恢复了也只翻账本，不重干。

### ① 这是个什么问题？

系统的恢复语义是"回到该步边界**重跑**"（M6 checkpoint、M10 interrupt resume）。一旦重跑，**已执行过的副作用会再执行一次**——重复发邮件/扣款/删除。要回答的问题：**"某个操作到底做没做过？结果是什么？"**，据此决定"该举手重跑"还是"该回放旧结果"。

### ② 用户都会怎么问？

- "断电重启之后，会不会把扣款/邮件再做一遍？"
- "恢复现场会不会和原来的执行对不上？"
- "干到一半崩溃了，重启后这段'没结果的操作'怎么办？"

### ③ 曾经出现过什么 badcase？

- M6 恢复=重跑节点 → 副作用会被重做（"本层最初最大的隐患"，[03](03-工具副作用.md) §4.2）。
- 崩溃缺环：登记了意图但没有结果，重启后若不识别就会当作没执行重跑。
- **内容漂移 bug**：重放路径也走 `after_tool`，把带 `[重放]` 前缀的内容再写回日志 → 多次重放不断累加前缀（[03](03-工具副作用.md) §5.2）。
- **新 id 同参数**：模型重新规划后 `tool_call_id` 变了、参数一样，按 call_id 记不住（[18](../02-arch-design/18-副作用防护接入Workflow执行路径设计.md) D2）。
- workflow 图通道、快照恢复 = 重放剩余包：无防重放时同一执行点二次执行。

### ④ 解决思路是什么？

三件套：**执行前记账（intent）→ 三态判定 → 持久化日志 + probe 兜底**。三态：未见过 → 登记意图 → 正常执行；已 Completed → **回放记录结果，绝不重跑**；Intent（无结果，崩在中途）→ **拒绝重跑，回喂"结果未知，请人工确认"**；Failed → 默认拒跑（可配 `retry_on_failure`）。幂等键两种口径取舍：`ToolCallId`（语义最明确）vs `ToolNameAndArgs`（能抓"新 id 同参数"，可能误杀合法重复）。

### ⑤ 在 cppchain 中怎么实现？

**双层结构**：

- **agent 层 `SideEffectGuard` + `ToolExecutionJournal`**（[03](03-工具副作用.md) §4.2）：幂等键 = `tool_call_id`；三态判定（上表）；`FileJournal` 持久化——意图**执行前落盘**（否则崩溃后无法识别）、原子写（临时文件 + rename）、损坏 **fail-closed 抛异常**（可显式 `StartEmpty`）、`key_prefix` 键前缀租户隔离；只读工具不记账。
- **workflow 层 `ExecutionGuard`**（[18](../02-arch-design/18-副作用防护接入Workflow执行路径设计.md)、[21](21-副作用防护落地与验收记录.md)）：幂等键默认 **NameAndArgs**（compact JSON 指纹）；**会话日志为唯一事实源**（`replay_exec_log_reader` 跨进程重建 LogState）；`prepare`（串行段：词面门禁 / replay / probe）→ `run`（并行段真执行）；Intent 残留 → **probe 四格**（Complete→replay / Partial→blocked / Absent→安全执行 / Unknown→blocked，fail-closed）；`pre_approved` 人审豁免；`done_ids` 过滤（run_tools 先扫已有 ToolMessage 的同 id，跨 checkpoint 续跑不重复执行）；审计 `AuditRecord{ts,tool,key,decision,who,why}` 追加 `.wfr/audit/*.audit.jsonl`。

关键架构约束（[18](../02-arch-design/18-副作用防护接入Workflow执行路径设计.md)）：防重放必须**与 handler 处于同一段不被快照打断的边界**——放在前置节点会被快照恢复绕过，导致 handler 二次执行；所以它只能在执行点内部 + 日志事实源。

### ⑥ 实际测试结果如何？

- **`side_effect_guard` 三场景**（离线确定性）：①首次扣款 = 真实执行 1 次；②崩溃重启（从落盘日志恢复）= **重放 1 次、扣款仍是 1**；③结果未知（intent 无结果）= 阻塞 1 次、拒绝重跑（[03](03-工具副作用.md) §5.2）。
- **agent 层 16 项单测**：重放不重复执行 / intent 拒跑 / failed 拒跑与可重试 / 只读不记账 / 两种键模式 / round-trip / 跨进程重启重放 / 意图即时落盘 / 原子写无残留 / 损坏 fail-closed / 键前缀租户隔离。
- **workflow 层**（[21](21-副作用防护落地与验收记录.md)）：`ExecGuard*` 13 + `ExecGuardProbeFile*` 2 + `WfSideEffectGuard*` 7；同 fire_once 内被 deny 追加的 error ToolMessage guard 看不见（冻结快照）→ 修正为 **prepare 之前过滤**"最后 AI 之后已有同 id ToolMessage"，有对应回归测试；重放不二次记账（内容漂移修复）。
- **真机 B 场景**：同参数续聊 `执行 1 · 重放 1 · 审计 1`，mtime 停首轮、磁盘不二次写，模型主动核实（[21](21-副作用防护落地与验收记录.md)）。
- **恢复/并行防重放**：M10 断言 `interrupt 前副作用 before×2 / after×1`；`done_ids` 使跨 checkpoint 续跑同 call id 不重复执行（[13](13-M10图运行时补全落地与验收记录.md)、[41](41-B2证据版本单调性落地.md) 测试纪律）。

### ⑦ 解决效果如何？

"重放不动盘、拒绝不执行、只读不记账"的铁律在三态判定 + FileJournal/会话日志下对**真实工具**成立；崩溃重启后不重复扣款是硬断言而非嘴上承诺。遗留：保留策略（条目只增不减）与 SQLite 后端未做，FileJournal 接口可平替（[03](03-工具副作用.md) §6）。

## 三、防环调用（Degenerate Loop）

> **一句话**：模型反复调同一把工具打转时，认指纹连续 3 次就喊停；但换参数、换工具、只读查询都不算数，别误伤正常循环。

### ① 这是个什么问题？

此前防"重复执行同一调用"靠 replay/probe；但 **agent 反复调工具成环**（死循环打转）只有次数上界兜底——workflow `max_steps=100`、loop `on_max→_timeout`、agent `max_iterations=10`。**换参数/换工具绕圈**时只能"跑满轮次强停"，不经济也没有语义（[38](38-Agent工具环检测落地.md)）。

### ② 用户都会怎么问？

- "模型一直在反复调同一个函数，为什么到第 100 步才停？"
- "它是不是卡死在一个死循环里烧 token 了？"
- "怎么区分'真的在打转'和'正常地一页页遍历数据'？"

### ③ 曾经出现过什么 badcase？

换参绕圈（O1,O1,O2,O2 这种错开法）在无环检测时拦不住；拦截口径太宽会误伤分页遍历这类**参数递进的正当循环**；达阈值后若不保存指纹，下一轮又从头计数（实现 bug）。终态只有 `_turn_end`/`_fail` 两档时，超时/取消/做不到与"失败"语义混叠。

### ④ 解决思路是什么？

用户拍板三条语义：**连续 3 次才提示**（前 2 次正常执行，第 3 次起拦截）；**拦截不执行**（达阈值不进 to_exec、不进 guard）；**只读工具完全豁免**。判定规则要"够窄"：换参数、换工具即复位——只识别**连续重复**，不识别跨工具周期（明确边界）。退化循环的结局要有**独立终态**（超时/取消/做不到 ≠ 失败）。

### ⑤ 在 cppchain 中怎么实现？

- **`_tool_loop` 指纹表**：state 键（`merge_slots` reducer），表结构 `{_prev:[上一轮指纹], <fp>:连续次数}`；指纹复用 `ExecutionGuard::key_for(NameAndArgs)`（compact JSON）；"连续"= 上轮 `_prev` 含该指纹；拦截的调用也记入"上轮来过"，下轮继续累进（拦截后计数测试逼出的修正）。
- **loop 容器**：`loop_counts` 先判后加，超限走 `on_max`（缺省 `_turn_end`）（[15](15-loop节点落地与label-goto迁移记录.md)）。
- **终态四档 + A7 第 5 档**：`__timeout__`/`__cancelled__`（写 `plan.terminal` + plan_log 终态行 + `goto __end__`，**不抛异常**，超时/取消≠崩溃）；A7 `__impossible__`——judge 判"做不到"→ `advance=false` + `outcome=impossible`（第 5 值，**jgate 的 `outcome=="fail"` 不误送 `_fail`**），step `status=impossible` 独立档，cursor 推进集天然排除（[33](33-治理全链workflow落地与验收.md)、[40](40-A6独立验收subagent落地.md)、`git 629a6b3`）。
- **并行 Executor**：`max_rounds=4` 防病态循环（≤4 轮：模型→工具→再模型）（[31](31-交接式A→B交接件契约与并行Executor真机对照验收.md)）。

### ⑥ 实际测试结果如何？

`tool_loop_test.cpp` 6 例（763 → **769**）：`three_consecutive_same_call_blocks_on_third`（前 2 次 success、第 3 次 error，`guard.executions()==2` 证明第 3 次未执行）；`different_args_reset_chain`（O1,O1,O2,O2 全过）；`switching_tool_breaks_chain`；`read_only_tool_exempt`；`blocked_call_count_persists`（order{P}×4 第 3、4 次都拦）；`state_key_visible_after_execution`。A7：既有 verify/plan/governed 冒烟 20 例全过（`git 629a6b3`）。

### ⑦ 解决效果如何？

"够窄不误伤"——放过遍历分页，拦截空转；指纹表完全 state 派生（读→算→写），快照恢复可重算一致；拦截与执行分离（error 回喂让模型换策略）保持循环不中断。**边界**：A→B→A→B 跨工具周期环未覆盖（需周期检测）；并行 run_tools 多写者的 `_tool_loop` 更新会丢更新（记录边界）。

## 四、实现结果可信（Trustworthy）

> **一句话**：不听话看货——每一步设验收标准机器自动查；重要步骤再让一个"只有只读权限的独立质检员"亲手打开产物核实还不算，证据还带系统发的版本号，伪造不了。

### ① 这是个什么问题？

AI 自报"完成了"不可信，三处失真：**盲报**（没产物也说做完）、**闭门评判**（判官只读对话记录、不真看产物）、**过期/伪造**（拿旧文件或假时间冒充新鲜结果）。本质：**怎么证明"执行真的产生了合格产物"**，而不是"模型自述合格"。

### ② 用户都会怎么问？

- "它说做完了，我怎么知道真的做完了？"
- "生成的报告数字准不准？会不会是它自己编的？"
- "写着'已完成'，其实产物文件根本不存在，怎么防？"
- "它拿三天的旧文件糊弄我，怎么识破？"

### ③ 曾经出现过什么 badcase？

- **L1 盲标 done**：真实任务上 2/2 全 done 但**产物根本没落地**、模型自认"产物没写/需重跑步1"——C1/C4/C7（[24](24-复杂任务三级验证对照验收.md)）、B2 批 A1 合同提取/A3 邮件归档（[26](26-B2批对照验收.md)）。
- **K1 洞**：`judge_model_review` 只把 goal+criteria+最近消息喂给模型，"模型顺着执行记录自说自评，不真读产物文件"（[40](40-A6独立验收subagent落地.md)）。
- **mtime 可伪造**：verify 判据只有"文件存在/内容对"，没有新鲜度概念，工具可 `touch` 伪造"新鲜"（[41](41-B2证据版本单调性落地.md)）。
- **final 口头完成**：pev_l3 单角色真机，judge 已抓出"产物不存在"，final 仍口头自述穿衣建议（产物双缺）（[29](29-多Agent角色化mch验收.md)）。

### ④ 解决思路是什么？

核心一句：**"判据是数据不是嘴"**。每步设验收标准（优先只读断言 probe/schema/rule，可离线、注入安全）；难判的语义用模型裁判，但裁判必须**接地**（真读产物）且**输入隔离**（只喂判据不喂执行对话）；产物带**引擎分发的单调版本号**防伪；诚实三态 `done/fail/unverified`，判不了就标 `unverified` 而不是假装 done；全程 fail-closed（不可解析/缺判据/证据过时一律拒）。

### ⑤ 在 cppchain 中怎么实现？

- **PEV 环**（[19](../02-arch-design/19-复杂任务规划执行验证环设计.md)）：`plan` 节点产出结构化计划（每步 = `{id, goal, verify, deps}`）→ `plan_review` 确认门 → 逐步执行 → `verify` 判据 → fail 则 retry/降级/回退。**每步验证，不是终验**。
- **验证三级**：L1 无验证（盲跑基线）；L2 确定性判据（probe/schema/rule，不调 LLM，**性价比之王默认带**）；L3 `kind:model` 语义裁判（规则先过再背书，fail 带理由回喂）。
- **A6 独立只读验收 subagent**（[40](40-A6独立验收subagent落地.md)）：verify `kind=agent`——宿主只给只读 toolset（`file_read/list_dir`，写工具**不在 registry = "不存在而非被拒"**）；`judge_agent_review` 构造最小验收 agent（`max_iterations=8`，提示词 `kAuditorPrompt` 无注入面），只回一行 JSON `{verdict: done|fail|unverified, evidence}`；**transcript 完全隔离**；判不了 → unverified + 推进（K2 fail-open 免疫，靠 Reviewer 批级终审兑责）。
- **B2 证据版本单调**（[41](41-B2证据版本单调性落地.md)）：版本号由引擎 **`next_artifact_version()`**（全局原子 `++`）分配，模型/工具伪造不了；state 键 `_artifact_ver`（merge_slots）；节点层按 `call.args.path` 登记；verify 判据 `evidence.version ≥ want`，**过时 → 映射 Partial=fail-closed**、未登记 = 过时；task 档案快照跨进程保单调。
- **mch 角色化批级终审**（[29](29-多Agent角色化mch验收.md)）：`judge` 步内自查 + **Reviewer 独立批级终审**；`judge_batch_review` 输入隔离（只喂目标+步骤+步内判定），输出不可解析/缺字段 fail-closed。
- **安全计算 + 可机检查判定面**：`calculator.hpp` 递归下降求值（非 eval，`max_expr_len=200`）给出"必须精确"的计算兜底；`expr` 节点 + jgate（`$judge.result.outcome=="fail"`→`_fail`）。数值一致性主线（五引擎 + Agent Loop"提取→表达式→工具→回填"，Apple FY2023 真机）为 781 后增量，详见**[篇七](#七防幻觉与数字一致性anti-hallucination--numeric-consistency)**。

### ⑥ 实际测试结果如何？

- **三级对照 42+ 轮**（[24](24-复杂任务三级验证对照验收.md)，7 个真实外部任务 × 3 级 × 2 次）：C1 L1 盲 done / L2 首试 fail→重试 done / L3 裁判 fail×2（"步内没给建议"，final 里有也不算）；C4/C7 L1 2/2 done 但没产物、L2 双试 Absent fail、L3 fail×2；C5 L3 验"产物状态在"而非"动没动"（状态主义≠过程主义）。过程产物：`probe_file` 误当子串 → 新增 `probe_file_contains`。
- **B2 办公/注入**（[26](26-B2批对照验收.md)）：A2 好案例三级都真过；A1 难案例 L2 重试耗竭 fail、L3 fail；V1 误导注入 L3 揪出"未产出"；V3 判据从严不误杀；office 外部引擎补上后 A1 真写出 `FAIL`（判据正常工作）。
- **中断与回退**（[25](25-复杂任务批4中断与回退验收.md)）：`WfPlanReview.*` 4 例 + 真机 continue 连走两边界；rollback_to 单测序列；abort 会话仅 2 条（不再调模型）；674 全绿。
- **A6**（[40](40-A6独立验收subagent落地.md)）：6 例（done 推进 / fail 拦 / unverified 推进 / 只读工具 / 无 toolset 空工具 / 模型错 fail-closed）；769 → **775**。
- **B2**（[41](41-B2证据版本单调性落地.md)）：6 例（版本推进 / 过时 fail / 未登记 fail / 零版本回归 / 跨 fire 单调（独立 thread）/ run_tools 登记）；775 → **781**。
- **mch 真机对照**（[29](29-多Agent角色化mch验收.md)）：pev_l3 产物双缺 vs mch 双产物落盘（468B+468B）；681 全绿。

### ⑦ 解决效果如何？

L1 盲跑保证、L2 机械门便宜又硬（默认带）、L3 语义门最严但要有"步内义务明确"；A6 把"判官只读 transcript"补成"真拿只读工具读产物拿证据"（K1 解药）；B2 版本号模型伪造不了（A9 正解）；`unverified` 诚实推进 + Reviewer 兑责，堵住"没验证就放行"。**遗留**：数值一致性主线（783 口径）尚待建档（细节见[篇七](#七防幻觉与数字一致性anti-hallucination--numeric-consistency)）；A5/能力面"跑测试命令"未纳入。

## 五、可回溯（Traceability）

> **一句话**：全程有账：哪份日志是唯一事实源、计划账本只追加不改写还带角色、批准过什么都有审计档、交接任务有交接单——出了事一条条翻得清。

### ① 这是个什么问题？

系统出问题后要能回答"**谁、何时、凭什么、批准了什么、干了什么**"。之前只有执行日志（intent/result），**没有审批决策留痕**——"可置信 = 决策有据可查"（[20](20-副作用全景分析.md) 断层②）。另一面：有损操作（截断/压缩/拒绝）若不观测，问题会以"模型变笨了"的形式难以归因；并行执行不加约束，回溯时与串行对不上号。

### ② 用户都会怎么问？

- "这条命令是哪个模型、凭什么被批准的？"
- "它最后这个结论从哪来的，能一步步查吗？"
- "压缩之后它是不是把过程给弄丢了，所以变笨了？"
- "并行跑和串行跑，记录能不能对上？"

### ③ 曾经出现过什么 badcase？

- 审计缺失：只有 intent/result，无"何时批准了什么"（[03](03-工具副作用.md) §6）。
- 压缩把时间戳一起压掉 → 状态时效与压缩两条路径叠加时失效不可见；有损操作不留痕 → 模型变笨难归因（[05](05-五大问题现状盘点.md) 横向观察 3、[06](06-状态时效性.md)）。
- 重放路径二次记账 → 日志内容漂移（[03](03-工具副作用.md) §5.2）。
- 并行 Executor 不写 plan/plan_log 时无人收拢 → 重复收拢/重复 review 风险；`after_tokens` 统计口径 bug 让对比报告失真（[19](19-历史处理补测与统计口径修复.md)、[31](31-交接式A→B交接件契约与并行Executor真机对照验收.md)）。

### ④ 解决思路是什么？

**单一事实源 + 追加式账本 + 审计留痕 + 交接单 + 观测纪律**。日志是"常态事实源"（记录发生了什么），审计是"决策留痕"（谁批准了什么），计划账本是"进度投影"（追加不改写、每行带角色）；任何"丢信息"的操作都要可观测（截断标字节、压缩留摘要与计数、拒绝回喂原因）。并行执行必须维持"确定性契约"——并行与串行逐键相等，日志才能重放对齐。

### ⑤ 在 cppchain 中怎么实现？

- **会话日志 = 唯一事实源**：`.wfr/sessions/<name>.log.jsonl`（engine 事件/节点日志）；`project_stream_to_log` 防同一节点记两遍（stream 双源互斥）；`replay_exec_log_reader` 用它重建 ExecutionGuard 状态（跨进程防重放，见篇二）。
- **plan_log 账本**：追加式；每行带 `role`（judge 行 `executor`、review 行 `reviewer`）、`kind`（announce/judge/review/rollback/cancel/terminal）、终态行；`review` 相位不推进 cursor、不改步骤状态（批级终审只留判定）（[29](29-多Agent角色化mch验收.md)、[33](33-治理全链workflow落地与验收.md)）。
- **step status 全档**：done / failed / unverified / impossible / aborted / rolled_back / pending / in_progress / skipped。
- **审计档**：`AuditRecord{ts,tool,key,decision,who,why}` 追加写 `.wfr/audit/*.audit.jsonl`（原子改写）（[21](21-副作用防护落地与验收记录.md)）。
- **handoff 交接单**（[31](31-交接式A→B交接件契约与并行Executor真机对照验收.md)）：state `handoff` 键（merge_slots，各步各写 `<step>` 子键）+ best-effort 落盘 `.wfr/handoffs/<task>.json`；字段 `{from, to, goal, done:[{step,kind,verdict,why,role,artifacts}]}`——**谁写的、落盘在哪、产物路径**一目了然。收拢语义：**parallel 是 plan/plan_log 的唯一串行单写者**（engine 不加 append reducer，防止破坏整数组回写）；重复进入折叠 0 自灭；`par_done` marker 保 review 恰跑一次；死锁硬错不静默。
- **Executor 内部**：工具结果**先副本追加给下一轮上下文、再 move 进 updates**（同一对象 move 后已空，直接 push 会给出空 Tool 消息）——日志与状态不分支（`node_types.cpp:2768-2771`）。

### ⑥ 实际测试结果如何？

- **审计**：21 落盘断言（decision allow 等）；29 断言 plan_log 每行带 role + review 输入隔离。
- **handoff**：`handoff_contract_with_artifacts`（`.wfr/handoffs/session.json` 落盘 `{from,to,done:[3]}`）；`reviewer_input_isolation`；`executor_multi_round_loop_collects_artifacts`（[31](31-交接式A→B交接件契约与并行Executor真机对照验收.md)，702 全绿）。
- **并行确定性**（[30](30-Send并行波与冲突护栏验收.md)）：`parallel_equals_serial_keywise` / `wave_result_equals_serial`（并行 vs 串行逐键相等）；`event_order_follows_send_order`（seq 严格单调）；`checkpoint_after_wave_and_resume`；693 全绿。
- **测试全景**（[36](36-测试全景报告与方法论.md)）：763 测试 × 8 二进制（tool 173 / workflow 307 / agent 100 / model 56 / graph 55 / state 43 / message 19 / webui 9 + debug_derive_js）；workflow 层方法矩阵（guard 计数 + 收件箱交叉断言、模拟钟、串行链、中断悬挂→resume…）。**内核纪律五条**：①断言路径真被走到（副作用看计数器/磁盘/收件箱，不看模型自述）②真机喂数据、离线可重演 ③fail-closed 测负例 ④串行/并行语义显式 ⑤契约自检冗余。

### ⑦ 解决效果如何？

账本三态 = ExecutionGuard（"提交点"）；日志是常态事实源、审计是决策留痕、交接单是来源可溯；并行=执行方式而不是另一条时间线（逐键相等 + seq 单调），重放与运行期不分支。遗留：审批"谁批准"已留审计，但人类对批决策文案被骗的防线不在引擎覆盖范围（[23](23-提示注入健壮性.md)）。

## 六、可恢复（Recoverability）

> **一句话**：干到一半能停能退能换路——中断点设在步骤边界，退就退到第 K 步换法重来；跨好几天的任务有档案，下次接着跑不从头来、不跑偏。

### ① 这是个什么问题？

长任务最怕前功尽弃：**中断只能到动作级**（能按一个工具、不能"任务中间停下看进度改计划"）；**回退只能整批丢弃**（不能"回退到第 K 步换方法重跑后续"）；**跨批不持久**（多轮分批的任务无档案就续不上、会跑偏）。还要分清：恢复语义下 **interrupt 前已发生的副作用必然重跑（节点级幂等靠约定）**，工具级防重复由 guard 兜住（见篇二）。

### ② 用户都会怎么问？

- "跑了一半想停下来改个计划，怎么继续？"
- "第 5 步方向不对，能回到第 3 步换方法重来吗？"
- "这个任务要连跑好几天，明天接着跑会不会从头再来/跑偏？"
- "中断时它已执行的副作用，恢复后会再执行吗？"

### ③ 曾经出现过什么 badcase？

- M10 之前：interrupt 语义缺失、超时/取消不成档（[13](13-M10图运行时补全落地与验收记录.md)、[33](33-治理全链workflow落地与验收.md)）。
- 恢复 = 重跑节点 → 副作用重做（见篇二）；`current=*next` 整条替换会让 Send 第二个包丢失（[13](13-M10图运行时补全落地与验收记录.md)）。
- 长程批① 真机个别轮 final 把工具调用 DSL 当正文打印、产物未落盘（模型行为，档案流本身仍正确写回）（[27](27-长程任务批1验收.md)）。
- 同线程跨 fire 回放奇偶性 → revision-fork 测试一直 SKIP（[28](28-长程任务专题验收.md)）。

### ④ 解决思路是什么？

三件套：**中断 = 步骤边界上"到站停车"**（三选一：继续 / 回退第 K 步 / 放弃）；**回退 = 两级粒度**（定点 `rollback_to:K` + 整批丢弃边界，**不做命令反做**，宿主靠 git 快照、沙箱靠销毁）；**长任务 = 一份落盘档案**（每次触发一个批，批尾写回，续跑从档案还原）。恢复语义必须与"防重放"分工：引擎管可恢复，副作用防重跑归 guard。

### ⑤ 在 cppchain 中怎么实现？

- **M10 运行时**（[13](13-M10图运行时补全落地与验收记录.md)）：invoke 重写为**四态包队列**；包队列**追加而非替换**（super-step 语义）；`InterruptSignal` 不继承 `std::exception`（防节点泛捕获误吞）；重跑包**保留原包局部输入**（修 `key 'item' not found`）；resume 三态、单活跃中断；**时间旅行 fork** = 恢复原语复用 + 换线程（从历史 checkpoint 恢复，分叉点 = 新链 parent，找不到分叉点 `CheckpointNotFound` fail-closed）。
- **并行冲突护栏**（防并行重放/丢写，[30](30-Send并行波与冲突护栏验收.md)）：波内成员写同一默认 overwrite 键且无 reducer → `ConcurrentWriteConflict`（fail-closed）；累积类 reducer 按声明序折叠；波成员 interrupt → `InterruptUnavailable`（拒绝，不默默串行化）。
- **回退**（[25](25-复杂任务批4中断与回退验收.md)）：`rollback_to:K` → cursor=K、steps[≥K] 归 pending 重做，**历史 verdict 仍留 plan_log**（事实源不丢）+ 追加 `{kind:rollback}` 事件；abort → `plan.aborted=true`、未做步标 `aborted`、**不再调模型**；确认门 `plan_review`（缺省确认门，`--set plan_confirm=false` 直过）。
- **长程任务档案**（[20](../02-arch-design/20-长程任务任务档案与批还原设计.md)、[22](../02-arch-design/22-长程任务实现全景.md)）：`.wfr/tasks/<task>.json` = `task/goal/steps/cursor/batch_no/last_summary/strategy`；`task` 节点 begin（读档还原 `state.plan` + 注入"📅 第 N 批 @ 今天"，无档建档）/ end（写回 cursor、`batch_no+1`、`last_summary`）；护栏：begin 缺种子早返、end 遇空 plan 不覆盖档案；**revision-fork**（`.history/batch<N>.json` 历史快照，`--set task_revision=N` 续跑）；**recheck_prev** 批间 L3 复查（游标处插 `audit_prev` 判据步）；**wfr cron**（`--once` 一轮收）；每次 fire 用**全新 checkpointer + 独立线程**（跨批续跑正确契约 = 档案文件本身）。
- **历史压缩"不重算"**：摘要/精简以 op 落日志（fold/transform + base_size 守卫），第二次不重算；op 只改派生视图、原文仍在日志（缺任一条 replay 就分叉）。

## 七、防幻觉与数字一致性（Anti-Hallucination & Numeric Consistency）

> **一句话**：数值环节**整体搬出模型**——LLM 只做"提取命名 → 写表达式"，求值、核对、闭环断言全交引擎（铁律：**LLM 禁止自行计算**）；模型自述的每个关键数字都要能回到原始材料并对上号（接地 + 时效 + 凭据 + 一致性校验）。

### ① 这是个什么问题？

- **防幻觉**：模型"纸上谈兵"三态失真——**没核实就说**（产物/数据不存在也答"完成/存在"）、**拿过期数据冒充最新**、**凭据丢失后自补来源不明的话**。数字类幻觉最伤报告可信度：口算错、编数字、来源对不上。
- **数字一致性**：一份文档/报告里的数字要能**互相印证**——引用与原文一致（㊀引用错位）、推导前后自洽（㊁推导自洽）、量级分布合理（㊂Benford）、摘要忠实复述原文（㊃摘要复述）。数字自相矛盾 = 报告整体不可信。
- **共同根因**：只要"算数 / 复述 / 核对"落在 LLM 的自由发挥上，就没有一致性可言——解药是同一条：**把数值环节从模型手里拿回来**。

### ② 用户都会怎么问？

- "报告里的 44.1% 是哪来的？和原始材料对得上吗？"
- "它拿来就用的旧数据过期了吧？自己不知道怎么办？"
- "它口算的百分比 / 换算错了，谁能拦得住？"
- "摘要里复述的数字和原文不一致，怎么发现？"

### ③ 曾经出现过什么 badcase？

**防幻觉（仓库可查）**：

- 无时效守卫时模型**直接用 4 秒前的旧余额作答**；加守卫后才重新取数（[06](06-状态时效性.md) 真机 A/B）。
- 压缩把"余额 101（10:00 观测）"压成"余额 101"，**时间戳丢失 → 失效不可见**，比过期更危险（[06](06-状态时效性.md)）。
- 双向撒谎：模型"说做了但没真做 / 真做了但不报告"——靠收件箱 / 磁盘交叉断言抓（[36](36-测试全景报告与方法论.md)、[37](37-副作用工具实现方法参考.md)）。
- 历史压缩五档对照：facts **12/12 全保住**，差别只在**凭据**——concise 说不清出处，evidence 档保留数据源 URL（[16](16-历史消息处理专题.md)）。

**数字主线（记录口径，见 ⑤B 标注）**：

- 单位口径混用——首版源值按百万美元、摘要按亿美元，contains 全挂；
- `fetch_url` 遇 PDF 非法字节让 run_tools 的 JSON update 崩溃（`.exception.type_error.316`）；
- `digits_at(i,5)` 把 `HH:MM` 当整体数字校验（带冒号）→ 带时间字符串全误报；
- `starting_price - quote` 算成 `[-100,+∞)` 而非 `[0,+∞)`（单边约束平移下界错）。

### ④ 解决思路是什么？

- **防幻觉三条腿**：①**接地**——"问世界现状"（probe 只读断言），不凭模型嘴；②**隔离复核**——judge 输入隔离 + A6 独立真读产物（见[篇四](#四实现结果可信trustworthy)），防"顺着自己编的记录自评"；③**时效与凭据**——观测时间戳 + TTL"到点替模型判断"（[06](06-状态时效性.md)），压缩保留凭据 / 来源（[16](16-历史消息处理专题.md) keep_evidence）。
- **数字一致性主干方案**：**命名绑定 → 代数式 → 确定性求值 → 闭环校验**；铁律 = **LLM 禁止自行计算**——它只做"提取命名绑定 + 构造代数式 / 断言"，求值全交引擎；四 case 四维拆解：**㊀引用错位 ㊁推导自洽 ㊂Benford ㊃摘要复述**。

### ⑤ 在 cppchain 中怎么实现？

**A. 已落地且仓库可查（本篇实测锚点）**：

- **安全计算器 `calculator`**（`include/cppchain/tool/calculator.hpp`、`src/tool/calculator.cpp`）：递归下降解析 + **直接求值（非 eval）**，`max_expr_len=200` 防超长输入；覆盖四则 / 百分比 / 幂（右结合）/ 科学计数 / 常量 / 函数（sqrt/round/pow/min/max/sin…），语义对齐 Python（`-2^2=-4`）；`format_number` 整值显示整数、否则 `%.12g` 去尾零；语法 / 除零 / 溢出 → `ToolError` 回喂。wfr 把 `make_calculator_tool()` 注册为**内置宿主工具**（与 datetime/weather/web_search 并列，`src/wfr/main.cpp:518`）。
- **`expr` 节点 + jgate**（`src/workflow/node_types.cpp:787`、`src/workflow/expr.cpp`）：`Expr::eval` 表达式门，governed.json 用两个 expr 门做"可机检查判定面"——`jgate: $judge.result.outcome=="fail"`→`_fail`，`gate: $review.result.verdict=="fail"`→`_fail`（[33](33-治理全链workflow落地与验收.md)）。
- **Agent Loop 回填通道（通用件）**：model → run_tools → ToolMessage 回填，工具结果以机制保证进上下文（executor 内"先副本再 move"，见[篇五](#五可回溯traceability)）；主线把它定型为"提取 → 表达式 → 工具 → 回填"（见本节点 ⑤B）。
- **状态时效**（[06](06-状态时效性.md)）：`ToolSpec::ttl` + 观测时间戳 + StaleStateGuard 失效标注，"到点替模型判断"。
- **凭据保留**（[16](16-历史消息处理专题.md)）：`keep_evidence` 历史档保住数据源 URL，evidence 档才说得清出处。
- **评测纪律（防幻觉的度量）**：副作用 / 产物看计数器 / 磁盘 / 收件箱、**不看模型自述**（[36](36-测试全景报告与方法论.md) 纪律①）；calculator 的 `error_messages_are_actionable`（错误信息可操作）实测支撑"模型从报错中自修"。

**B. 数字一致性主线（记录口径 · 尚待建档）**：

> ⚠️ **溯源声明**：以下按项目主线记录（2026-10-17 立项：先调研 → 定 case → 逐刀落地）口径转录。**本仓库当前未含该主线对应的验收档案、代码与素材**——`docs/04-problems/data/` 现仅存 `lot/`，其记录的章节编号与现网 problems/ 不完全对应；完整准确性以日后正式建档为准（另见[篇四](#四实现结果可信trustworthy) ⑦）。

- **调研与四维拆解** → 四 case 选档：㊀引用错位 ㊁推导自洽 ㊂Benford ㊃摘要复述。
- **第一刀 Benford**：`benford_ok` verify 谓词（量级分布合理性作为可机检查的验证项）。
- **`number_sheet`（标量）**：命名绑定 + 代数式；**裸数字拒绝**（不绑定不可用）、未知数据名报错、比较链、**闭环断言**；12 SKU 真实价 `sum_all=71488`。
- **`time_sheet`（时间）**：四类值（标量 / 日期时间 / 时长 / 星期）；时长字面量 `15min/2h30m`（**禁裸数字**）、`now()/today()/weekday_on_or_after()`；固定偏移时区 + 本地日历；**可注入固定时钟**（离线确定性）；会议通知案（合成样例，明确非真实公开文件）。
- **`interval_sheet`（区间 / 约数）**：值 = 闭区间 `[lo,hi]`；约数半宽 = **末位有效数字的一半**（`约9100→[9050,9150]`、`约620万→[615万,625万]`）；`±` / `~` / 千·万·亿 / 千分位；**方向性约数**（`约620万以上→[615万,+∞)`）与**严格开区间**（超过 / 低于…）；**三态断言 pass/fail/unknown——不确定不算通过**（fail-closed）。
- **`affine_sheet`（区间依赖）**：`AffineForm = center + Σcoeff·ε`，加减同符号系数精确合并 → **`a-a=0`、`(a+b)-a-b=0`、`a/2*2-a=0`**；开性传播、与 interval 共用边界 API。
- **`claim_audit`（引用错位 / 摘要忠实）**：rows/claims → **角色核对**（数字对角色错 → fail）+ **数值 / 单位核对**（区间包含 / 重叠 / 不相交三态；单位换算 / 约数覆盖 / 缺引用 / 部分重叠全覆盖）。
- **非线性 / 百分比**：interval/affine 增 `abs/sqrt/square` 与**百分比绑定**（`44.1%→0.441`、`约44.1%→[0.4405,0.4415]`）。
- **Agent Loop 正式交付（`number_agent`）**：LLM 提取命名 bindings → 写代数式 / 断言 → 调 number/interval/affine/claim 工具 → **按工具结果回填**；**case = Apple FY2023（亿美元口径）**——A 恒等式 / B 摘要约数 / C 仿射相关 / D 引用忠实 / E 负例探针；终态 JSON `positive_checked_passed=true`、`probes_detected=true`；模型在工具报错后**自我修正**（裸数字 → 等式、精确 `44.1%` → `约44.1%` + contains）。
- **收尾三件**：`percent_format` 回填（ratio → `"44.13%"`，乘 100 / 四舍五入在工具内）；**联网取数**（`web_search` + `fetch_url` 进 numbers toolset，按原文单位进 bindings、**不换算**；真机搜 SEC 10-K、PDF 被拒后模型自改 SEC HTML R3 页，取 Net sales $383,285 (Millions)、`web_verified=true`）；`backfill_verify` 回填校验（run_tools 累积 `numeric_values`，最终 JSON 数值必须来自工具结果，`verify_backfill → gate_backfill` 不过即 `_fail`）。

### ⑥ 实际测试结果如何？

**A. 已落地件（仓库可查）**：calculator **11 例**（`tests/tool/calculator_test.cpp`：优先级 / 右结合 / 常量函数 / 科学计数 / 畸形表达式为错误 / **错误信息可操作** / 格式化 / handler 往返 / 失败回喂 / 缺参 arg error）；governed 用 `jgate`/`gate` 两个 expr 门判 `_fail`（720 基线段内，[33](33-治理全链workflow落地与验收.md)）；状态时效真机 A/B（无守卫旧余额答 vs 有守卫重取最新，[06](06-状态时效性.md)）；压缩五档 `keep_evidence` facts 12/12、evidence 档凭据完整度约 concise 的 3.9 倍（[16](16-历史消息处理专题.md)）。

**B. 主线记录（记忆口径 · 待建档）**：基线链 706（Benford）→721（number_sheet）→733（time_sheet，12 单测）→745/751/755（interval 三刀）→766/769（affine 两刀）→783（非线性 / 百分比 + 收口）→787（percent_format）→789（联网）→798（PDF + backfill_verify）；Apple FY2023 真机 `positive_checked_passed=true`/`probes_detected=true`，backfill 真机 `ok=true`（checked=5）。相关 demo 与素材目录（头部价格 / 会议通知 / 头皮价格 / 方向性价格 / 仿射依赖等）均随主线推进产生，未随本仓库归档（见 ⑤B 声明）。

### ⑦ 解决效果如何？

与整本专题同一哲学——**"把相信模型换成找得到一个提交点"**：数字一致性把"模型自由算"换成"命名绑定 → 引擎求值 → 闭环断言"（模型只提取和构造，算与核都"带不走节奏"）；防幻觉把"模型嘴上状态"换成 probe/A6 的接地断言、TTL 的时效判定、keep_evidence 的凭据保留。**治本点在"数值环节整体搬出模型"（LLM 禁止自行计算）**——与"再问一遍模型"是不同量级的方案。**遗留**（主线口径）：仿射 + ±∞、除法线性化、claim_audit 多行联合 / 源定位、PDF 扫描件 OCR、token 成本；**主线在 problems/ 的验收档案仍是待办**（见 ⑤B 声明）。
