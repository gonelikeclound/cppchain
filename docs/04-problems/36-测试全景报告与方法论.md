**方法**：脚本化通道驱动 agent 循环，断言历史压缩的 op 落盘 / 审批记忆复用 / token 计数。多为带真实状态文件的集成式。

## 三、测试方法的内核纪律

1. **断言路径真被走到**（problems/03 §5）：副作用看计数器/磁盘/收件箱，错误看法，不看模型自述。
2. **真机喂数据，离线可重演**：动态库真 dlopen；模拟钟让"时间流逝"变确定性输入。
3. **fail-closed 测负例**：probe Unknown/Partial、deny 越界、未知工具名——每类都有专门用例。
4. **串行/并行语义显式**：状态依赖的调用不进同批并行（run_tools 批内并发实测，problems/35 §三）。
5. **契约自检冗余**：effect_class_violations 启动 fail-fast + wfr fire 后动态库复检。

## 五、运行命令

```bash
source ~/opt/gcc16/env.sh
cmake --build build/dev -j && ctest --test-dir build/dev --output-on-failure -j   # 全量
ctest --test-dir build/dev -R workflow_tests --output-on-failure                   # 单层
./build/dev/tests/workflow_tests --gtest_filter='WfSidefxNotify.*'                 # 单套件
./run-tests-report.sh && ./run-webui.sh   # 生成静态测试报告 → webui「测试」tab 查看
```
> webui「测试」tab（web/ + run-tests-report.sh）：把 8 个 gtest 二进制 `--gtest_output=json`
> 汇总成 `web/tests_report.json`（见 tools/make_tests_report.py），前端 `fetch` 渲染成
> 分套件/用例表（✓/✗ + 耗时 + 失败点名）。方案 A = 离线快照，改代码后需重跑脚本才更新。
