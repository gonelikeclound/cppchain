# 16 · 历史消息处理专题（wfr-㊵）—— 摘要 / 精简 / 长内容裁剪

> 三个方向的探索：**① 历史摘要**（较早的一段折成一条 LLM 摘要）、**② 历史精简**
> （按规则过滤：去思考过程 / 去错误工具轮 / 去检索类调用）、**③ 长内容裁剪**（长工具结果、
> 长 AI 回答）。机制设计见 [02-arch-design/17](../02-arch-design/17-历史消息处理机制设计.md)。

## 一、起因

「上下文压缩」主线（[04](04-上下文压缩.md)）到 wfr-㉙ 只有**渲染期变换**：`load_history` 的
三档 mode + budget，**不落盘**。这够不着两件事：

1. **摘要**要调 LLM，结果必须**固化** —— 否则每次重跑都重算（花钱、慢、结果还可能不同）。
2. **精简/裁剪不可组合** —— 三档是固定策略，表达不了"既去思考过程、又去检索类调用、又保凭据"；
   长 AI 回答的裁剪、按**工具类别**过滤，也都没有。

其中两条是**这个专题最该守的性质**：

- `history_ops_test`：**op 只改派生视图** —— 被折掉的那句话必须仍然躺在日志文件里，同时
  `"op":"fold"` 自己也要在日志里（少任何一半都会让 replay 分叉）。
- `history_process_test`：**第二轮不重新摘要** —— 断言模型调用次数不增加。

## 四、真机对照

**方法**（沿用 [04-problems/14](14-wfr-chat2思考历史对比落地与验收记录.md)）：同一段历史
复制成多份 → 同一句追问 → 只切 `--set` 档位。原始历史 22 条 / 23619 token。

| 档位 | 条数 | tokens | 关键动作 | 回答 |
|---|---|---|---|---|
| 摘要 `sum_style=evidence` | 22 → 5 | 23619 → **7389（−69%）** | 折叠 18 保 4，摘要 949 tok | 「上海现在晴 20.6°C（体感 22.3°C），今天 16.1~25.3°C。」 |
| 摘要 `sum_style=concise` | 22 → 5 | 23619 → 6773（−71%） | 摘要 338 tok | 「上海当前 20.6°C（体感 22.3°C）。」 |
| 精简 `aggressive` + `drop_categories=retrieval` | 22 → 11 | 23619 → **12285（−48%）** | 丢 5 组（全按类别）+ 剥思考 5 | 答对 |
| 精简 `minimal`（只去思考过程） | 22 → 22 | 23619 → 23619 | 剥思考 10 | 答对 |
| 裁剪 `truncate`（工具预算 20） | 22 → 22 | 23619 → 22645(−4%) | 裁 6 条工具结果 | 「上海现在晴，20.6°C；明天毛毛雨 18.6~24.5°C」 |

**核心主张的真机确认（摘要落日志 → 不重算）**：

```
第 1 次（when=messages, max_msgs=15）：
  📝 摘要 folded（ok）· 22 → 5 条 · 23614 → 6773 tok · 折叠 18 保 4
第 2 次（同一会话续聊）：
  📝 摘要 skipped（below_threshold）· 6 → 6 条 · 折叠 0 · 摘要 0 tok
```

第二次**完全没有摘要调用** —— 摘要是从会话日志里 apply 上一轮的 fold op 复用的。

## 五、几条如实记录的观察

1. **`keep_last` 是下限**：设 3 实测保 4 条 —— `safe_boundary` 为避免"保留区以孤儿
   ToolMessage 开头"多留了一条。真实端点会因孤儿直接 400，这个"多留"是**要的**。
2. **`minimal`（只去思考过程）在真机上不省 token**：`剥思考 10` 条但体积没变 —— 因为历史里
   那些 ReasoningBlock 本来就是空的（思考模型逐轮决定要不要想）。**规则生效 ≠ 体积下降**，
   这条值得记住：去思考过程的价值取决于上游模型是否真的产出了思考。
3. **`concise` 比 `evidence` 省一半摘要 token，代价**（见下面第五点，是"凭据"而不是"事实"）。
4. **裁剪的收益与内容形态强相关**：这次的工具结果是天气 JSON（每条约 146 tok），裁到预算 20
   只省 4%；换成长网页正文（`web_search`）收益会大得多。

5. **真机质量对照（第四轮做的，比前三点更硬）：三档的差别在"凭据"，不在"事实"。**

   方法：造 12 城天气的历史（49 条 / 73603 tok），复制 4 份，同一句追问，只切 style
   （`when=always` 保证都折叠）——另加一份 `sum_when=off` 当全量基线。

   | 维度 | `full`（基线） | `concise` | `detailed` | `evidence` |
   |---|---|---|---|---|
   | **事实召回**（12 城气温） | 12/12 | **12/12** | **12/12** | **12/12** |
   | **凭据召回**（工具名 / 参数 / 来源） | ✓ | **✗** | ✓ | ✓（含数据源 URL） |
   | 摘要 token | — | 508 | 1175 | 824 |
   | 对话 prompt token | 73603 | 15705 | 16372 | 16021 |

   两条结论：

   - **"事实"这一维度上三档没有差别** —— 12 个城市的气温全对。原因不难理解：这些事实
     同质、量也不大，模型有"余量"把它们全写进摘要（哪怕 `concise` 只用了 508 token）。
     所以**别指望调 style 来救事实丢**；它救的是别的东西。
   - **"凭据"这一维度上差别明显**。问它"你确定这些是真实查出来的吗？用什么工具、什么参数？"
     （且不许重查）：
     - `concise`：**说不清**，思考里明确写 *"For the earlier cities, I don't have the exact
       parameter logs for those in this conversation… I should not claim details I don't have."*
       —— 于是它主动把答案降级成"不确定"。
     - `detailed`：工具名 + 参数（`city`；苏州那次另有 `country=CN`）+ 返回字段，并主动提示
       时间戳可能异常。
     - `evidence`：以上全部 **+ 数据源 URL**（Open-Meteo），直接说"是真实查的"。

   这正是 wfr-㉙ 探针那条"模型否认自己查过"的**温和版本**：不缺事实，缺的是**为自己答案
   背书的能力**。**要不要多花 30% 摘要 token 买这个能力，取决于后续会不会被追问"凭什么"**
   —— 例如要出报告、要交叉核对、要防幻觉的场景该用 `evidence`；闲聊式续聊 `concise` 够了。

## 六、怎么复现

```bash
# 1) 造一段带工具轮的多轮历史
wfr chat2 --session base "北京天气怎么样？顺便查一下上海未来三天天气"
for q in "那明天呢？" "广州呢？" "再查一下深圳" "杭州呢"; do wfr chat2 --session base "$q"; done

# 2) 同一份历史复制多份（唯一自变量 = 历史处理方式）
cd .wfr/sessions && for s in s_ev r_ag c_tr; do cp session-base.log.jsonl session-$s.log.jsonl; done

# 3) 同一句追问，只切档位
Q="你刚才说上海多少度？直接回答，别再查了"
wfr hist_sum   --session s_ev --set sum_when=always --set sum_style=evidence --set sum_keep_last=4 "$Q"
wfr hist_rules --session r_ag --set rule_preset=aggressive --set drop_categories=retrieval   "$Q"
wfr hist_clip  --session c_tr --set clip_scope=tool_results --set clip_tool_budget=20        "$Q"

# 4) 调试台并排；点 sum/refine 看 op 原文与统计
wfr debug hist_sum --all --open
```

## 七、遗留

1. **不做用 LLM 摘要超长单条内容**（第三方向只做截断与落盘引用）—— 若要做，复用 `summarize`
   的提示词与调用路径即可，但会多一次调用。
2. **`fold` 不严格幂等**（靠 `base_size` 守卫 + skip 机制兜住）；若要更强保证，可给 op 加
   "base 内容指纹"。
3. **规则集合的固定优先级不可配**（reasoning → error → category → orphan → clip_tools →
   clip_ai）。目前没必要可配，但真出现互相影响时再看。
4. **假工具（examples/support/fakes.hpp）没有类别** —— 离线测试按"纯数据 map"显式传，
   这正是 agent 层的契约；demo 若要用类别过滤需自行传 map。
