## 五、关键结论

1. **核心机制已落地**：账本三态（=总纲 C1 活例）、审批决策、verify 三级、task 层（=总纲 G1 已闭合）、审计。我们 wfr-㊸ 是"总纲 L3 保障 + L4 事实"的真实实现子集。
2. **五个实质缺口**（对应总纲判定，按我们可做性排）：
   - **G4 直调包装层自检**——低成本高收益：扫描工具注册表，副作用类缺幂等/补偿声明 → 启动 fail-fast（防静默遗漏）
   - **G5 ReAct+ANSWER 的 L4 真空**——诚实性问题：`UNVERIFIED` 显式状态 or 轻量核对器（数字/日期/ID）
   - **UNVERIFIED 独立状态**——现在"L1 无验证"=done+why，靠 Reviewer 问责；显式化可让"未验证"可度量（总纲度量三层）
   - **effectClass 显式声明**——把词面 CommandClass 升级为"效果域副作用分类"（只读/可幂等/不可逆），供 G4 自检 + 审批分级用
   - **G7 终态四档**——`_turn_end/_fail` 外补 超时/取消/未验证 等档（对齐"run→Terminal 四档"）
3. **明确不做的**：补偿票据/回收站（我们基调"不做命令反做"，git 快照兜底）；G3 路由召回/结构谓词（无 L0/L1 入口，超副作用范围）；Signal 传感器（无 LLM 信号埋点）。

## 六、规划（三档）

### P0 —— 值得立即做（低成本高收益，约束正确性）
1. **G4 工具注册表自检**：启动时扫描 registry，凡非只读工具缺幂等/补偿/风险声明 → fail-fast 报错（把"运行时才发现遗漏"提前到启动）。
2. **G5 UNVERIFIED 显式状态**：verify 无判据时落 `UNVERIFIED`（而非 done+why），reviewer/收尾可据此问责与度量。
3. **effectClass 声明**：ToolSpec 加 `effect_class`（read / idempotent / irreversible），审批与 G4 自检共用——把词面 CommandClass 升级为效果域分类。

### P1 —— 可选（对齐总纲度量/观测）
4. **终态四档**：`_turn_end/_fail` 外补 `_timeout`（loop max 触达）/ `_cancelled`（用户中断），对齐"run→Terminal 四档"。
5. **task 级假成功率抽检**：长程档案加人工复核标记，配合 export 统计"UNVERIFIED 占比"（总纲度量 task 层）。

### 押后（超范围 / 与基调冲突）
- 补偿票据/回收站；G3 路由召回/结构谓词三档路由；Signal 传感器；G6 中途升级；G8 探索额度。
