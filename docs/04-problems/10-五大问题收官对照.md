## 2. 跨问题横向观察（M9 收口的元结论）

1. **三个"信息密度"解法可以叠加出第五档**：压缩（把旧史变摘要）→ 截断（把长结果切短）→
   artifact（全文出 prompt）→ 子代理隔离（M8，内部不进主线）——从"少而旧"到"压根不在"。
   M9 让前两档有了 token 预算口径，M8 让第四档有了结构保证；横向表把它们放到同一把尺子上。
2. **"有损操作必须可观测"在新件里全部兑现**：截断标字节/token、落盘标路径/大小、记忆化标
   memo_hits、压缩标 summaries/saved——没有一处静默丢信息。
3. **评测口径仍分两层**：`tokens::estimate` 是启发式（触发与预算用），真 token 以端点 usage 为权威
   （m9_budget 的摘要成本用的就是真实 usage）——两者都在表里，互不顶替。
4. **M8 的主上下文干净与 M9 的成本量化是同一信仰的两面**：都是"让 prompt 信息密度更高/更便宜"；
   面向 M10 时，interrupt/Send 会在这把尺子上继续加刻度。
