### 2. tool_registry 节点 + 活动工具集（select 内置选择，本轮核心）
| 机制 | 内容 |
|---|---|
| **IR** | `ToolSource{from,type,load}` 结构**不变**，type 词表扩为 `so / select`：`{from:"builtin",type:"select",load:[内置名]}` |
| **活动工具集** | 节点运行期把两类源 load 并集发布进 `results.<id>.active_tools`（保序去重）；so 源同时加载进 `NodeContext.shared_tools`，select 源**仅激活不拷贝定义**（定义留宿主内置表） |
| **消费（think=model）** | `c_model` 三路：活动集（共享→内置兜底取 spec）> toolset 组件共享重建 > 编译期快照；活动集**优先于 toolset**。取不到定义 fail-closed throw |
| **消费（run=run_tools）** | `c_run_tools` 活动集 = **允许名单**：非活动名 tool_call → error ToolMessage 回喂；拒绝发生在 `guard.prepare` **之前**（与 done_ids 过滤同位置）；无活动集 → 全执行（零回归） |
| **校验** | `v_tool_registry`（VN23）：type 词表 / select 须 from=="builtin" / select 名须能于内置 registry 解析；`c_tool_registry` 同名纵深防御（兜手工 IR） |
| **助手** | `scan_active_tools(state)`：扫 results 全帧 `active_tools` 求并集，无帧带则 nullopt（旧路径分支） |

## 二、验收判据

1. **活动集闭环**：tool_registry 作入口节点 → think 的 schema 恰为活动集、run 只执行活动集。
2. **内置选择不拷定义**：select 源只是名单；消费端共享→内置兜底解析，mock 顶替语义保留。
3. **允许名单防注入**：非活动名绝不执行（含 guard 路径）。
4. **零回归**：无 tool_registry 节点 → scan 返回 nullopt → 全部走旧路径；既有 720 基线不变。
5. **治理契约**：动态工具携带 read_only/effect_class/approval，可过 `effect_class_violations` 自检。

## 三、边界（记录在案）

- **c_executor（并行 composite）内部自带 ToolNode，绕过活动集**；单一 `c_tool` 节点按名绑定编译期定义，不受活动集约束。两者为后续工作。
- **排序依赖**：tool_registry 须为 entry/先于消费节点（find 指针稳定性 + 活动集先发布）；误放 loop 体 → 每轮重 dlopen（幂等浪费）+ 同帧被 reducer 右胜覆盖。无图拓扑 VN 规则，靠文档与校验文案约束。
- **多 registry 帧**：消费方扫全帧并集，帧序按节点 id 字典序；单 registry 节点（推荐形）顺序=声明序。
- 基线变更：`src/CMakeLists.txt` 补 tool_plugin.cpp；`tests/CMakeLists.txt` 加 `CPPCHAIN_MOCK_TOOLS_DIR` 目录宏（tool_lib_dirs 按 `lib<from>.so` 找库）；`tests/wf/tool_registry_select_test.cpp` 登记 workflow_tests。
