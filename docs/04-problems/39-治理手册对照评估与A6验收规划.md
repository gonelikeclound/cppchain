## 一、总判断

手册 §14 的一句话（"把相信模型换成找得到一个提交点"）与 cppchain 已做的事**完全同向**：`ExecutionGuard` 三态、`plan_log` 账本、task 档案、环检测指纹表都是"提交点"。**不是方向分歧，是细节对齐**。

对照下来，真正缺四件事（按性价比排）：

| 优先级 | 动作 | 借的技术点 | 补的缺口 |
|---|---|---|---|
| **1（本次）** | **A6 agent 型验收者**：verify 加"独立带工具的验收 subagent"，真读文件/真跑检查，三态输出 | A6 A4 K1 K2 | 判官接地（K1：只读 transcript 的洞）|
| 2 | **B2 证据版本单调性**：版本号由宿主分配，替代 mtime | B2 B1 | 证据新鲜度（A9 正解）|
| 3 | **A7 impossible 档 + E6 前置条件不可重试**：给"判不了/做不到"独立出口 | A7 E6 | 三态裁决 |
| 4 | **D4 重复意图逃生阀**：环检测命中重复键 → 显式确认而非拒绝 | D4 | 环检测升级（可选）|

**明确不引入**：补偿票据/回收站（C9-C11，我们基调"不做命令反做"，git 快照兜底，problems/32 §五.3）；G3 路由召回/结构谓词（无 L0/L1 入口）。

## 三、A6 落地规划（本次实施）

### 目标
给 `verify` 节点加第 4 类判据 `kind=agent`：**派一个独立验收 subagent**（带读文件/跑命令工具），真读产物/真跑检查，返回三态（`done/fail/unverified`），回喂具体证据。治 K1（判官只读 transcript 的洞）——probe 已接地，但复杂产物（多文件/需执行）靠 subagent 才够。

### 设计要点（待确认）
1. **验收者来源**：复用现有 subagent/executor 机制（M8 ask_expert / wfr-㊾ Executor）？还是独立最小化 subagent（只给 Read/Grep/expr + 受限命令）？倾向**独立最小化**（验收者不该有写权限，与 A6 "inspection only" 对齐）。
2. **三态输出**：`done / fail / unverified`（判不了 → unverified，对齐 problems/33 的 UNVERIFIED 纪律，K2 fail-open 免疫）。
3. **判据声明**：verify `phase=judge` 的 `verify.kind` 扩为 `{probe, rule, model, agent}`；agent 判据含 `criteria`（验收条目）+ 产物路径。
4. **身份隔离**：验收 subagent 不应产生副作用（只读），其对话不污染主 messages（独立回话 / 只回 verdict + evidence）。
5. **上限**：验收者最多 N 轮（对齐 A6 "最多 50 轮" 的精神，落地按预算缩）。

### 测试与验证
- 新 case：probe 能判的简单产物用 agent 判据也过；需多文件/执行的真验收用例 done；判不了 → unverified；验收者无写权限（写工具被拒）。
- 全仓 ctest 回归。
