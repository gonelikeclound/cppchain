## 一、起因（承接 20）

`file_write` 挂不进 wfr loop 的根因是 **Workflow 图通道的工具执行不经过任何中间件**——
agent 循环通道那套纵深（`ToolApproval` + `SideEffectGuard` + `FileJournal`）在图通道一个都没有。
补的是一段**缺失的通道**，不是加一层新墙。

| 批 | 提交 | 交付 | 测试 |

**设计要点**（都是这次踩出来的，防再翻车的记录）：

1. **审批 = 节点，防重放 = 执行点**：审批是"要不要做"的决策 → 图上可见、可 route、可中断；
   防重放是"做了没有"的状态 → 必须与 handler 处在同一段不被快照打断的边界（graph 恢复按
   节点粒度重放剩余包，前置节点检查会被绕过 → handler 二次执行）。
2. **`replay_exec_log_reader` 是冻结快照**：跨进程续聊读旧会话 → 三态（未开始/已完成/Intent）。
   ⚠️ 同一 fire_once 内 approve 追加的 error ToolMessage guard **看不见** → 被拒绝的调用若进
   guard 会被当"未见过 → 执行"（deny 被静默反转）。化解：**run_tools 在 guard.prepare 之前过滤**
   掉"最后 AI 之后已有同 id ToolMessage"的调用。
3. **probe 判据必须区分完成度**：产物存在 ≠ 完整。写一半的残缺文件算 `Partial` → fail-closed，
   "宁可请人，不可重跑"。probe 必须只读（否则自己成副作用）、抛异常当 `Unknown`（绝不当作 Absent）。
4. **节点 = state 纯函数**：`ToolApproval` 复用判定但 `MemoPolicy::Off`（memo 是进程内可变态，
   会让图节点在重放时行为分歧）。

## 四、真机验收（三段闭环）

### 场景 A · 写文件（wfr-㊷ ③）

```
$ wfr chat --workdir tmp/wfr-sidefx --reset '调用 file_write 写 notes/test.md，内容 "sidefx v1"…'
🔧 file_write({content:…, path:…}) → {"bytes_written":9,"created":true,…}
副作用防护: 执行 1 · 重放 0 · fail-closed 0 · 审计 1 行
```
- 磁盘 `tmp/wfr-sidefx/notes/test.md` 真实创建，9 字节；
- 审计 `.wfr/audit/session-default.audit.jsonl` 落 `decision=allow`。

### 场景 B · 同参数续聊防重放（wfr-㊷ ③）

```
$ wfr chat --workdir tmp/wfr-sidefx '再写一遍同样内容到同样路径'
副作用防护: 执行 1 · 重放 1 · fail-closed 0 · 审计 1 行
```
- 第二次同参数 `file_write` → **重放**（审计 `replay`），文件 mtime 停在首轮、未二次写；
- 模型主动 `list_dir` 验证"只有一个 9 字节的文件"——它看到了重放旧结果、且察觉
  `created:true` 异常去核实，行为符合设计（旧结果供作答，真机不动盘）。

### 场景 C · approve 拒绝写（wfr-㊷ ④）

```
$ wfr sidefx_approve_demo --workdir tmp/wfr-approve --reset '用 file_write 把 hello 写入 notes/hello.txt'
💬 写入请求被拒绝了… 审批拒绝 —— 工具 file_write 被策略禁止（副作用审批）
```
- 磁盘 `notes/` 目录**根本不存在**（磁盘断言：没创建）；
- 会话日志里 `审批拒绝：工具 'file_write' 被策略禁止（副作用审批）` error ToolMessage；
- 模型如实转述被拒、且明确"不会绕过策略"（与 problems/03 §5 的真机观察一致——模型对
  被拒副作用会如实说明而非硬来）。

## 五、遗留开放项

1. **交互式审批**：`approve_tools` 的 deny 接 M10 `interrupt` / proactive `ask_user`
   （暂停等人批，再 resume）——现在只做策略式。
2. **持久化审批记忆**：approve 的 memo 关闭（节点纯函数）；跨会话"这工具会议室已批过"不落盘。
3. **幂等键分类**：`ToolSpec` 标 `idempotent` → 自动选 `ToolCallId` vs `NameAndArgs`
   （problems/03 §6.2 的开放项，与长程任务「结果不飘移」相关）。
4. **`FileJournal` 存废**：wfr 已换成会话日志为事实源；agent 层 `SideEffectGuard`/`FileJournal`
   是否一并收编。
5. **SQLite / Store 后端、日志保留策略**（长程任务底座）。
