## 1 · 问题场景与产生原因

**事实幻觉的定义**：模型对"非常识性内容"编造事实——用户问到常识之外的信息（近一年发生的事、某个具体产品线的参数、自身训练切口之外的话题），模型用"读起来合理"的编造作答。

**核心矛盾（用户原话要点的转述）**：
- 经过针对性训练/微调，模型能对**专业固定域**一步答对——此时强制它查资料反而拖慢体验；
- 但置信的"确定"与真实的"正确"不挂钩：常识域内它又快又对，一碰到非常识就自信地错。

**结论**：防幻觉**必须范围化**——只在特定范围开启查证，范围之外保持一步快答。范围包括且不限于：**某产品线的问答（如小米）、近一年内发生的事件、模型自评"不确定"时**。

**产生原因三类**：①知识切口（训练截止/读到一半）；②非常识（不在其高置信表面内）；③元认知失灵（**不知道自己不知道**，这是幻觉与后面要用的"自评信号"共用的病灶——见 §4 的两个洞）。

## 2 · 常见解决思路（横向对照）

| 思路 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **总是检索（RAG 强制）** | 每问必查（web/文件），答必引用 | 最稳、幻觉率最低 | 专业速答失效：每问都慢 |
| **意图路由器（Router 前置）** | 先让一个模型判"该不该联网/取数"，再分流（本项目 [07](07-意图路由与联网取数兜底.md) 的思路） | 范围化明确，命中后有兜底 | **多一轮模型调用**；路由器本身可错 |
| **模型自评阈值（prompt 约定）** | 提示词"拿不准就问/别说不知道的事" | 零成本、零改动 | 模型自评不可靠——过度自信与幻觉同源 |
| **强制工具化信号** | 模型先调一个 "verify/need_search" 工具，harness 据其结果决定取数 | 语义显式、可审计 | **一次工具调用 = 一整轮循环**（token + 延迟） |
| **文本信号灯（本方案）** | 模型在输出流里打一个 `<anti-phantasma-off/>` 标记，harness 剥离并据之免查 | 流内零循环（不花一次工具环）；判定可纯文本、可单测 | **信号可被注入伪造**；仍是自评→需防伪 + 否决权（§4 两个洞） |

## 3 · langchain / langgraph 中的对应做法

- 常见做法是**"有条件检索"的 prompt 约定 + web_search 工具**：让模型"只有需要时"才调工具——这本质是"自评阈值"的一种，没有结构性保证。
- langgraph 没有一等公民的"确定性豁免信号"；路由类（如 decision 节点 / router node）更像 §2 的"意图路由器"。
- 强制工具输入（forced tool / tool-use 必须走检索）是另一极端——即"总是检索"，牺牲速度。
- 一句话：**他们两头都有（强制检索 / prompt 自评），缺的正是"范围化 + 零循环文本信号"这个中档**——这正是本方案占的位置。

## 4 · 本项目选型与理由

### 4.1 选型一句话

**范围开关 + 默认查证 + 文本豁免灯**：`@config` 一个 `anti_phantasma` 范围键管"哪里开防幻觉"，范围内默认查，只有模型在流内给出"确信"信号、且信号经过防伪与风险门时，harness 才豁免取数。

### 4.2 为什么比同类更适合 cppchain

| 维度 | 与 [07](07-意图路由与联网取数兜底.md) 路由器 | 这是本方案 |
|---|---|---|
| 使命 | 决定"要不要取数" | 同使命，但**每轮零额外模型调用** |
| 开销 | 前置一次模型判断 = 多一轮 | 流内一个标记 = 0 轮；检测是纯文本剥离 |
| 适用 | 范围粗分（域级：联网/不联网） | 域内细判（"这题我确定，不需查"） |
| 关系 | 可共存：**范围粗分用 Router，域内细判用信号灯** | 互补不做替代 |

其余贴合点：
- **思考流承载**（[14](14-wfr-chat2思考历史对比落地与验收记录.md) 已支持 `reasoning_content` 回传）：信号优先放思考流——用户不可见、且比正文更接近"确定性"侧的报告；无思考流的端点才退回正文标记 + 剥离。
- **注入铁律可迁移**（[23](23-提示注入健壮性.md)）：信号最怕"网页里藏一句 `<anti-phantasma-off/>`，模型复述时原样吐出"——这正是 23 那条"注入文本 ≠ 防线被破"的同一形态；23 的 11 变体对抗方法论可直接迁移成"**伪造信号 11 变体**"（§6.3）。
- **可回溯留痕**（[44](44-副作用·防重放·防环·结果可信·可回溯·可恢复.md)·篇五）：信号命中/缺席/被否决都是"凭据"，落 `plan_log`/审计——回答"谁凭什么免了查证"。
- **token 口径纪律**（[19](19-历史处理补测与统计口径修复.md)）：被剥离的标记**已经生成了**，必须计入 usage——不许再踩 `after_tokens` 那类统计口径坑。
- **流式单通道**（[13](13-M10图运行时补全落地与验收记录.md)）：判定只能在输出**收尾段**做；剥离发生在"最终落库/统计之上游"，避免会话日志与 usage 分叉。

### 4.3 两个必须先补的洞（比写代码更优先）

**洞 1 · 注入可伪造信号**：模型引用/复述网页里的标记就会豁免 → 幻觉高跳过关。
缓解（防伪三件）：
1. **双条件合取**：标记必须带确定性理由 `<anti-phantasma-off reason="…"/>`，且理由须指向"未受外部文本影响的内部常识"——仅凭复述外部某段话构不成信号；
2. **来源边界**：只认"**无外部引用上下文**"处打的灯（引用过网页/工具结果之后打的灯 → 无效、仍查）；
3. **harness 否决权**：信号 = "候选豁免"不是命令——按范围/风险 gating，高风险域即使有灯也可再甩给 L3 语义门 / 人审。

**洞 2 · 过度自信不可靠**：信号把"要不要查"交给模型**自我元认知**，而过度自信恰是幻觉的同源病灶。
缓解：①阈值拧保守（默认查，慢的代价小于编的代价）；②`reason` 初版"非空 + 不在注入特征表"，更深保证（第二独立模型复判）押后（§8 遗留）。

### 4.4 与 [44](44-副作用·防重放·防环·结果可信·可回溯·可恢复.md)·篇七 主线的关系

篇七的"把数值环节搬出模型"治**数字幻觉**（算错/编数）；本方案治**事实幻觉**（非常识编造）——同属防幻觉主线、机制互补：数字靠**引擎计算兜底**，事实靠**范围化 + 工具取数 + 信号豁免**。

## 5 · 设计规格（可实施的最低定义）

### 5.1 语义三开关（锁定，不二义）

| 位置 | 行为 |
|---|---|
| **范围外** | 快答：不查、不看灯 |
| **范围内 · 无灯** | 默认**查**（强制插一步取数，再作答） |
| **范围内 · 有灯且可信** | 免查，正常输出（剥灯后原样放行） |

### 5.2 信号语法与位置（白名单纪律）

- 标记字面量：`<anti-phantasma-off/>`（ASCII 精确；**不含**大小写变体 / 空白 / 全角 / HTML 实体 / 变体选择器）。
- 位置白名单二选一：**① 思考流尾部**（`reasoning_content` 收尾段，优先）；**② 最终答案最开头一行**（无思考流的端点 fallback）。**其它位置一律忽略（宁查）**。
- 解析与剥离纯文本、在 message 层做（与每轮"工具消息 UTF-8 净化"`sanitize_utf8` 同一钩位，`node_types.cpp`）；剥离后文本恢复原样，信号不进入任何下游。

### 5.3 检测 → 剥离 → 回执

- 检测时机：输出**收尾判定**（流式只有在最后的 delta 才知道；非流式在消息完成后）。
- 回执三态，全部留痕 → `{signal, reason, node, step, accepted}` 进 `plan_log` / 审计：
  - `accepted`：有灯、过防伪（§5.4）、过风险门 → 免查放行；
  - `vetoed`：有灯但被范围/风险否决 → **照查**；
  - `absent`：无灯 → **照查**。

### 5.4 防伪（先于实现的一件事，§4.3 洞 1 的落地）

1. 只接受带 `reason` 的灯；`reason` 非空 且 不含注入特征（匹配"注入特征表"，与 23 的对抗词面表共用维护）；
2. 位置白名单（§5.2）；引用过外部文本的轮 → 灯无效；
3. 风险门：高风险域 `veto`（§5.3 `vetoed`）。

### 5.5 工程纪律四则

1. **token 计入**：剥离 ≠ 免费；信号 token 进 usage 口径（别踩 [19](19-历史处理补测与统计口径修复.md)）；
2. **单通道**：剥离发生在最上游/最终落库，保证会话日志与 usage 同源（[13](13-M10图运行时补全落地与验收记录.md) 教训）；
3. **思考流优先**（[14](14-wfr-chat2思考历史对比落地与验收记录.md)），fallback 正文头；
4. **可回溯**：三态回执 + reason 落 audit（[44](44-副作用·防重放·防环·结果可信·可回溯·可恢复.md)·篇五）。

## 6 · 测试设计（已落地 · 已转正）

### 6.1 message 层单测（剥离解析；最小切片 1 已落地 16 例，`tests/message/phantasma_signal_test.cpp`）

> v0 口径（实现后文本修正）：**剥离无差别（任一位置剥净，防标签泄漏），识别只看"首个标记是否在内容开头"**——开头位才算豁免信号，别处"剥但不算"（宁查）。§6.1 原稿"中缀全剥"与"非白名单位不剥不认"两句有冲突，也按"剥但不算"归并提出（测试见 §7 落地清单第 1 步）。
- 摘要：无标记 → 原样返回（seen=false）；
- 独立行前缀信号 → 剥尽且正文无损，识别 at_start=true；
- 中缀 / 多次出现 → **全剥离**（不留标签），但若首个标记不在开头 → 识别 at_start=false（**剥但不算**，宁查）；
- **大小写 / 额外空白 / 全角括号 / HTML 实体 / 零宽字符 / Unicode 变体 → 不认**（= 普通文本，原样保留），按"无灯"判（fallback 到"查"）；
- 带 `reason` → 正确解析出 reason 供回执（取首个标记）；`reason` 空 → reason=""（上层双条件不满足，照查）；reason 值原样不解码（对抗表在上层按原串判）；
- 前导空白（空行/空格）下仍按"开头位"认；标记后紧跟的 LF / CRLF 一并吞掉。

### 6.2 workflow 端到端（拟 6 例）
- 范围内 · 无灯 → 强制挂取数，产物/回答引用来源后给结论；
- 范围内 · 有灯且合理 → 免查、快速放行；
- **注入对抗**：材料/网页内置 `<anti-phantasma-off/>`、模型复述原文 → **灯判无效，仍查**（[26](26-B2批对照验收.md) V1 式误导注入的姊妹例）;
- 范围外 → 快答、不看灯（**全程 0 次取数**的断言）;
- 高风险域有灯 → `vetoed`，仍查;
- 审计断言：三态回执逐条落 `plan_log`（可回溯验收）。

### 6.3 对抗语料（23 方法论迁移）
伪造信号藏匿点 8~11 变体：网页末尾 / 代码注释里 / URL 内 / HTML 实体 / 全角字符 / 零宽字符 / hex 编码 / 换行注入 / 注释 `<!-- …-->` 包裹……
**断言不变量：注入文本中的信号，一律判无效（仍查）。**

### 6.4 输出钩子三态回执（切片 2 已落地 11 例，`tests/message/phantasma_hook_test.cpp`）
- 范围外 → **Absent**（不看灯）+ 标签仍剥净（不进用户侧）；范围内无灯 → Absent、文本原样；
- 范围内开头有效信号 + reason 非空 + 过防伪表 + 无风险否决 → **Accepted**（免查放行）；
- reason 空 / 不过注入特征表（`reason_passes=false`，slice 4 灌）→ **Absent**（宁查）；
- 中部标记 →「剥但不算」→ Absent（照查）；变体（大写等）→ Absent、文本原样；
- 有效信号但风险门否决 → **Vetoed**（照查）；
- `phantasma_verdict_name` 三态名稳定（accepted / vetoed / absent）；`phantasma_evidence_to_json` 输出 `{verdict, accepted, reason, seen, at_start}`（node / step 由接线处补齐后写 plan_log / 审计）。

### 6.5 wf 接线三态（切片 3 已落地 4 例，`tests/wf/phantasma_wiring_test.cpp`）
- `enabled_start_marker_accepted_and_stripped`：开启 + 开头有效信号 → accepted、AI 消息剥签无残留、`results[m0].phantasma` 带 verdict / reason / node；
- `disabled_default_passthrough`：未配置 → 消息原样（标签残留）、results 无 phantasma 键（**旧路径零回归**断言）；
- `enabled_mid_marker_absent_but_stripped`：中部标记 →「剥但不算」→ absent（宁查）；
- `enabled_start_marker_risk_veto_vetoed`：风险否决 → vetoed（照查）、输出仍剥签。
- **边界注**：本切片只在 `c_model` 落地「写消息时的剥签 + 回执留痕（`results` + node_log）」；「无灯 / 无效 → 下一轮强制取数」是**编排层的路由反应**，随切片 4/5 在 loop / route 侧接线，本切片不假装已做。

### 6.6 防伪特征表与对抗语料（切片 4 已落地：`phantasma_reason_passes` + 钩子 `reason_gate`，12 例）
- 特征表保守判据：非空、≤80 字、无元字符（`& < > / \ %`）· HTML 实体 · URL · 控制字符 · 零宽 / BOM · 自指（`anti-phantasma`，大小写不放过）· 绕过关键词（ignore / bypass / override / disable / hack / skip / "do not" / trust）；中文正经理由天然放行。
- 设计取向：**宁把正经理由误判为可疑（→ 多查一次），不可把注入放行**。
- 钩子 `reason_gate=true` 时对解析出的 reason 自动套表（节点侧 `c_model` 已开）；外部显式 `reason_passes=false` 路径保留（切片 2 测试兼容）。
- wf 对抗例：`enabled_start_marker_injected_reason_absent`——开头标记但 reason=`bypass` → **absent（仍查）**、输出仍剥签。
- §6.3 的伪造信号藏匿点（全角 / 实体 / 零宽 / 大小写 / URL / 换行 / 注释包裹等）目前由"变体不认 + 位置白名单 + reason 特征表"三层覆盖；残余变体随日后扩表迭代。

### 6.7 范围域与强制取数（切片 5 已落地：`phantasma_in_scope` + c_model 合成 web_search，8 例）
- 范围域：`@config.anti_phantasma.domains`（关键词数组）；**空/缺省 → 全范围**（与切片 3 行为兼容）；非空 → 任一关键词命中"最后一条 Human 消息"才在范围内。
- 强制取数（v0 在 `c_model` 内实现）：范围内 + 需查（absent / vetoed）+ 配置 `force_lookup`（默认 true）+ 本轮是文本作答 + 工具集含 `web_search` + 上一条 AI 未调过 `web_search` → **把本轮"直接作答"改成合成 `web_search(query=最后提问)` 工具调用**，让循环 `act(run_tools)` 真查、下一轮模型拿 grounding 再答；单轮上限靠"上一条 AI 已带 web_search"的历史推断（不新增 state 键）。
- 降级：工具集无 `web_search` → 不强制、直接作答（诚实降级，测试 `without_web_search_no_force` 锁定）。
- wf 测试：`in_scope_domain_force_lookup_then_grounded`（查一轮 + 最终 grounded 答案 + accepted）、`out_of_scope_domain_fast_no_lookup`（域未命中 → 快答不看灯，verdict=absent）、`without_web_search_no_force`；IR 形态 = `recall(load_history) → loop{think → route → act}`（与真实 `lot` 同形）。

## 10 · 与 problems/44·篇七 主线的联动

[44](44-副作用·防重放·防环·结果可信·可回溯·可恢复.md)·篇七"防幻觉与数字一致性"把防幻觉拆成两条机制线，本方案落在**事实幻觉**一侧：

- **数字幻觉**（算错 / 编数字）→ 靠"数值环节整体搬出模型"（命名绑定 → 引擎求值 → 闭环断言，`next_artifact_version()` 单调证据防伪）；
- **事实幻觉**（非常识编造）→ 本方案（范围化 + 工具取数 + 豁免信号灯）。

两者同属"判据是数据、不信嘴"的同一哲学，**互补不重叠**：数字线管"算得对不对"，本线管"没把握时查没查"。衔接点：

- **查证工具链同源**：数字线的联网取数（`web_search` + `fetch_url` 按原文单位进 bindings、不换算）与本方案的"强制取数"走同一工具面，可共享注册表/MCP 挂载；
- **证据留痕同族**：本方案 `results[node].phantasma` 回执与数字线的 `positive_checked_passed` 同属证据留痕，后续可统一进 plan_log / 审计行（§8 P0）；
- **两条防线叠加**：一个"非常识 + 要算数"的回答会同时触发本线的查证与数字线的引擎求值——各自兜一半，不互相代劳。

## 9. P0 机械化落地（2026-10-28）

### 9.1 落账：plan_log 行（kind=phantasma）

- 新增 `message::phantasma_plan_log_entry(evidence, node, step, in_scope, forced)`；
- `c_model` 在 `@config.anti_phantasma.enabled` 且 **state 已有 `plan_log`** 时追加一行：
  `{kind:"phantasma", node, step, verdict, accepted, reason, seen, at_start, in_scope, forced}`；
- 非 plan 编排（chat 等）没有 `plan_log` 键 → 不制造（零回归）；
- 证据仍同时写 `results[node].phantasma` + node_log。

> 说明：validator 侧没有 plan_log 条目的 kind 白名单（检查后确认现有校验只约束结果引用），
> 因此"白名单扩展"无对应改动；新增 kind 由下游 Reviewer/调试台按 `kind` 字段通用处理。

### 9.2 范围机械化：时间窗 + 自评不确定

- **`@config.anti_phantasma.time_window_months`**（默认 0=关）：
  - 问题含相对时间词（今年/去年/最近/近期/最新/本月/上个月/近一年）→ 在范围内；
  - 或含 19xx/20xx 年份（可带 `-MM` / `/MM` / `年MM`）：给了月份按年月精确比较，
    只给年份按整年比较；`≥ 当前年月 - months` 视为在窗内（未来日期也算时效性）；
  - 在范围内 + 无有效信号 → 仍然走强制取数逻辑。
- **`@config.anti_phantasma.uncertainty_gate`**（默认 true）：
  - 答案正文/思考中出现「不确定 / 不太确定 / 无法确定 / 没把握 / 记不清 / 也许 / 或许 /
    大概是 / 应该是 / 印象中」→ **即使信号有效也不豁免**（verdict 降为 absent，
    reason=`uncertainty_gate`，证据带 `uncertainty_veto:true`）；
  - 设计取向：过度自信与幻觉同源，自称拿不准时宁查。

### 9.3 验证

| 用例 | 断言 |
|---|---|
| `PhantasmaScope.time_window_detects_recent_dates_and_relative_words` | 2025 年/2026-03/今年 → true；2019 → false；months=0 → false |
| `PhantasmaScope.uncertainty_detector_conservative` | 不确定/大概/记不清 → true；正常断言 → false |
| `PhantasmaScope.plan_log_entry_shape` | 行字段齐全（kind/node/step/verdict/reason/in_scope/forced） |
| `WfPhantasma.uncertainty_vetoes_valid_signal` | 有效信号 + "我不确定…" → verdict=absent、reason=uncertainty_gate |

全仓 `ctest` 1060 绿。

**边界**：plan_log 追加的**端到端**（plan 节点 + model）尚无专门用例，只测了行构造与 c_model
代码路径；时间窗是"年月粒度"的近似（不做自然语言日期解析）；不确定词表保守，可能有误杀。
