## 2. A · 三中间件做深

### A1 阈值策略：压缩触发从"消息数"升级为"token 占用"

- **现状**：`TrimHistory(Options{max_messages})` —— 按条数触发，对不同长度消息"一视同仁"。
- **深化**：新增 `Options{ max_tokens }`。触发判定改为 **估算占比**：
  ```
  触发条件 = 计 messages 的 estimate_msgs(msgs) > max_tokens
  折叠量仍按条数（desired = max_messages 语义保留），边界安全复用 TrimHistory::safe_boundary
  ```
- **token 估算（无 tokenizer）**：`estimate(text)`：
  ```cpp
  // CJK 一字≈1 token，其余按"字节/3≈0.75·字符"启发式，最后 +overhead 每消息 ~4 token
  std::size_t estimate(std::string_view text);
  std::size_t estimate_msgs(std::span<Message const> msgs);   // 含 role 开销
  ```
  工具结果、system prompt 一并计入；`usage` 元数据存在时（真机）可用它标定启发式的偏差比。

### A2 token 量化：成本可见 + 截断按预算

- **① 摘要成本量化**（压缩的隐性代价）：`TrimHistory` 只记录**摘要次数**（`summaries()`）
  与估算"省下"的 token（`estimated_tokens_saved()`）；摘要那次 LLM 调用的 **usage 由调用方
  的 Summarizer 回调自己捕获**（它对 `model->invoke` 的返回值有完整访问权），
  `m9_budget` demo 即如此统计。这样中间件不必持有模型指针，也不必重定义 usage 的归属。
- **② 截断按 token 预算**：`TruncateToolResults` 新增 `max_tokens` 模式：
  ```
  max_tokens 模式 → 用 estimate 评估，超限则按 token 预算回退到安全字符边界截断，
  并标注「已截断 N token（约 M 字符）」
  ```
  与字节截断并存（默认仍字节；预算模式显式开启），供"省的是每轮重复的钱"那一档继续量化。

### A3 审批记忆化：同一工具不重复问

- **现状**：`ToolApproval` 每次调用都问/都拒，会话内同一工具反复触发。
- **深化**：加**会话级记忆**：
  ```cpp
  struct ToolApprovalOptions {
    // fingerprint = tool 名 + 归一化参数（参数 JSON 序列化后排序键名）
    enum class MemoPolicy { Off, RememberDeny, RememberAll };
    MemoPolicy memo = MemoPolicy::RememberDeny;
    std::size_t max_entries = 128;   // 有界，防无限增长
  };
  ```
  - `RememberDeny`：同一 fingerprint 被拒过 → 本轮直接拒（不问）；放行不记忆（每次仍审，因为放行有副作用敞口）。
  - `RememberAll`：已决即记（放行也记住）→ 同 fingerprint 后续直接放行/拒绝。
  - **与 Journal 的关系**：记忆化管"**要不要审**"，Journal 管"**执没执行过**"——两件事不混：
    记忆化省的是审批开销，Journal 防的是副作用重放。
- 观测：`denials()` / `memo_hits()` 计数（验证路径真的被走到）。

## 6. 开放点

1. **精确 tokenizer**：目前启发式估算 + 端点评点 usage 标定；若自建端点没有 usage，估算误差需量化。
2. **动作级评测集**（工具查找）：hybrid 只动召回，评测集本身维持 01 的思路。
3. **Journal 持久层**：审批记忆化 + Journal 都还是内存/单文件；"耐久"需未来接真实落点。
4. **LLM 精排**（hybrid 末位）：默认不做，留给需要时当调用成本谈。
