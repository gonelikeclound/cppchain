# 29 · 超长工具返回：混合解法设计（七法 × 三轴 + 运行时路由 + 评测）

> **定位**：problems/02「超长工具返回」追加篇的设计档——把"问题分析"落成**可实施的设计**，
> 并记录**评测设计**与**最终结果**。问题背景/七法逐项/选型理由见
> [problems/02](../04-problems/02-超长工具返回.md) §7；本档只写三件事：
> ① 设计方案（组件、接口、不变式）；② 评测设计（语料、任务、指标、公平性）；③ 最终结果与结论。

## 一、结论先行

1. **没有单一解法**：没有任何一种手段能同时做到"不漏、不贵、不假"；解法是
   **取全 / 定位 / 预算** 三轴上的混合路由。
2. **成本单位是"每轮留在上下文里的 token"**（大小 × 剩余轮数），不是"单条结果字节数"。
3. **运行时默认用"预取单次"（route）**；需要兜底时用 **hybrid 预算版（≤1 轮工具 + 强制收口）**；
   纯工具自选（base）成本与失控风险最高，只作对照。
4. 真机实测（DeepSeek-flash，7 题）：route **6/6 有信号题 · 0 工具调用 · 2,223 token**；
   hybrid **7/7（含 1 题路由盲区）· 1 次工具 · 14,639 token**；base **6/7 · 16 次工具 · 39,331 token**。

## 二、设计方案

### 2.1 三轴与七法（能力清单）

| 轴 | 手段 | 实现 | 先验假设 |
|---|---|---|---|
| **取全** | ① 翻页读全 | `file_read(offset, max_chars, next_offset)` | 知道"读到哪里了" |
| | ② 落盘回读 | `artifact` 落盘 + 引用行（S3 执行时自动；`write_tool_artifact`） | 有可回读的文件通道 |
| **定位** | ③ 字面搜索 | `file_grep`（ECMAScript 正则、行号、命中上限） | 知道要找的字面 |
| | ④ 结构化提取 | `file_extract`（json/yaml/markdown/xml） | 知道结构/键路径 |
| | ⑤ BM25 词法 | longdoc 关键词臂（`keys` 倒排 + IDF） | 问题词与正文词面重叠 |
| | ⑥ 向量语义 | longdoc blurb 向量臂（余弦 + 权重混合） | 语义相近、词面可不同 |
| | ⑦ 采样跳读 | `file_sample`（head/middle/tail，带"不保证覆盖"声明） | 没有先验 |
| **预算** | 截断 / 摘要 / 凭据行 / 丢弃 / 隔离 | `TruncateToolResults`、历史规则、summary、subagent | — |

### 2.2 组件与代码落点

| 切片 | 内容 | 代码 |
|---|---|---|
| **S1** | `file_read` 分页（UTF-8 边界对齐；`next_offset` 非空=还有） | `src/tool/file_tools.cpp` |
| **S2** | `file_grep`（递归、正则、二进制/超大跳过、总扫描预算、**跳过 `.wfr/.git`**） | 同上 |
| **S3** | 工具结果**执行时**自动句柄化（`@config.tool_result_artifact`，默认关） | `src/workflow/node_types.cpp` `c_run_tools` |
| **S4** | `file_extract`（JSON Pointer/点路径、YAML 键路径、MD 标题、XML 元素路径） | `src/tool/file_extract.cpp` |
| **S5** | `file_sample`（三段采样 + offset + 覆盖率声明） | 同上 |
| **S6** | `file_context` 路由节点（判定 + 升级 + 预算 + 证据） | `src/workflow/file_route.cpp`、`node_types.cpp` |

### 2.3 `file_context` 节点（运行时路由）

**输入**：最后一条 Human 消息 + 工作区文件（经只读工具访问，不直接碰盘）。

**判定（确定性，零模型成本）**：

| 信号 | 路由 |
|---|---|
| JSON Pointer / 点路径 / 中文章节 / `Section N` | `file_extract`（候选文件：提问点名 → 结构化扩展名 → 前 3 个） |
| 引号内容 / 代码字面（`0x9F3A`、`code=…`） | `file_grep`（pattern 转义，全工作区） |
| 全局词（总结/讲了什么/结局/最后/结尾） | `file_sample`（点名文件或最大文件） |
| 完整性词（有没有/一共/全部）但无字面 | **不预取**，交模型规划（采样不能作完整性的兜底） |
| 无信号 | 不预取（route=`none`） |

**升级阶梯**：`extract` 未命中 → `grep`（选择器原文）→ `sample`；`grep` 未命中 → `sample`。
每步写 attempt `{tool, detail, hit, bytes}`，最终写 `results.<id>`。

**预算**：`budget_chars`（默认 2000）、`max_files`（默认 5）；超预算截断并标
`…[路由预算已满]` + `budget_hit=true`。

**输出**：片段写 `state[system_context]`（model 节点自动带上，同 longdoc_retrieve），
证据写 `results.<id>`（`route` / `attempts` / `candidates` / `budget_hit`）。

**配置**：`@config.file_route = {enabled, budget_chars?, max_files?}`；
wfr 平铺 `--set file_route=on`。**默认关 → 零回归**。

**片段格式（真机教训）**：结构化提取必须标
`【<path> · selector=… · format=…】\n提取结果：\n<text>`——
只给裸值（如 `443`）时模型会怀疑"素材没给值"。

### 2.4 预算版 hybrid（chat / chat2 模板）

结构不变式（不靠提示词自觉）：

```
recall → files(file_context) → think(model, tools)
   ├─ 文本 ─────────────────────────────────→ _turn_end
   └─ tool_calls → act(run_tools) → final(model, 无工具) → _turn_end
```

- **至多一轮工具**；工具用完必有 `final` 强制作答（不会出现"调 4 轮后空答"）；
- `file_context` 预取默认关；多轮工具探索交给 `lot` 等专用 workflow。

### 2.5 工程纪律

1. **UTF-8 安全**：所有截断/分页/采样回退字符边界（否则 JSON 序列化 `type_error.316`）；
2. **协议完整**：不产生孤儿 `ToolMessage`；`safe_boundary` 保护工具组；
3. **搜索面**：`.wfr`（会话日志/产物）与 `.git` 不进 grep——否则路由会"搜到自己的提问"；
4. **诚实标注**：截断标字节数、采样标"不保证覆盖"、未命中标"≠不存在"；
5. **默认关**：新能力（S3/S6）默认关闭，旧路径零回归。

### 2.6 远期统一抽象（未实现）

```text
DocumentHandle { id, path|url, size, structure?, index? }
  page / grep / extract / bm25 / vector / sample
```

在线侧"超 N token 自动句柄化"、预索引侧 longdoc 索引即持久化索引——当前两者共用同一套
工具与格式，但尚未抽成统一对象（`longdoc.index.json` 已是该形状的雏形）。

## 三、评测设计

### 3.1 离线确定性评测（`examples/file_retrieval_eval`）

**语料**（每份都预埋答案位置，保证可确定性断言）：

| 语料 | 形态 | 考什么 |
|---|---|---|
| `log.txt`（4000 行） | 纯文本、行结构 | grep / 翻页 |
| `report.md`（40 节） | 长 Markdown | 章节提取 |
| `config.json`（200 项填充） | 嵌套 JSON | JSON 指针 |
| `app.yaml`（1500 项填充） | 缩进 + 块列表 | YAML 键路径 |
| `feed.xml`（20 条目） | XML | 元素路径 |
| `novel.txt`（60 章） | 长中文叙事 | 中文章节 / 采样 |

**任务 8 个**：字面定位、JSON/YAML/XML 结构、Markdown 章节、中文章节、无先验全局、完整性读全。

**臂**：grep / extract / sample / paging / 混合路由。

**指标**：`hit`（答案是否进入返回文本 = Read@budget 的确定性版）、`calls`（工具轮数）、
`bytes`（返回字节数）。**不测模型利用率**（离线无模型；留真机）。

**断言**：每个任务的"正确方法"必须命中；采样对中段答案必须如实漏掉；
翻页对完整性任务必须命中且轮数 >20；混合路由 8/8。

### 3.2 真机评测（`examples/file_route_live`）

**两套对照**（同一语料/问题/模型，只变"取数方式"）：

| 臂 | 结构 | 测什么 |
|---|---|---|
| **route** | 预取 → model 单次（不给工具） | harness 预取是否够用 |
| **hybrid** | 预取 → 带工具答一次 → **强制收口** | 路由判错/盲区时能否兜底且不失控 |
| **base** | 只给工具 + loop（max 4） | 模型自选工具的成本与风险 |

**问题 7 个**：6 个有路由信号（JSON 指针 / YAML 键路径 / 代码字面 / 章节 / 引号字面 /
结尾采样）+ 1 个**路由盲区**（"app.yaml 里 host 的值"——无结构/字面/全局信号，预取必然不命中）。
盲区题专门验证兜底；route 臂在该题按设计失败，不计入 route 分母。

**指标**：正确（答案含预埋事实）、模型工具轮/调用数、input/output token、路由证据
（route/attempts）、失败时打印预取上下文（区分**漏读**与**利用率**）。

**公平性控制**：同一工作区、同一问题、同一模型（deepseek-flash）、同一工具集；
每条臂独立 session/线程；真机结果注明随机性（同题多次运行可能不同）。

### 3.3 指标定义

| 指标 | 定义 | 回答什么问题 |
|---|---|---|
| **Read@budget** | 答案所在片段是否进入返回文本 | 方法能不能取到 |
| **漏读率** | 答案存在但没取到 | 路由/方法问题 |
| **利用率** | 取到了但答案错 | 提示词/模型问题 |
| **token / 任务** | 真实 usage 合计 | 成本 |
| **工具轮 / 调用** | 轨迹计数 | 轮次成本与失控风险 |

### 3.4 复现

```bash
./run-demo.sh file_retrieval_eval   # 离线，无端点
./run-demo.sh file_route_live       # 真机，需 .env 的 LLM_API_KEY
FILE_ROUTE_LIVE_ONLY=1 ./build/dev/examples/file_route_live   # 只跑第 2 题（下标 1）
```

## 四、最终结果

### 4.1 离线矩阵（8 任务，确定性）

| 任务 | grep | extract | sample | paging | 混合 |
|---|---|---|---|---|---|
| T1 日志错误码 | **✓1/62B** | — | ✗ | ✓29/232KB | grep |
| T2 JSON 端口 | ✓1/12B | **✓1/4B** | ✗ | ✓1/8KB | extract |
| T3 YAML 端口 | ✓1/71B | **✓1/3B** | ✓ | ✓1/8KB | extract |
| T4 XML 标题 | ✓1/89B | **✓1/24B** | ✗ | ✓1/1617B | extract |
| T5 报告章节 | ✓1/59B | **✓1/1049B** | ✗ | ✓5/39.5KB | extract |
| T6 小说章节 | ✓1/45B | **✓1/1823B** | ✗ | ✓3/24KB | extract |
| T7 结局 | — | — | **✓1196B** | ✓14/106.5KB | sample |
| T8 最后一行 | — | — | ✓ | **✓45/355.6KB** | paging |

汇总：**grep 6/6 · 1.0 轮 · 56B**；**extract 5/5 · 1.0 · 581B**；**sample 3/8 · 1198B**；
**paging 8/8 · 12.4 轮 · 96.9KB**；**混合 8/8**。

→ 已知字面用 grep、已知结构用 extract（比 grep 更省且不依赖答案字面）；采样只能改变"看没看到"，
不能证明"有没有"；翻页买的是完整性与顺序性。

### 4.2 真机三臂（7 题，DeepSeek-flash）

| 臂 | 正确 | 模型工具调用 | 总 token |
|---|---|---|---|
| **route** | 6/6 有信号题（盲区题按设计失败） | **0** | **2,223** |
| **hybrid 预算版** | **7/7** | **1**（只在盲区题） | 14,639 |
| **base** | 6/7 | 16 | 39,331 |

- route vs base ≈ **18×** token、0 vs 16 次调用；hybrid ≈ route 的 6.6×、base 的 37%；
- 盲区题：route 无素材 →"没找到"；hybrid 调 1 次 `file_extract` → `localhost` → 收口答对；
- base 在"引号字面"题再次 4 轮工具后空答。

### 4.3 两个真机才发现、已修的问题

1. **利用率失败**：route 臂 YAML 题素材里明明有 `443`，模型却说"未给出具体值"——片段只有裸值。
   注入格式改成「**提取结果：**\n443」后同题 **3/3 命中**。
2. **工具诱惑**：仅用提示词约束不够（引号题 4 轮空答）。改为**结构限轮 + 强制收口**后：
   hybrid 5/6→**7/7**、工具调用 10→1、token 32.7k→14.6k。
   **提示词管不住的，用图结构管。**

### 4.4 模板落地 smoke（chat / chat2）

| 场景 | 期望路径 | 实测 |
|---|---|---|
| chat · 有信号（YAML 键路径） | 预取 → 直答 | ✓ `443`，0 工具 |
| chat · 路由盲区（host） | 无素材 → 1 次 `file_grep` → final | ✓ `localhost`，1 工具 |
| chat2 · 有信号（JSON 指针） | 预取 → 直答 | ✓ `8443`，0 工具 |

### 4.5 当前状态

- `FileToolsTest` 48 例、`WfFileContext` 8 例、`WfToolResultArtifact` 4 例；
- 全仓 `ctest` **1011 全绿**（1 例 longdoc 语料 SKIP）；

## 五、取舍与未解

1. **结构化提取是"常用子集"**：YAML 只支持缩进映射 + 块列表；XML 无命名空间/属性选择器；
   Markdown 只认 ATX 与中文章节标题——解析失败 fail-closed，不猜。
2. **在线路由未接 BM25/向量**：`file_context` 的升级阶梯目前是 extract→grep→sample；
   接 longdoc/embeddings 需要索引或端点，留作下一步。
3. **`DocumentHandle` 未抽对象**：在线工具与 longdoc 索引形状一致，但没有统一接口。
4. **真机随机性**：单题多次运行会变（route 臂有 17/18 的累计记录）；评测报告必须注明次数与口径。
5. **任务级成功率**未量化（当前只测"答案是否进上下文"与"最终答案是否含事实"）；
   更严格的评测需要任务集与判分器（可复用 problems/02 §7.5 的指标）。
