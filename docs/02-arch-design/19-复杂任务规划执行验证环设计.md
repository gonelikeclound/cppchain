# 19 · 复杂任务「规划 → 执行 → 验证」环设计（wfr-㊹ 定架构）

> **这是什么**：01-discuss/07 建档专题的第一份实现级架构。把已有件（M10 interrupt、approve_tools、
> ExecutionGuard/probe、loop、会话日志事实源）组装成**任务级 P-E-V 环**，并定义「可中断」「可回退」
> 在任务维度的语义。**不是造新原语，是定组织。** 对应实现分期见 §八；验收格式沿用 problems/NN。

## 一、五问五答（01-discuss/07 §四 → 本稿定论）

| 第一问 | 定论 | 理由 |
|---|---|---|
| ① 验证粒度与判据形态 | **每步验证 + 判据优先 probe**；LLM 复核 **不纳入第一版** | 每步验证才能"定点回退"；probe 只读、确定性、注入安全（沿用 problems/23 纪律）。LLM judge 有注入与背书成本，列为后版本 |
| ② 回退语义 | **两级**：定点回退（`rollback_to:K`）= 执行指针回 K + 后续标 rolled_back；整计划丢弃 = cursor 归零。**不做命令反做**（沿用 06 §7 L7） | 副作用由快照/沙箱承担，计划层只管"指针 + 决策痕迹"；失败步的产物由 probe 判（Partial → 按副作用处理） |
| ③ 中断落点与计划可变性 | 落点 = **步骤边界**（执行前/验证后）；resume 可 **continue / rollback_to:K / abort**；计划**不可直接被编辑**（编辑 = 新的 `plan` 节点产出改版计划，决策痕迹不断） | 步内中断会让"半截工具副作用"沾一手（tools 副作用已由 approve/guard 管，步内不额外开窗）；计划可变必须以**新计划**表达，保证审计线性 |
| ④ 计划的一等公民形态 | 计划 = state 里的**数据对象** `plan{goal, steps[], cursor, strategy}`，由新 **`plan` 节点**产出 | 数据即审计、数据即回放（会话日志事实源不变）；节点产出 + 本地校验（steps 结构必检，坏则 route 重来/澄清） |
| ⑤ 重规划 | 失败重试 `/回退后换法`由 **on_fail 策略表**定；局部重规划 = 调 `plan` 节点重产受影响的后缀 | 计划会过期——把"重规划"做成环内一等动作，别当一次性 |

## 二、P-E-V 环（怎么转）

```
plan 节点：model 产出 plan（steps[].{id,goal,verify,deps} + cursor=0 + strategy）→ 本地校验
   │   （坏/不清 → route ask 人类澄清，人给方向后重规划）
   ▼
loop 容器（plan_verify_flow）——每轮一组：
   ① plan_review（可选，步骤边界 HITL，默认按 strategy 穿过）
   ② model：做 steps[cursor].goal（调工具走 run_tools/approve——工具级防线原封复用）
   ③ verify：按 steps[cursor].verify 判 Completeness → done / Partial·Absent → fail
   ④ 决策：done → cursor+1（_continue）；fail → retry×N → 回退依赖步 / 交给人的中断点
```

- **cursor = 执行指针**：计划、每步结果、verify 决策全部进 state 与日志（可审计、可回放、时间旅行免费）。
- 工具级防线（approve_tools / guard / 沙箱 / 审计）**原封不动**，任务级环只在其上加"组织"。

## 三、计划数据形态（state["plan"]）

```jsonc
{
  "goal": "对比三城 3 天天气并出报告",
  "cursor": 2,                                    // 当前执行下标（0 起）
  "strategy": { "on_fail": "retry", "max_retry": 2, "rollback_deps": true },
  "steps": [
    { "id": "s1", "goal": "查北京天气",
      "deps": [],
      "verify": { "kind": "probe", "probe": "file", "path": ".out/beijing.json",
                  "match": {"complete": "keys:current,daily"} },
      "status": "done" },                          // pending|in_progress|done|failed|rolled_back|skipped
    { "id": "s2", "goal": "查上海天气", "deps": [], "verify": {...}, "status": "in_progress" },
    { "id": "s3", "goal": "写对比报告", "deps": ["s1","s2"], "verify": {"kind":"human","note":"终稿给人复核"}, "status":"pending" }
  ]
}
```

- **规律**：`verify` 三种——`probe`（自动、只读、对象产物）、`human`（边界复核，第③步的自然落点）、
  `model`（**预留**，第一版不做，见五问①）；验证判据的**注入安全**沿用 23 的词面纪律（判据是数据，
  不是模型的自由发挥）。
- state 另加 `plan_log`（追加式：每步的 verify 结果 / 决策 / 中断点 / 回退点）——审计留痕，回放即复盘。

## 四、新节点（各一个 NodeType 条目，注册进 `node_types.cpp` 的 `builtin_node_types()`）

| kind | 职责 | 关键行为 |
|---|---|---|
| `plan` | 模型产出计划（一次/重规划） | 调 model（带 schema 提示词）→ 解析步骤数组 → 本地校验（steps 非空、字段合法、依赖有向无环）→ 写 `state["plan"]`；坏 → 状态失败、route 到「重来/澄清」 |
| `verify` | 判当前步骤完成度 | 读 `plan.steps[cursor].verify` → probe（复用 ToolSpec::probe 判定 Complete/Partial/Absent/Unknown）→ `done`（Complete）/ `fail`（其余）；把结果追加 `plan_log` |
| `plan_review` | 步骤边界的任务层 HITL | 可选节点（workflow 里按需插入）。`interrupt(payload={plan, cursor, plan_log摘录}, ctx)` 悬挂 → resume 语义：`continue` / `rollback_to:K` / `abort`；返回对应写 cursor/状态。**复用 M10 interrupt + MemoryCheckpointer + wfr fire 循环**（与 approve_tools 同一套悬挂/恢复骨架，泛化成"HITL 环路"） |

实现要点：
- 新增 `NodeKind::Plan / Verify / PlanReview`（ir.hpp §NodeKind 枚举 + node_types.cpp 表），避开 Dynamic；
- `interrupt` 语义沿用 graph.hpp:133 的契约：首次抛 InterruptSignal → 引擎落快照；恢复重跑、interrupt() 返回 resume 值（节点是**纯 state 函数**，重跑一致——这条直接继承 approve_tools 的论证）；
- **副作用纪律**：`interrupt` 之前的副作用重跑会重复（graph.hpp:132 注）——所以步骤边界中断不放副作用：「执行前」中断点在**本步模型调用之前**（这步还没动手），不是之后。

## 五、可中断（任务级 HITL 的语义）

- 中断点 = 步骤边界：执行前（`plan_review` 在 model 之前）与验证后（可选）。
- payload 要人看的就是"进度 + 下一步"：`{plan.goal, done:[已完成步骤的 verify 摘要], next: steps[cursor]}`，人能据此裁决是有意义的（区别于工具级"这个命令批不批"）。
- resume 语义即三态（continue / rollback_to / abort）——abort = 任务终止但仍留审计痕迹（和 approve 的 abort 一致）。

## 六、可回退（两级，都不做命令反做）

1. **定点回退 `rollback_to:K`**：cursor:=K；steps[K+1..] 标 `rolled_back`；依赖它们的步骤走 **重规划**（环内调 plan 重产受影响后缀）。副作用：宿主场景靠执行前的 git 快照（problems/22 实践）、沙箱场景靠销毁（wfr-㊸③）——**probe 判 Partial 的产物一律当副作用处理**，不隐式信任。
2. **整计划丢弃**：cursor:=0、steps 全重置（plan 保留即"旧计划归档"；或直接重规划）。
3. 裁量权：`strategy.on_fail` 走自动（retry×N → 回退到首个未满足依赖的步）；人可见的复杂决策在 `plan_review` 中断点裁决。

## 七、审计与验收口径（沿用"验证陷阱"纪律）

- 会话日志是唯一事实源：plan、每步 verify 决策、中断点、回退点全部落日志 → replay/调试台/时间旅行免费。
- 验收判据 = **副作用计数器 + 磁盘断言**，不靠模型自述（problems/03 §5）：
  每步真执行几次、verify 判了几次、中断挂了几次、回退改了 cursor 几何——全部可数。
