# 20 · 长程任务：任务档案与批还原设计（wfr-㊿ 定架构）

> **前文**：01-discuss/12（建档，5 条第一问）→ 本稿把 **第一问「任务持久形态 + 批还原」** 定论。
> 单批的 PEV 环（arch 19）原样复用；本题只做“跨批”：**任务 = 一份落盘的档案**，每次触发 = 一个批，
> 批内走 PEV，批尾写回档案。不引入常驻调度（cron 押后）。

## 一、第一问的回答（定论）

| 问 | 定论 | 理由 |
|---|---|---|
| 任务的持久形态 | **任务 = `.wfr/tasks/<task>.json` 档案**（goal + 长清单 steps + 批进度 cursor + 批间摘要），跨批唯一事实 | 会话日志是“交互史”，档案是“任务态”——分离后计划不会因批内变化而烂；replay 仍给模型全部历史 |
| 批的边界与推进 | 一批 = 一次 wfr 触发；批内 `plan.cursor` 从 `batch_start` 推进到 `batch_end`（本轮目标几步）；批尾 `task end` 写回档案 `cursor += 批内推进`、追加批摘要 | 沿用 PEV 环的 cursor 语义，最大限度复用 |
| 续跑契约 | **档案即 checkpoint**（跨批的显式契约）；session replay 是给模型的“记忆”，档案是“计划+批进度” | 05 第一问的答案：replay 是记忆、档案是计划，两者都要，分工明确 |
| 感受时间 | `task begin` 把 `{batch_no, date}` 写进上下文的 announce；模型每批开局先看到“第 N 批 @ 今天” | DeepSeek-R1 的 `{cur_date}` 同款，代价一个占位符 |
| 调度 | 不做内部轮询；批由宿主/人触发 | cron 押后到 05 押后清单 |

## 二、档案 schema（`.wfr/tasks/<task>.json`）

```jsonc
{
  "task": "daily-report",
  "goal": "每天汇总一条真实新闻并存档，第 3 批出周总结",
  "created": "2026-10-13",
  "steps": [
    { "id": "s1", "goal": "用 web_search 查今天 AI 热点，写 .out/hot.txt", "deps": [] },
    { "id": "s2", "goal": "读 .out/hot.txt 给一句结论", "deps": ["s1"] },
    { "id": "s3", "goal": "把结论追加进 .out/week.txt", "deps": ["s2"] }
  ],
  "cursor": 0,                // 全局已完成步数（跨批累积）
  "batch_no": 1,              // 已跑批次数
  "last_summary": "",         // 上批批间摘要
  "strategy": { "on_fail": "retry", "max_auto_rollback": 1 }
}
```

## 三、新节点 `task`（phase=begin|end）—— 与 `plan`/`verify` 并列，注册进 builtin

- **begin**（批头，`recall → task(begin) → loop…`）：
  - 读 `<workdir>/.wfr/tasks/<task>.json`：有 → `state.plan = 档案`（steps 全清单 + `plan.cursor = 档案.cursor` + `plan.batch_start`）；无 → 直接以 `@config.plan_steps`（或 plan 节点产出的）建初始档案并写盘（`created`、`batch_no=1`）。
  - 注入时间感：往 messages 加一条 `user: "📅 第 {batch_no+1} 批 @ {今天}"`（announce 之前先由 begin 置 `plan.batch_no+1`）。
  - 发布 result `{action: begin, batch, cursor, steps_total}`。
- **end**（批尾，`loop → task(end) → final`）：
  - 把当前 `state.plan`（已完成步状态 + cursor 累积）+ 批摘要写回档案（`cursor = plan.cursor`、`batch_no+1`、`last_summary = final 或 judge 汇总`）。
  - `end` 成功后，下次触发由 `begin` 从档案续——**这是跨批唯一接口**。
- 批内仍走既有环（announce/judge/on_fail 不变）；`verify` 的判据可跨批复用（产物落盘即手账）。

## 四、工作流 `lot`（一次触发 = 一批）

```
recall(会话) → task(begin, resume 档案) → loop[max=批步数+余量] {
    step(announce) → think(model·tools=chat_bash) → route → act | approve(deny) 
    → judge(verify) → _continue } 
→ task(end, 写回档案) → final(批间总结)
```

## 五、分期（wfr-㊿）

| 批 | 内容 | 验收 |
|---|---|---|
| ① | `task` 节点 (begin/end) + 档案读写 + 时间感注入 + `lot` workflow | 单测（档案往返 / 两批还原 cursor 累积 / begin 缺档建档）+ 真机 2~3 批续跑（批间计划稳定、模型看到第几批） |
| ② ✅ | 批间可改（revision-fork：历史快照续跑）+ 批间 L3 复查（recheck_prev→audit_prev 步）| 678 全绿（WfLot 3/3）+ problems/28，2026-10-14 |
| ③ ✅ | 轻量 `wfr cron`（自循环读 .wfr/cron.json 到期重进本进程跑 lot 批；--once 一轮即收）；OS cron daemon 仍押后 05 | cursor 3→4 batch 1→2 真机 + problems/28 |

## 六、边界
- 档案与会话分工：**档案=计划·批进度，会话=交互史·模型记忆**；两者都留（不互相替代）。
- 不引入外部存储：JSON 档案即可；SQLite/Store 属 05 #3 押后。
- `task` 命名避开与现有 `plan`/`verify` 撞义：`task` 管“跨批”，`plan` 管“单批计划”。
- demo 用手工分批触发（批 1..3 各一次 wfr），验证批间收敛与时间感。
