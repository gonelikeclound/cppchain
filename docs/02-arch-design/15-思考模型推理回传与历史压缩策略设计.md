# 15 · 思考模型推理回传与历史压缩策略（wfr-㉙）

> 本篇回答一个具体问题：**思考模型（返回 `reasoning_content` 的那些）下，历史里必须带推理内容吗？
> 如果我想把历史简化成 user-input / assistant-result，是不是就做不了？**
> 结论先说：**能做，协议上不冲突**；真正的代价在**质量**（模型会不会否认自己查过），
> 所以本系列把它做成**可切换、可对比、可观测**的三档。

## 1. 定位与边界

- 消费者是 `wfr` 命令行运行器与 workflow IR（见 [14](14-wfr命令行工具与调试可视化设计.md)）。
- 本篇只做**历史形态**这一个自变量：不改检索、不改工具、不改调度。
- 不覆盖：真定时调度、跨 agent 的历史共享、精确 tokenizer（token 口径仍是启发式估算）。

## 2. 背景：三个实测结论

在真机端点（`LLM_BASE_URL` + `deepseek-flash` / `deepseek-v4-pro`）上探针实测（脚本与原始输出见
[04-problems/14](../04-problems/14-wfr-chat2思考历史对比落地与验收记录.md)）：

| # | 结论 | 证据 |
|---|------|------|
| 1 | **剥掉 reasoning 不报错** | 五种剥法（`reasoning_content` 置空串 / 删字段 / 再加 `reasoning_effort=high` / 再加 `thinking={"type":"enabled"}`）× 两个模型，**全部 200**；"历史轮压成 user + 最终 assistant" 也 200 |
| 2 | **换模型就白得思考过程** | `deepseek-flash` / `deepseek-v4-pro` 默认就是思考模式并返回 `reasoning_content`；`deepseek-chat` 恒不返回（`reasoning_tokens` 恒 0） |
| 3 | **代价在质量而非协议** | 把工具轮整轮丢掉后，模型会**否认自己查过**（实测原话："我上一条关于北京天气的回答其实是编造的，我并没有实际查询"），然后重新发工具调用 |

⚠️ **结论 1 的适用边界**：这是**该端点/该渠道**的实测。官方文档与生态补丁（langchain PR #35093、
n8n PR #34924）都说 DeepSeek V4 家族存在"思考模式下带 `tool_calls` 的 assistant 必须回传
reasoning"的约束；官方 R1 系（`deepseek-reasoner`）规则**恰好相反**（带了才 400）。规则随
版本/渠道变，所以本系列**不把"反正不报错"写进设计**，而是做成开关（§4）。

## 3. 历史压缩三档：扩展 `load_history`，不新增节点 kind

### 3.1 为什么是扩展而不是新 kind

`load_history` 加 `mode` / `budget` 两个**运行期**参数。四条理由，按权重：

1. **回声抑制零改动（决定性）**。压缩结果绝不能落盘，否则下次 replay 的 `add_messages`
   会把整段消息再追加一遍（无 id 消息按追加处理）。编译器已对 `kind=="load_history"`
   做了抑制（`compiler.cpp` 的 wrapper 与 `project_stream_to_log` 两处）；扩展路线这两处
   **一行不用改**，独立节点则要改两处并各加一条回归测试。
2. **VG9 语义天然自洽**。`validator.cpp` 判"首个 load_history 必须早于首个 model/run_tools"。
   压缩内嵌其中自动满足；独立节点会出现"compress 放在 load_history 之前 → 静默无效"的新漏洞。
3. **语义要求**。`fire_once` 传给引擎的 state 输入只有 `{config}`，本轮 human 消息是靠日志
   replay 带回来的 —— "读历史"与"压历史"必须在同一个节点里做。
4. **复用是抄规则不是抄类**。`TrimHistory` 的"工具轮成组"判定（`agent.cpp`：AI 带 `tool_calls`
   时把其后连续的 Tool 消息并入同组）照抄；但 `TrimHistory` 本身是 Middleware（带 summarizer /
   volatile_policy 等无关语义）且是"超限才折叠"，不复用。

代价：调试台上压缩不再是一个独立图形节点。实测 `debug_view` 的前端**从不读** `describe()`
的输出（只画 id 与原始 `def`），所以独立节点本来也带不来视觉收益 —— 可见性改由 §3.5 提供。

### 3.2 三档定义

样本（一轮"北京天气"在下次触发时 replay 出来的样子）：

```
[0] human  "北京天气怎么样？"
[1] ai     content=[reasoning:"用户问天气，需要调用 get_weather", text=""]
           tool_calls=[{id:"call_1", name:"get_weather", args:{"city":"北京"}}]
[2] tool   tool_call_id="call_1"  text="{\"city\":\"北京\",\"temp\":12,...}"
[3] ai     content=[reasoning:"拿到结果，可直接回答", text="北京今天 12°C，晴。"]
[4] human  "那上海呢？"
```

| 档位 | 做什么 | 结果 | 用途 |
|---|---|---|---|
| `full`（默认） | 逐条保留全部消息，零改写零丢弃 | 5 条，含 2 个 ReasoningBlock | 基线 |
| `drop_round` | 删「ai(tool_calls) + 其后**连续的** tool」整组；删所有 ai 的 ReasoningBlock | `[human, ai, human]` 3 条 | 反例档 |
| `keep_evidence` | **不丢任何消息**；删所有 ai 的 ReasoningBlock；`tool` 结果超预算才改写为"凭据行" | 5 条但体积小 | 推荐档 |

**硬约束**：`drop_round` 必须让 AI(tool_calls) 与其全部 Tool 消息**同去同留**，绝不产生孤儿
ToolMessage（真实端点会直接 400）——与 `TrimHistory::safe_boundary` 是同一精神。

### 3.3 `keep_evidence` 的"凭据行"

超预算（默认 200 token，可调）的工具结果被改写成：

```
get_weather({"city":"北京"}) → {"city":"北京","temp":12,...
…[历史工具结果已压缩：原文 214 tokens / 1024 字节（保留前 200 tokens）；完整内容在
.wfr/sessions/session-xxx.log.jsonl 里，如需细节请重新调用该工具]
```

- 工具名与参数从**前一条 ai 消息的 `tool_calls` 按 `tool_call_id` join 回来**（与 `run_tools`
  的 `by_id` 手法一致）—— 凭据行必然带真实工具名与真实参数，不是编的。
- 头部按 token 预算做 UTF-8 安全截断（`char_boundary`）。
- **≤ 预算的结果逐字保留**：小结果本身就是最强证据，不动它。所以凭据行在最常见场景下是
  **逐字真实**的；只有超长返回才进"压缩+标注"形态。

### 3.4 缺省 / 非法的差异化语义（三处刻意不同）

`@config` 缺键会经 `resolve_ref` 得到 `Json(nullptr)`，`as_string` 再 dump 成字符串 `"null"`
—— 这是"缺省"的识别依据（refs.hpp 的宽松语义）。

| 参数 | 缺省（未设 / 空 / 解析成 null） | 非空但拼错 |
|---|---|---|
| `mode` | 回落 `full` | **抛硬错**（fail-closed） |
| `budget` | 回落 `200` | 抛硬错 |
| `reasoning_echo` | 回落 `drop` | 抛硬错 |
| `params.<k>` | **丢弃该键**（不发 `"k": null`） | — |

前三个是"枚举型参数要有个安全基线"，最后一个是"厂商参数不发比发 null 安全"——**它们不一样是
刻意的**，改动时别统一。非法档硬错是为了让 `--set history_mode=keep_evidnce` 这种拼错当场报出来，
而不是静默按 `full` 跑完还让人以为对比做了。

### 3.5 可见性：压缩过程怎么"看得见"

1. **终端**：`load_history` 发布 `results[<id>]`（统计对象），chat2 里紧跟一个 echo 节点打印
   `🏷️ 历史 keep_evidence（budget 50）：5 → 5 条 · 1961 → 1891 tok · 丢 0 改 1`。
2. **调试台**：同一条 `source=node` 诊断日志带完整统计 JSON，点 `recall` 节点即可看（`source=node`
   不参与 replay，铁律见 `session_log.cpp`）。
3. **校验**：VR2 的可引用 result 白名单加了 `LoadHistory`（原为 tool / model / run_tools）。
   这是**新增一项**而非放开：指向 expr 的 `$x.result.f` 仍被拒（回归测试在 `tests/wf/echo_test.cpp`）。

> **wfr-㊵ 追加**：本篇讲的是**渲染期变换**（结果不落盘）。后来补上了另一半 ——
> **可持久化的派生视图**：`summarize`（折叠成 LLM 摘要，产 fold op 落会话日志，于是重跑不重算）
> 与 `refine_history`（规则化精简/裁剪，产 transform op）。见
> [17-历史消息处理机制设计](17-历史消息处理机制设计.md)。原先 §7 开放点里"压缩不进调试台图形"
> 也已解决：两个新节点有独立配色、点开能看到 **op 原文**。

## 4. 出站 `reasoning_content`：三档开关

`Message` 出站时是否回传推理内容，由 `CallOptions::reasoning_echo` 决定：

| 档位 | 语义 |
|---|---|
| `Drop`（默认） | 永不回传 —— 引入前的行为，既有调用点与测试零变化 |
| `ToolCalls` | 仅当该 assistant 带 `tool_calls` 时回传 —— V4 家族那条约束的最小实现 |
| `Always` | 只要有 ReasoningBlock 就回传 |

实现落在 `wire.hpp` 的 `message_to_openai`（原来无条件只发文本块）。多块用**无分隔符**拼接：
流式分块本就是无缝的，加分隔符反而改变了原文。

⚠️ **`ToolCalls` 档的适用边界**：它只对"本来就有 reasoning 的消息"补字段。一段历史里若有某轮是
用**非思考模型**产生的（根本没有 ReasoningBlock），那段历史在严格端点上仍无法满足回传要求 ——
即 `ToolCalls` **仅适用于全程使用思考模型的会话**。

## 5. 厂商参数透传：`model.params`

model 节点新增 `params`（对象），运行期逐键解析后并入 `CallOptions::extra`（原样进请求体）。
两个语义值得记住：

- **解析为 null 的顶层键被丢弃**（`@config` 缺键 → 不发 `"reasoning_effort": null`）。
- **保留键在编译期被拒**（VN13）：`build_request` 的 extra 合并是**右胜**，所以
  `model` / `messages` / `stream` / `stream_options` / `tools` / `tool_choice` /
  `response_format` / `temperature` / `max_tokens` / `stop` 不许从 `params` 走。程序化构造的 IR
  仍可绕开（见 §7）。

`reasoning_echo` 也支持写成 `@config.*`，故**思考档位能从 workflow JSON/命令行调**，不必改代码。

## 6. chat2 与对照方法

`share/wfr/workflows/chat2.json` 是内置 `chat` 的**超集**（多一个 `echo_hist` 节点），
`chat.json` 原样不动 —— 修改过程与新旧对比本身可回看。

**system_prompt 与 chat.json 逐字节相同**：对照实验只允许"历史形态"一个自变量。若再加一句
"若历史里已有结果就直接采信"，结论就不可归因了（那是另一个实验）。

正确的 A/B 姿势是**同一段历史 × 同一句话 × 不同渲染** —— 复制同一份日志三份：

```bash
wfr chat2 --session cmp "北京天气怎么样？"                      # 造一段带工具轮的历史（缺省 full）
for m in full drop evid; do cp .wfr/sessions/session-cmp.log.jsonl .wfr/sessions/session-$m.log.jsonl; done
wfr chat2 --session full "你刚才说北京多少度？直接回答，别再查了"
wfr chat2 --session drop --set history_mode=drop_round    "…"
wfr chat2 --session evid --set history_mode=keep_evidence --set evidence_budget=50 "…"
wfr debug chat2 --all --open        # 三份并排；点 recall 看统计 JSON
```

裸跑 `wfr chat2 "…"` = 现有 `chat` 的行为（所有开关回落默认），**安全基线**。

## 7. 开放点

1. **`keep_evidence` 的机制假设**：探针证明了"整轮丢掉 → 模型不信自己"，但"保 AI(tool_calls)
   + 结果凭据 → 恢复信任"只在单轮样本上验证过（§04-problems/14 有反例讨论）。要改的是**策略
   参数**而非架构：`budget` 已可调，另可加"最近 N 轮保真"的滑窗。
2. **`extra` 右胜**：VN13 只在编译期挡保留键，`build_request` 未加过滤；程序化构造的 IR 可绕开。
3. **token 口径是启发式**（CJK≈1 字/token）：三档对比的**相对趋势可信、绝对值不可引用为成本**。
4. **`ToolCalls` 档的会话纯度要求**（§4）。
5. **压缩不进调试台的图形**：想让策略在图上可见，最小改动是在节点列表标签里带上 `n.def.mode`。
